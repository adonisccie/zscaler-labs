Lab 14: Navigate the Incident, Self-Service, Application Overview Dashboards

LAB 14 · SDC

SDC scenario (Labs 14–16): Your organization has deployed Zscaler Digital Experience to proactively monitor network and device performance for all users. You are expected to monitor trends and incidents that affect multiple users and take corrective action before issues escalate. Your team also troubleshoots reports of poor user experience and identifies the root cause.

Lab 14 scenario: As the Zscaler administrator, you know your organization relies on ZDX to monitor and improve user experience across endpoints, networks and applications. Your role is to analyze the signals from ZDX dashboards (Incident, Self-Service, Application Overview and User Overview) and use this data to find the root cause of user experience issues. By understanding key performance trends and metrics, you will make informed decisions to improve the digital experience across the organization.

Objectives: By the end of this lab, you will:

  • Navigate and analyze ZDX's dashboards, including Performance Overview, Incidents, Self-Service, Application Overview and User Overview.
  • Analyze root cause indicators for application, network and user issues.
  • Troubleshoot key performance problems and plan corrective actions.

💭 THINK FIRST · DIGITAL EXPERIENCE MONITORING

ZDX turns "the app is slow" into numbers: a 0–100 ZDX Score per user and app, built from probes that measure every leg from the device to the application.

  • Users rarely open a ticket the first time an app is slow. Why is proactive monitoring (Incidents, Most Impacted Applications) more valuable than waiting for helpdesk calls?
    Q1 — MODEL ANSWER
    By the time tickets arrive, many users have already lost productivity, and each ticket is one anecdote ("Teams was choppy"). ZDX sees everyone continuously, so it can spot that 200 users in one region on one ISP degraded at 10:05, before most of them call. Incidents group those signals around an epicenter (Wi-Fi, ISP, Zscaler data center, application), so you fix one cause instead of triaging 200 tickets, and you can tell users "we know" before they ask.
  • One user has a Poor score for Microsoft Login while everyone else in the same office is Good. Which dashboards would you move through, and in what order, to narrow down the cause?
    Q2 — MODEL ANSWER
    Go from wide to narrow. Application overview confirms the app is healthy for others, so it isn't the SaaS. Users → that user → device details (CPU, memory, Wi-Fi signal, OS). Then Web Probe metrics (is it DNS, TCP connect, server response or page fetch?) and Cloud Path hop view (which leg adds latency or loss: Wi-Fi, home router, ISP or egress?). When colleagues are fine, the problem is almost always on that user's device or last mile.
  • The lab's closing note says troubleshooting in ZDX is probe-driven. Why does a custom (non-predefined) application give you no ZDX data until you configure probes for it?
    Q3 — MODEL ANSWER
    ZDX doesn't guess from user traffic. ZCC runs synthetic probes (web probes for page fetch/server response/DNS, and Cloud Path traceroute-style probes for each hop) against known targets on a schedule. Predefined apps (Microsoft 365, Zoom, Salesforce…) ship with those targets built in. For your own app, ZDX doesn't know which URL to fetch or which host to trace until you define a probe. No probe means no baseline and no score. That's also why the probe data gives a clean baseline that user traffic alone can't.
Task 14.1 View ZDX Performance Dashboard ▾

In this task, you take the role of a Zscaler administrator and explore the ZDX performance dashboard (Map View), including Most Impacted Applications, Regions by ZDX Score and the ZDX Score.

1 Log in to the Experience Center

  1. Go to https://console.zscaler.com and sign in with the SDC account:
    • Username: SDC Admin Username (in your lab access information)
    • Password: SDC Password
MFA setup prompt: click Skip.

Note: When you log in to your SDC account you'll be taken to Multi-factor Authentication. Click Skip and move on to the next step.

2 Open the Map View

  1. In the Search menu, type Map View and click it.
  2. At the top, select 24 Hours from the drop-down list to set the reporting interval.
Search Map View (Digital Experience > Applications). It was previously called Performance Overview.
Time range: 24 Hours.

3 Explore the key dashboard features

  1. Review Most Impacted Applications: scroll through the list and click an application (e.g., Zoom) to drill into its performance metrics.
  2. Analyze geographic performance in the Regions by ZDX Score map:
    • Click a location to see its ZDX Score and the total number of users in that region.
    • Use the + / − controls to zoom in or out.
    • Click Draw Fence and use your mouse to select a geographic area.
    • Click Filter Selection and review the fenced region's performance metrics.
    • Click Reset (top-right corner of the map) to clear the applied settings, if needed.
Pick Zoom in Most Impacted Applications. Click a map marker for that region's ZDX Score and user count.
Regions by ZDX Score: location pop-up, Draw Fence (top right) and the + / − zoom controls.
Draw a fence → Filter Selection. Reset clears it.
The Custom fence table shows each fenced location's ZDX Score and users, with the ZDX Score chart below.

4 Review the ZDX Score details for selected applications

  1. Scroll down to view the ZDX Score for the selected application.
  2. Click Add Another Application at the bottom to compare the ZDX scores of more applications.
ZDX Score over time for the selected app → Add Another Application.
Pick a second application from the list (e.g., Okta).
Two lines, two apps: compare Zoom and Okta over the same window.

5 Filter by geolocation

  1. At the top of the ZDX dashboard, click Geolocations, select a location from the drop-down, and click Apply filters.
  2. View the Performance Overview reports for the chosen location.
  3. Click Reset to clear the filter.
Geolocations → choose locations (here, five Asian countries) → Apply filters.

6 Explore the filtering options

  1. At the top of Map View, explore the filtering options: Departments, Zscaler Locations, User Groups, Geolocations, Location Groups, Last Mile ISPs and Operating Systems.
  2. Select filters, apply them, and review the results.
  3. View the ZDX Score based on the filters applied.
The Map View filter bar: slice the ZDX Score by department, location, group, ISP or OS.

7 Review the Wi-Fi Dashboard

  1. Type WiFi in the Search menu and click it.
  2. Review these Wi-Fi parameters:
    • Total Access Points
    • Wi-Fi Performance of Access Points
    • Total Devices Connected
WiFi dashboard: Total Access Points, their Wi-Fi performance, Total Devices Connected and the ZDX Score distribution.

Task 14.4 View User Overview Dashboard ▾

In this task, you will analyze user-specific metrics and explore reports to troubleshoot and improve user experience.

1 Open Users Overview and scope by application

  1. In the Search menu, type Users Overview (Digital Experience > Users).
  2. Select an application from the Applications drop-down list, then click Apply filter.
Applications → Microsoft Login → Apply filter.

2 Find impacted users

  1. Use the ZDX Score drop-down (Poor, Okay, Good) to filter the users table.
  2. Select a user with Poor or Okay performance for deeper analysis.
ZDX Score filter: Poor + Okay → Apply.
The worst score floats to the top: Linda Lucas at 10. Open her report.

3 Review the user and device context

  1. Review information such as OS type, IP addresses and other device-specific metrics.
  2. Click View More Device Details.
  3. Review the Hardware, Network and Software tabs, then click Done.
Device Details for LINDA-PC: health, OS, memory, tunnel type, DNS servers and IPs → View More Device Details.
User Device Information: Hardware, Network and Software tabs → Done.

4 Review application performance for this user

  1. View the selected application's ZDX Score Over Time graph for this user.
Microsoft Login sits at 10/100 for the whole window. Note the Analyze Score and Compare to options; you'll use them in Labs 15 and 16.

5 Review the Web Probe metrics

  1. Scroll down to the Web Probe Metrics graphs.
  2. Click the graph-selector icon to select or unselect web probe graphs as needed.
  3. Click anywhere on a graph to get more details about spikes in Page Fetch Time, Server Processing Time, and so on.
Web Probe Metrics: Page Fetch Time for the Microsoft Login page probe.

6 Review the Cloud Path metrics

  1. Scroll down to the Cloud Path Probe Metrics graphs.
  2. View the Cloud Path graph for Latency and Packet Loss.
  3. Select or unselect any of the Cloud Path legs as needed.
  4. Scroll down to the Hop View and expand the leg with the highest differential latency (shown in orange).
  5. Mouse over a hop to get more information.
  6. Click Command Line View and identify hops with high packet loss and/or latency.
Cloud Path: switch between Latency and Packet Loss, and toggle legs with the checkboxes below.
Hop View: device → gateway → egress → ZIA Public Service Edge → app. The orange leg has the highest differential latency.
Mouse over a hop for its details: packet loss and average / min / max latency.
Command Line View: a traceroute-style table. Look for hops with high packet loss or latency.

Note: ZDX probes collect application performance data. Predefined applications include built-in probes by default, while custom applications need probes configured manually. Probes give both baseline and real-time visibility into where a problem is before user impact escalates. Troubleshooting in ZDX is probe-driven: probes generate the performance data that lets administrators pinpoint the exact hop or layer causing degradation, rather than relying on user complaints or assumptions. Understanding how probes work is essential for interpreting ZDX metrics, trends and alerts correctly, and for effective root-cause analysis.

QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, joe@, bev@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide follows the Nav 2.0 layout: open features from the Search menu.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
SaaS/Cloud App Policy that allows or blocks individual cloud apps (e.g., allow YouTube). It is enforced ahead of URL category rules.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZAgent
AI assistant in the Experience Center (top-right icon). With the Digital Experience agent and Troubleshooting skill, it explains the root cause of a user's poor experience.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
