Lab 5: Configure SSL Inspection Policies

LAB 5

Scenario: As the Zscaler administrator, you are tasked with enabling SSL/TLS inspection to monitor and enforce policies on users' encrypted web traffic. Most modern threats hide inside HTTPS traffic, so SSL inspection gives you visibility into encrypted sessions and lets policies be enforced properly. You need to configure SSL inspection for all destinations and define exemptions for trusted or privacy-sensitive categories.

Objectives: By the end of this lab, you will:

  • Enable and configure SSL inspection policies for all encrypted traffic.
  • Verify Zscaler’s certificate installation on the Windows Corp Client PC.
  • Analyze and resolve certificate pinning errors.
  • Analyze SSL inspection logs and identify inspection or bypass events.
Time: ~30 minutes
Tasks: 5.1 – 5.3 (5.2 optional)

Note: The Zscaler Root CA Certificate is installed on Windows Client PCs when the Zscaler Client Connector is installed. For Windows devices, the Root CA must be installed in both: (a) the System Certificate Store (Trusted Root Certification Authorities), and (b) the Firefox Certificate Store (based on the setting in the App Profile).

💭 THINK FIRST · SSL / TLS INSPECTION

SSL inspection is a trusted man-in-the-middle: ZIA terminates the TLS session from the browser, inspects the plaintext, and opens its own TLS session to the real server.

  • After you enable SSL Inspect All, Wikipedia's certificate is issued by Zscaler instead of Let's Encrypt, yet Chrome still says "Connection is secure". What makes the browser accept it, and what would happen on a PC without ZCC?
    Q1 — MODEL ANSWER
    ZIA signs a certificate for *.wikipedia.org on the fly using a Zscaler intermediate CA that chains up to the Zscaler Root CA. ZCC installed that root in the Windows Trusted Root Certification Authorities store (the "Install Zscaler SSL Certificate: On" setting from Lab 3), so Chrome trusts the chain. A device without that root would show a full-page certificate warning for every HTTPS site. That's why root-CA distribution (ZCC, GPO, MDM) is a prerequisite for inspection.
  • Threema fails with a Connection Error even though the Zscaler Root CA is trusted. What is the app checking that the browser isn't, and why is a Do Not Inspect rule the right fix instead of disabling inspection?
    Q2 — MODEL ANSWER
    Threema uses certificate pinning: it has the expected server certificate (or key) hard-coded and rejects any other, however trusted the issuing CA is. Zscaler's substitute certificate can never match. A narrowly scoped Do Not Inspect rule for the Threema cloud application, placed above SSL Inspect All, exempts only that app's traffic. Everything else stays inspected, so you keep visibility while the pinned app keeps working.
  • The scenario mentions exemptions for privacy-sensitive categories. Which kinds of sites might an organization choose not to decrypt even if it technically could, and why?
    Q3 — MODEL ANSWER
    Typical candidates are health/medical, finance/banking and sometimes government categories. Decrypting an employee's personal banking or medical session can conflict with privacy laws, works-council agreements or internal policy, and adds legal risk for little security gain. The trade-off is deliberate: exempt by category (not by "anything that breaks"), document why, and keep inspecting everything else, especially uncategorized and newly registered domains where threats actually hide.
Task 5.1 Enable SSL Inspection for All Destinations ▾

In this task, you will enable SSL inspection for all encrypted traffic.

1 Verify the current SSL Inspection status

  1. On the Corp Client PC, open a Chrome browser window in Incognito Mode.
    • Go to: www.wikipedia.org
  2. Click the site information (filter) icon in the URL field.
  3. Click Connection is secure > Certificate is valid.
The site-information icon (left of the URL) → Connection is secure.
Before inspection: *.wikipedia.org is issued by Let's Encrypt, the site's real CA.

Note: You will see that you have received the certificate from the destination web server. The site information icon looks like three horizontal lines connected by dots. In some browsers it is a padlock icon. It's usually shown to the left of the URL in the browser's address bar.

2 Enable SSL Inspection

  1. Back in the Zscaler Experience Center window, go to Policies > Common Configuration > SSL/TLS Inspection > SSL/TLS Inspection Policy.
  2. On the SSL Inspection Policy tab, click +Add SSL Inspection Rule.
  3. Configure the rule as follows:
    • Rule Order: 1
    • Rule Name: SSL Inspect All
  4. Scroll down to the ACTION section and select Inspect under Action.
  5. Click Save and Activate.
Policies → Common Configuration → SSL/TLS Inspection → SSL/TLS Inspection Policy.
Rule Order 1, name SSL Inspect All, status Enabled. Leave the criteria empty so it matches everything.
ACTION: Inspect, then Save.
Click Activate so the rule takes effect.

3 Verify the inspection status

  1. Close the Incognito browser or refresh it (to make sure the new policy is applied).
  2. Open a new browser window in Incognito Mode and visit www.wikipedia.org
  3. Click the site information (filter) icon in the URL field > Connection is secure > Certificate is valid.
After inspection: the same site is now issued by a Zscaler Intermediate Root CA. ZIA is decrypting and inspecting.

Note: You will see that you have received a server certificate signed by Zscaler.

Task 5.2 Verify Zscaler CA Installation [Optional] ▾

In this task, you will check whether the Zscaler Root CA is properly installed on the Corp Client PC.

1 Check the Windows certificate store

  1. Open the certmgr tool: type certmgr in the Windows search bar or run it from the command prompt.
  2. Go to Trusted Root Certification Authorities > Certificates.
  3. Confirm the following:
    • The Zscaler Root CA Certificate is listed.
    • The certificate is not expired.
Search certmgr → Manage computer certificates → Open.
Trusted Root Certification Authorities → Certificates: Zscaler Root CA is listed.

2 Verify via Google Chrome

  1. Open a browser window and type chrome://certificate-manager/ in the address bar.
  2. Click Local certificates.
  3. Select View imported certificates from Windows.
Chrome Certificate Manager → Local certificates → View imported certificates from Windows.
Chrome picks up Zscaler Root CA from the Windows store, which is why it trusts inspected sites.
Task 5.3 Review Certificate Pinning Errors ▾

Certificate pinning is a client-side mechanism that secures applications by checking that the SSL certificate presented by a backend server matches a trusted certificate hard-coded into the application. It helps protect against man-in-the-middle (MITM) attacks, but it can also cause SSL connection failures when the pinned certificate doesn't match an intercepting proxy's certificate, such as Zscaler's SSL inspection certificates. In this task, you will learn two common methods to resolve certificate pinning errors in applications.

1 Recreate the certificate pinning error

  1. Open a Chrome browser on the Corp Client PC.
  2. Download Threema Private Desktop for Windows:
    • Go to https://threema.com/en/download
    • Click Download Apps under Threema Private.
    • Click download for Windows. An .msix file is downloaded.
  3. Open the msix file from the Downloads folder and follow the installation steps. Then, from the Start menu, open Threema Beta.
  4. Observe the error message displayed during installation.
threema.com → Threema Private → Download Apps.
Desktop App 2.0 (Beta) → For Windows downloads the .msix installer.
After installing, open Threema Beta from the Start menu.
Connection Error. Threema rejects Zscaler's substitute certificate because it's pinned to its own.

2 Configure an SSL Bypass Rule

  1. From the SSL Inspection page, click Add SSL Inspection Rule and configure the following:
    • Rule Order: 1
    • Rule Name: Bypass Threema
    • Cloud Applications: click Instant Messaging and select Threema from the list. Click Done.
    • Scroll down. Under Action, select Do Not Inspect.
    • Click Save and Activate with the Activation icon in the top-right corner.
Rule Order 1 (above SSL Inspect All), name Bypass Threema, Cloud Applications = Threema.
Action: Do Not Inspect, then Save and Activate.

3 Try the Threema installation again

  1. Right-click the Windows Taskbar and select Task Manager.
    • Find Threema (if present) in the list of running applications.
    • Click End Task.
  2. Reopen the Downloads folder. From the Start menu, open Threema Beta.
Relaunch Threema Beta.
This time Threema reaches its server and shows Link Your Mobile Device with a QR code, so the bypass works.

4 Analyze SSL Inspection and Bypass Logs

  1. From the Experience Center, go to Logs > Web Insights > Logs.
  2. Configure the following:
    • Timeframe: Last 1 hour (you can also pick other timeframes, such as Last 2 hours or Current Day).
    • Add filters: SSL Inspected and Bypassed Transaction.
  3. Click Run Query.

Note: Allow time for logs to populate (typically ~5 minutes). Use the available filters and operators to explore the differences between SSL inspection and bypass events.

Web Insights → Logs with the SSL Inspected and Bypassed Transaction filters. The highlighted Threema rows were bypassed while other traffic was inspected.

Note: The Insights page lets you analyze transactions processed by Zscaler through customizable charts and logs. It also has filters and operators to drill down into specific insights for detailed analysis.

🧠
MENTAL NOTE
Issuer tells the story: Let's Encrypt = not inspected, Zscaler Intermediate CA = inspected. Trust comes from the Zscaler Root CA in the Windows store (installed by ZCC). Pinned apps (Threema) break under inspection, so add a narrow Do Not Inspect rule above SSL Inspect All. Prove it in Logs → Web Insights with the SSL Inspected / Bypassed filters.

Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
Application-layer policy that identifies apps by DPI (e.g., WhatsApp) regardless of port. Separate from Firewall Filtering.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZDX Copilot
AI assistant in ZDX that answers natural-language questions and summarizes root cause for a user's experience issue.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
