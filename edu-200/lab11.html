Lab 11: Troubleshoot Access to an Internal Application for a Specific User

LAB 11

Scenario: The Zscaler platform administrator has configured the internal application intranet.patraining.safemarch.com using Zscaler Private Access (ZPA) to secure user access to company resources. Joe, a user, cannot access the application because he is missing the ZPA service entitlement. In this lab, you will troubleshoot and resolve the access issue by granting Joe the ZPA service entitlement he needs.

Objectives: By the end of this lab you will:

  • Identify the root cause of Joe’s access issue using ZPA administrative tools.
  • Analyze the configuration and perform key troubleshooting steps to diagnose the issue.
  • Assign the missing ZPA service entitlement to remove the access restriction.
  • Evaluate the solution and confirm that Joe can access the internal application.
Time: ~25 minutes
Tasks: 11.1 – 11.2
💭 THINK FIRST · TROUBLESHOOTING ACCESS

"I can't reach the app" has many possible causes: the connector, the segment, the access policy, or the user. A good troubleshooter starts with the layer that is cheapest to check and rules things out in order.

  • The Student user reaches the intranet fine with the same connector, segment and PC. Which layers does that rule out for Joe's problem, and where should you look first?
    Q1 — MODEL ANSWER
    If Student works from the same PC, then the App Connector, server group, DNS/network path and the app itself are healthy. What differs is the identity, so check what's tied to Joe: his service entitlements (does he even get ZPA?), then the access policy criteria (does any rule allow Joe or his group for that segment?). A missing Private Access tab in Joe's ZCC already points straight at the entitlement.
  • The fix assigns ZPA to Joe directly on the Users tab. Thinking back to Lab 2, what would be the more scalable fix, and what would it change for other helpdesk staff?
    Q2 — MODEL ANSWER
    Assign ZPA to the Helpdesk L1 group on the Groups tab. Then every current and future Tier-1 engineer inherits private access the same way they inherit ZIA, and removing someone from the group cleans it all up. A direct user assignment fixes Joe today but creates a one-off exception that is easy to forget during audits or offboarding. Fine for a lab, but in production prefer the group.
  • After assigning the entitlement, the guide has you Update Policy in ZCC before testing. What would you see if you skipped that step, and why?
    Q3 — MODEL ANSWER
    ZCC learns its enabled services when it fetches policy at login or on its refresh schedule. Until then it still behaves as if Joe has no ZPA: no Private Access tab, no ZPA tunnel, and the intranet still fails. You might wrongly conclude the fix didn't work. Forcing Update Policy (or signing out and back in) makes the client pick up the change immediately, the same pull model you saw in Lab 3.
Task 11.1 Identify the Root Cause of the Internal Application Access Issue ▾

In this task, you will find out why Joe can't reach the internal application by analyzing his permissions and service entitlements.

1 Simulate the issue

  1. Log in to Zscaler Client Connector on the Corp Client PC:
    • Username: JoeSupport@<Student FQDN> (see Lab 2 for Joe's credentials).
  2. Open a browser and try to reach the internal application: http://intranet.patraining.safemarch.com
Sign in to ZCC as Joe. (The screenshot shows joe@. Use the Login ID you created in Lab 2.)

Note: Joe cannot access the application.

2 Troubleshoot user entitlements

  1. From the Experience Center, go to Administration > Identity > Authentication Service > User Management > Users.
  2. Find Joe and click Edit.
  3. Go to the Entitlements tab and check which services are assigned.
Users list. Click Edit on Joe's row.
Root cause: under Service Entitlements Joe only has Zscaler Internet Access. There's no Zscaler Private Access.

Note: As configured in Lab 2, Joe already has ZIA through the Helpdesk L1 group. ZPA is missing and has to be assigned to fix Joe's access issue.

Task 11.2 Resolve the Internal Application Access Issue ▾

In this task, you will assign Joe the ZPA service entitlement he needs to reach the intranet application.

1 Assign the Zscaler Private Access (ZPA) service entitlement

  1. Go to Administration > Entitlements > Service Entitlements > End User Entitlements.
  2. Select the Zscaler Private Access service from the list.
  3. Go to the Users tab and click Assign Users.
  4. Select the user Joe from the list.
  5. Click Next, then click Assign to confirm.
  6. Verify the assignment: confirm that Joe now has the ZPA service entitlement.
Service Entitlements → Zscaler Private Access.
Users tab → Assign Users.
Tick Joe and click Next.
Summary: Joe. Click Assign.
Joe now appears under ZPA service Users.

Heads-up: The lab guide says to confirm Joe has ZPA "via the HelpDesk L1 User Group", but these steps assign ZPA to Joe directly on the Users tab. Either works for the lab. To give it to the whole group instead, use the Groups tab and assign Helpdesk L1 (see Think First Q2).

2 Test access after troubleshooting

  1. Open Zscaler Client Connector and Update the policy (More → Update Policy).
    • Confirm that Private Access is now visible.
  2. Launch a web browser and go to: http://intranet.patraining.safemarch.com
Fixed: the intranet loads for Joe.
🧠
MENTAL NOTE
Works for Student, fails for Joe = look at identity. Check the user's Entitlements tab first: no Zscaler Private Access service = no ZPA tunnel, whatever the policy says. Fix: Service Entitlements → ZPA → assign the user (or better, the group). Then Update Policy in ZCC, check that the Private Access tab appears, and retest.

QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, JoeSupport@, BevIT@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This lab uses the Nav 1.0 (Original) layout.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
Application-layer policy that identifies apps by DPI (e.g., WhatsApp) regardless of port. Separate from Firewall Filtering.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZDX Copilot
AI assistant in ZDX that answers natural-language questions and summarizes root cause for a user's experience issue.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
