Lab 6: Configure Content Filtering & Access Control

LAB 6

Scenario: As the Zscaler administrator, your goal is to improve users' browsing experience by making sure they only reach safe and appropriate content. You will explore how Zscaler Internet Access (ZIA) enforces content filtering and access control to protect against threats such as phishing, malware and data leakage. You will also verify existing threat protection configurations, analyze risk reports, and test policy behavior to see how ZIA enforces organizational baselines for URL filtering, content categories and cloud application controls.

Objectives: By the end of this lab, you will:

  • Explore ZIA's threat protection configurations and analyze risk reporting.
  • Configure and validate a URL Filtering Policy that blocks risky websites (e.g., gambling, adult and shopping sites).
  • Test the effect of URL Filtering control on the end-user experience.
  • Create and verify a Cloud App Control policy that allows specific apps (e.g., YouTube) while restricting others in the same category.
Time: ~25 minutes
Tasks: 6.1 – 6.4
💭 THINK FIRST · URL FILTERING vs CLOUD APP CONTROL

You'll block whole URL categories, including Entertainment/Recreation (which covers video streaming), then allow YouTube with a different policy type. Both decisions apply to the same HTTP request, so one of them has to win.

  • The URL Filtering rule blocks Video Streaming, and the Cloud App Control rule allows YouTube. Why does YouTube end up allowed while Netflix stays blocked?
    Q1 — MODEL ANSWER
    ZIA evaluates Cloud App Control (SaaS application) policies before URL category policies. A request to YouTube matches the "Allow YouTube" Streaming Media rule first and is allowed. With Cascade to URL Filtering left off, the URL category block is never consulted. Netflix has no Cloud App Control rule, so it falls through to URL Filtering and is blocked as Video Streaming. A coarse category block plus a precise app-level exception is a common, maintainable pattern.
  • Malware Protection and Advanced Threat Protection are already on, yet 888.com loaded fine at the start of Task 6.2. Why is a gambling site not a "threat" in that sense, and what kind of control does stop it?
    Q2 — MODEL ANSWER
    Threat protection looks for malicious behavior or content: malware, C2 callbacks, phishing, cryptomining, XSS and a high Page Risk score. A legitimate gambling site is clean, so it passes. Whether employees should visit it is an acceptable-use question, answered by URL Filtering on the site's category. Security controls and acceptable-use controls are separate layers, and you usually need both.
  • The URL rule blocks Shopping and Auctions for everyone. What business problems could that cause, and how could you soften it without dropping the control?
    Q3 — MODEL ANSWER
    Procurement may need supplier sites, marketing may research competitors, and some SaaS vendors are categorized as shopping. A blanket block generates tickets and workarounds. Options: use Caution (warn and log) instead of Block, scope the rule to specific groups or departments, add time-of-day conditions, allow override for approved users, or add allow rules for specific sites above the block. The aim is the least disruptive control that still meets the policy.
Task 6.1 View Threat Protection Reports ▾

In this task, you will review the current threat protection settings in the ZIA admin portal: Malware Protection, Advanced Threat Protection and the Page Risk Score Index.

1 View Malware Protection settings

  1. In the portal, type Malware Protection in the Search menu and select the result (Cyberthreat Protection > Policy).
  2. Compare the current settings with the Recommended Policy settings.
  3. Note that the Malware Protections are enabled.
Malware Protection → Malware Policy tab: inbound/outbound traffic and HTTP/FTP inspection are on. Recommended Policy (top right) shows Zscaler's baseline for comparison.

Note: Malware protection defends against spyware, botnets, malicious active content and more.

2 View Advanced Threat Protection settings

  1. In the left navigation panel, go to Advanced Threat Protection.
  2. Compare the current settings with the Recommended Policy settings and note which Advanced Threat Protections are enabled.

Note: Advanced protections include settings against Command and Control traffic, Phishing, Cryptomining, Tunneling, Cross-Site Scripting (XSS) and more.

3 Review the Page Risk Score Index

  1. Review the Suspicious Content Protection (Page Risk™) setting. It calculates a score when the user accesses a page, analyzing the page's threat level dynamically.
Advanced Threat Protection: the Page Risk slider sets the score above which pages are blocked (Low → Moderate → High risk). Botnet Protection blocks C&C servers and traffic.
Task 6.2 Configure Content Filtering Controls ▾

In this task, you will create a URL Filtering Policy that blocks risky URL categories such as gambling, adult content and video streaming, and see how content filtering controls manage user access in ZIA.

1 Test high-risk URL access (before configuration)

  1. Open a browser on the Corp Client PC and try to visit a risky or unsafe website, such as 888.com (a gambling site).
  2. Verify that the website is currently accessible.
Before the rule: 888.com loads normally.

2 Create a URL Filtering Policy

  1. In the Experience Center, type URL Filtering in the Search menu and select the result (Internet Access > Policy).
  2. Click Add Rule.
  3. Configure the rule:
    • Action: Block
    • Rule Name: Risky URL Categories
    • Click Edit and change Rule Order to 1 if required.
    • Rule Status: Enabled
    • In Criteria, under URL Categories, search for and add: Adult Materials, Shopping and Auctions, Gambling, Entertainment/Recreation.
    • Make sure all options are selected for Request Methods and Protocols.
  4. Click Save and Activate.
URL Filtering Policy → Add Rule.
Criteria: URL Categories (the super-categories expand into many sub-categories) and all Request Methods. Actions: Web Traffic Block, name Risky URL Categories, order 1, Enabled.
Task 6.3 Test End-User Experience with URL Filtering ▾

In this task, you'll test user access to various websites after applying the URL Filtering Policy.

1 Test blocked URLs

  1. Open a browser and try to visit sites that were previously accessible, such as:
    • 888.com (Gambling category)
    • ebay.com (Shopping and Auctions category)
  2. Verify that these sites are now blocked by the URL Filtering Policy.
Zscaler block page: "Not allowed to browse Gambling category".

2 Test access to video streaming sites

  1. Try to access video streaming websites such as YouTube.com or Netflix.com.
  2. Verify that these websites are also blocked by the rule.
YouTube is blocked too, as Video Streaming (part of Entertainment/Recreation). You'll carve out an exception in Task 6.4.

Note: If testing doesn't work, try using Incognito mode in the browser.

3 If testing fails, verify the URL Filtering Policy status

  1. Go to the URL Filtering Policy and click Edit to confirm that the Rule Status is Enabled.
Task 6.4 Configure Cloud App Control ▾

The Cloud App Control Policy gives you granular control over how users access specific cloud applications and websites. In this task, you will create a rule that allows YouTube while other entertainment and recreation websites stay restricted.

1 Add a Cloud App Control Policy

  1. In the Experience Center, type SaaS/Cloud App Policy in the Search menu and select the result (Data Security > Inline CASB > Configuration).
  2. Scroll down the left-hand panel and select Streaming Media.
  3. Click Add Rule.
Cloud App Control Policy, viewed by Application Category → Streaming Media → Add Rule. No rules exist yet.

2 Create the Cloud App Control rule

  1. Set the Viewing/Listening action to Allow.
  2. Rule Name: Allow YouTube
  3. Rule Order: 1
  4. Rule Status: Enabled
  5. Under the Criteria section, open the Cloud Applications drop-down, select YouTube and click Done.
  6. Click Save and Activate.
Criteria: Cloud Applications = YouTube. Actions: Viewing/Listening Allow. Details: name Allow YouTube, order 1. Leave Cascade to URL Filtering off.

3 Verify the Cloud App Control Policy

  1. Make sure the new rule appears in the Streaming Media rules list.
  2. On the Corp Client PC, confirm that you can access YouTube.com, but access to other streaming websites such as Netflix.com is blocked.
Rule 1, Allow YouTube, is listed under Streaming Media.
YouTube now loads, because the Cloud App Control allow wins.
Netflix is still blocked by the URL Filtering rule (Video Streaming category).

Note: SaaS application policies are enforced with higher priority than URL category-based policies.

🧠
MENTAL NOTE
Threat protection (Cyberthreat Protection > Policy) stops what's malicious; URL Filtering (Internet Access > Policy) enforces what's acceptable. Risky URL Categories blocks Adult, Shopping, Gambling and Entertainment/Recreation. Cloud App Control (Data Security > Inline CASB) is evaluated first, so Allow YouTube wins over the category block while Netflix stays blocked.

QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, joe@, bev@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide follows the Nav 2.0 layout: open features from the Search menu.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
SaaS/Cloud App Policy that allows or blocks individual cloud apps (e.g., allow YouTube). It is enforced ahead of URL category rules.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZAgent
AI assistant in the Experience Center (top-right icon). With the Digital Experience agent and Troubleshooting skill, it explains the root cause of a user's poor experience.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
