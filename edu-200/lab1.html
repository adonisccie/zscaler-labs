Lab 1: Connect to the Virtual Lab Environment

LAB 1

Scenario: As the Zscaler administrator, you need a working, pre-configured environment (the Virtual Lab) that mirrors Labtenant's likely production setup. You'll use it to validate the platform and reach its core management console, the Experience Center, before you start configuration tasks.

Objectives: By the end of this lab, you will:

  • Connect to CloudShare and your lab virtual machines (VMs).
  • Familiarize yourself with the login options and clipboard copy/paste functions.
Time: ~10 minutes
Tasks: 1.1 – 1.3
💭 THINK FIRST · REACHING THE LAB

You are about to work inside a remote Windows desktop streamed to your browser. A few small habits now will save you a lot of frustration later.

  • CloudShare gives you Send Text instead of a normal Ctrl+V into the VM. Why can't your host clipboard simply be shared with the VM, and when will Send Text matter most in these labs?
    Q1 — MODEL ANSWER
    The VM is a separate machine whose screen and keystrokes are streamed through the browser. Your local clipboard never reaches its operating system unless the console explicitly sends it. Send Text types your text into the VM as keystrokes. It matters most for long, error-prone values: FQDN-based login IDs, URLs, provisioning keys and CLI commands for the App Connector later in the course. One typo in a provisioning key costs far more time than a paste.
  • On your first sign-in as student@<Student FQDN>, you are forced to change the password. Why does the Service Portal do this for a brand-new admin account, and why should you write the new one down now?
    Q2 — MODEL ANSWER
    The initial password was set by someone else and delivered through a shared channel (here, the CloudShare Credentials tab), so it should be treated as already exposed. Forcing a change means only you know the working credential from then on. Lab 3 and later labs ask for "the password you configured at initial login in Lab 1" for both the console and Zscaler Client Connector, so losing it now blocks you later.
  • The Corp App Connector VM has no desktop, only an SSH console. What does that tell you about the role this machine plays compared with the Corp Client PC?
    Q3 — MODEL ANSWER
    The App Connector is infrastructure, not a user device. It's a headless Linux service that sits next to the private applications and brokers ZPA connections outbound to the cloud. Nobody browses from it, so it needs no GUI. You'll only use its console to enroll it (Lab 9) and check its health. The Client PC is where a user works and where ZCC enforces policy.
Task 1.1 Verify Lab Access ▾

1 Locate the CloudShare lab URL

  1. Your unique CloudShare lab URL and passphrase will be shown on the classroom screen at the start of the session. Note these credentials carefully, because you need them to access your lab environment (example: https://use.cloudshare.com/…).

2 Access the Lab Login Page

  1. Open a web browser and go to the CloudShare lab URL shown on the classroom screen.
CloudShare login page.

3 Enter Your Credentials

  1. On the login page, enter the email address and passphrase provided in your invitation email, then click Login.
Enter your email and the class passphrase, then click Login.

4 Review the Lab Overview

  1. After you log in, you are taken to the lab environment dashboard. The screen you see matches the specific lab you've been assigned.
The environment Overview tab for EDU-200 · Zscaler for Users - Administrator.

5 Navigate to the VM List

  1. In the Overview tab, click Go to My VM List to open the VM List tab. This tab shows all virtual machines assigned to your lab session.
Click Go to My VM List.

6 Run the Virtual Machine

  1. In the VM List tab, click the Run button next to the virtual machine name to start the VM.
Three VMs: the Windows client, Windows Server 2025 and the ZPA connector. Click Run on each VM you need.

7 Verify the VM is Running

  1. Once started, the virtual machine's tab shows it running, which confirms the environment is ready to use.
A running Windows VM shows its lock screen in its own tab.

Note: For the Corp App Connector VM, click the VM, then click the SSH icon to see the VM running.

The App Connector VM has no desktop. The SSH icon opens its Linux console.

8 Open the Lab Guide

  1. Click the Lab Guide tab to open the hands-on lab guide. It opens in a new browser tab and gives detailed instructions for the lab exercises.
The Lab Guide tab, next to the VM tabs.

9 View your Zscaler tenant and SDC credentials

  1. To find your Zscaler tenant and Solutions Demo Center (SDC) credentials, click the Credentials tab in the left panel. These are the credentials you'll use in the lab.
Credentials → Zscaler Tenant: console link, your student@<Student FQDN> admin username and its one-time password.
Credentials → SDC Credentials: the Solutions Demo Center logins used for the ZDX labs (14–16).
Task 1.2 Use the Lab Clipboard ▾

During these labs, you will often copy commands, URLs and configuration values from the lab guide into the virtual machines.

1 Send text to the VM

  1. To use the VM clipboard, first copy the text from your host / lab guide.
  2. Click the Actions tab and choose Send Text.
  3. Paste the text into the text box and click Send.
Actions → Send Text. The same menu also has Send Password and Send Ctrl+Alt+Del.
Paste into the Send Text box and click Send. The text is typed into whichever field has focus in the VM.
Task 1.3 Sign In to the Experience Center Landing Page ▾

Note: Throughout this lab guide, <Student FQDN> means the domain assigned to your tenant. For example, if your student admin username is student@zs9901.labtenant.com, your Student FQDN is zs9901.labtenant.com. Enter it in the Lab Configuration panel above to fill in every login on these pages.

1 Log in to the Corp Client PC as the local Student user

  1. Launch the Corp Client PC from the CloudShare portal.
  2. Go to the Actions tab and click Send Password.
Actions → Send Password types the local student password for you, so there's no need to type it.

2 Sign in to the Experience Center

  1. In a browser window, open the Experience Center landing page: https://console.zscaler.com/

Note: You will be redirected to the Service Portal (formerly ZIdentity) login page to validate your identity.

  1. Authenticate with your student admin account:
    • Username: student@<Student FQDN>
    • Password: as provided in the Lab Access Instructions <Session Password>
    • Click Sign in.
  2. You will be prompted to change your password after you authenticate successfully. Remember the new password, because later labs ask for it.
Password changed. Use Re-Login to sign in again with your new password.

LAB PROGRESS
QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, JoeSupport@, BevIT@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This lab uses the Nav 1.0 (Original) layout.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
Application-layer policy that identifies apps by DPI (e.g., WhatsApp) regardless of port. Separate from Firewall Filtering.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZDX Copilot
AI assistant in ZDX that answers natural-language questions and summarizes root cause for a user's experience issue.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
