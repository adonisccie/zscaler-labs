Lab 2: Configure User and Administrator Access Entitlements

LAB 2

Scenario: You've secured the Zscaler console and now need a clean foundation for who can sign in and what they can access in Labtenant.com. Two new users, Joe (Support/helpdesk) and Bev (IT/admin), must be onboarded with the right departments and groups so they inherit the correct entitlements. Joe should have limited, read-only access suited to Tier 1 support, while Bev has full administrative access. You then validate both users' experience by logging in and confirming what each can and cannot do.

Objectives: By the end of this lab, you will be able to:

  • Create the required org structure (departments, groups).
  • Provision users and place them correctly so policies and entitlements apply.
  • Configure entitlements and confirm they're applied to the right identity or group.
  • Validate that access is correct through role-based UI restrictions and service status.
Time: ~40 minutes
Tasks: 2.1 – 2.4
💭 THINK FIRST · IDENTITY & ENTITLEMENTS

In this lab you never give Joe any permission directly. Every entitlement goes to a group, and Joe just joins it. Think about why before you start clicking.

  • Why assign the ZIA and ZDX entitlements to the Helpdesk L1 group instead of directly to Joe? What happens on the day a second helpdesk engineer joins, or Joe moves to another team?
    Q1 — MODEL ANSWER
    Group-based access ties permissions to a role, not a person. A new helpdesk engineer only needs to be added to Helpdesk L1 to get exactly the same access, with nothing to copy or forget. When Joe moves teams, removing him from the group revokes everything in one step, so there's no leftover access. It also makes audits simple: "who can read ZIA?" becomes "who is in these groups?". This is the RBAC foundation that zero trust's least-privilege principle depends on.
  • Joe gets a ZIA administrative entitlement and a ZIA service entitlement. What does each one actually allow, and what would Joe experience if he had only the administrative one?
    Q2 — MODEL ANSWER
    An administrative entitlement controls what Joe can see and do in the admin console (here, read-only through the Executive Insights App role). A service entitlement controls whether Joe's own traffic is protected by ZIA through the Client Connector. With only the admin entitlement, Joe could log in to the console and view ZIA data, but ZCC would not turn Zscaler Internet Access ON for him. These are two separate planes, a management plane and a data plane, and Task 2.4 tests each one separately.
  • Joe has read-only access and Bev is a Global Administrator. Why is "can Joe see the Add Rule button?" a better test than "can Joe log in?"
    Q3 — MODEL ANSWER
    Logging in only proves authentication, that the identity exists and the password works. The security outcome you care about is authorization: is each person limited to exactly what their role needs? Checking for a privileged action (Add Rule in Admin Sign-On Policy) that Bev can perform and Joe can't even reach tests the boundary itself. That's the difference between "the account works" and "the access is correct."

Task 2.1 Create Departments and User Groups ▾

In this task, you will create the Support and IT departments and the Helpdesk L1 user group. You will create Joe and Bev and assign their departments and groups in Task 2.2.

1 Open Departments

  1. Type Departments in the Search menu and open the result (Administration > Authentication > Directory).
Search menu → Departments. The result shows where it lives: Administration > Authentication > Directory.

2 Create the Support department

  1. Select Add Department.
  2. In the Add Department section, enter:
    • Department Name: Support
    • Description: Support Department
  3. Click Save.
Add Department: Support / Support Department, then Save.

3 Create the IT department

  1. Select Add Department and enter:
    • Department Name: IT
    • Description: IT Department
  2. Select Save.
IT department: IT / IT Department.

4 Confirm the departments

  1. Confirm that IT and Support appear in the Departments list.

5 Create the Helpdesk L1 user group

  1. In the left navigation bar, select User Groups (Administration > Authentication > User Groups).
  2. Click Add Group.
  3. In the Add Group pane, enter User Group Name: Helpdesk L1
  4. Click Next, then select Save.
Left nav User Groups → Add Group: Group Name Helpdesk L1, then Next and Save.
Task 2.2 Create Users ▾

In this task, you will create users Joe and Bev and map them to the departments and user groups you created in the previous task.

1 Create user Joe: General Information

  1. From the left navigation panel, go to Users and click Add User.
  2. In General Information, enter:
    • Login ID: joe@<Student FQDN>
    • Primary Email: enable Same As Login ID
    • First Name: Joe
    • Last Name: Web
    • Department: Support
    • Additional Attributes: SyncZPA
    • SyncZPA (optional): 123
  3. Click Next.
Users (left nav) → Add User in the top-right corner.
General Information for Joe: Login ID joe@…, Same As Login ID on, Joe Web, Department Support, SyncZPA 123.

2 Joe: Security Settings

  1. On the Security Settings step, configure:
    • Password Option: Set By Administrator
    • Password: Admin-123!
    • Confirm Password: Admin-123!
    • Prompt for Password Change After the Initial Login: Unchecked
    • Multi-Factor Bypass, Skip Second Factor Authentication: Enabled
    • Skip Until: set as far out as allowed.
  2. Click Next.

Note: For lab purposes, the second factor of authentication is skipped. Zscaler recommends enabling Multi-Factor Authentication (MFA) for all users.

Security Settings: Set by Administrator, password-change prompt unchecked, Skip Second-Factor Authentication enabled with a far-out date.

3 Joe: Assign Groups

  1. On the User Groups step, click + Assign Group.
  2. Select the checkbox for the group Helpdesk L1.
  3. Click Assign, then click Save.
Assign Groups: tick Helpdesk L1 and click Assign. Joe inherits everything you give this group in Task 2.3.

4 Create user Bev

  1. Click Add User and set:
    • Login ID: bev@<Student FQDN>
    • Same As Login ID: Enabled (Primary Email becomes bev@<Student FQDN>)
    • First Name: Bev
    • Last Name: Carey
    • Department: IT
    • Additional Attributes: SyncZPA
    • SyncZPA (optional): 123
  2. Proceed to the Security Settings step and configure the same values as for Joe:
    • Password Option: Set By Administrator
    • Password / Confirm Password: Admin-123!
    • Prompt for Password Change After the Initial Login: Unchecked
    • Skip Second Factor Authentication: Enabled, Skip Until as far out as allowed.
  3. Click Next.
  4. On the User Groups step, click + Assign Group, select Zscaler Global Administrators and click Assign.
  5. Click Save.
For Bev, tick the built-in Zscaler Global Administrators group. It already carries full admin entitlements to every service.
Task 2.3 Add Administrative and Service Entitlements ▾

In this task, you will assign administrative and service entitlements so that Joe (through Helpdesk L1) gets read-only console access and ZIA protection.

1 Assign the ZIA administrative entitlement (Helpdesk L1)

  1. Type Administrative Entitlements in the Search menu and select the result (Administration > Role Management).
  2. Click Zscaler Internet Access.
  3. In the Zscaler Internet Access - Administrative pane, click Assign Groups.
  4. Select the checkbox for the Helpdesk L1 group.
  5. From the Role drop-down menu, select Executive Insights App.
  6. Click Next, then Assign.
Administrative Entitlements lists every service in the tenant. Click Zscaler Internet Access.
Zscaler Internet Access - Administrative: the groups that already have admin roles are listed. Click Assign Groups.
Helpdesk L1 → Role Executive Insights App, then Next and Assign.

Note: For simplicity, this lab uses the predefined Executive Insights App role, which conveniently provides read-only access to the Zscaler portal, the permission level intended for this user. In production, you can create a custom role for this purpose under Administration > Admin Management > Role Based Access Control > Roles.

2 Assign the ZDX administrative entitlement (Helpdesk L1)

  1. Select the Back arrow next to Zscaler Internet Access - Administrative.
  2. Click Zscaler Digital Experience.
  3. In the Zscaler Digital Experience - Administrative pane:
    • Click Assign Groups.
    • Select the checkbox for the Helpdesk L1 group.
    • From the Role drop-down menu, select ZDX Read-only Admin.
  4. Click Next, then Assign.
Use the back arrow next to the pane title to return to the entitlements list.
Back on the list, click Zscaler Digital Experience.
Helpdesk L1 → Role ZDX Read-only Admin. Other ZDX roles include ZDX Service Desk Tier 1 and ZDX Super Admin.

Note: The ZDX Read-only Administrator role is a pre-built role.

3 Assign the ZIA service entitlement (Helpdesk L1)

  1. In the Experience Center, type End User Entitlements in the Search menu and open the result.
  2. Click Zscaler Internet Access.
  3. In the Zscaler Internet Access - Service pane:
    • Click Assign Groups.
    • Select the checkbox for the Helpdesk L1 group.
  4. Click Next, then Assign.
Service (end-user) Entitlements: ZDX, ZIA and ZPA. This controls whose traffic each service protects.
Select Helpdesk L1 → Next → Assign. No role is needed for a service entitlement.

4 Verify the entitlements for user Joe

  1. Open the Users page from the left navigation panel.
    • Select the user Joe Web.
    • Go to the Entitlements tab.
    • Verify that both the administrative and service entitlements are assigned to Joe.
  2. Click the X button to close the user pane.
Joe's details: 2 administrative entitlements (ZIA Executive Insights App, ZDX Read-only Admin) and 1 service entitlement (ZIA), all inherited from Helpdesk L1.

Note: Open the Users page and select Bev. Review Bev's administrative and end-user entitlements in the same user-detail view.

Select bev to compare: Bev's entitlements come from the Zscaler Global Administrators group.
Task 2.4 Validate Entitlement Access for Users ▾

In this task, you will log in to the Experience Center to validate the administrative entitlements and access for users Joe and Bev.

1 Validate administrative entitlements for Joe

  1. On the Corp Client PC, open a new Incognito window in Chrome.
  2. Go to the Experience Center landing page: https://console.zscaler.com/
  3. Authenticate with Joe's account:
    • Username: joe@<Student FQDN>
    • Password: Admin-123!
  4. Click Sign in.
  5. Compare the navigation items and available configuration actions for Joe with those available to the student admin account. Record which areas Joe can open and which actions are unavailable.
  6. Confirm that Joe cannot access Admin Management, Sign-On Policies or other administrative configuration areas that were available to student@<Student FQDN>.
  7. Confirm that Joe can only view existing Digital Experience data and cannot create or modify objects.
  8. Click the Account settings icon in the top-right corner of the dashboard to Sign out.
Sign in as joe@<Student FQDN> in an Incognito window, so the student session isn't reused.
Joe's console is trimmed down. Under Administration > Role Management > Digital Experience, he can only view roles (eye icon). There are no add, edit or delete actions.

Note: The Helpdesk L1 group has read-only privileges for ZIA and ZDX. Joe inherits this read-only access, which removes access to core administrative areas (such as Policies and Admin Management) and limits him to view-only analytics and experience data.

2 Validate administrative entitlements for Bev

  1. In the same Incognito window, go to the Experience Center landing page: https://console.zscaler.com/
  2. Authenticate with Bev's account:
    • Username: bev@<Student FQDN>
    • Password: Admin-123!
  3. Click Sign in.
  4. Type Admin Sign-On Policy in the Search menu and select the result (Administration > Authentication > Settings).
  5. Confirm that in the Admin Sign-On Policy window, Bev is allowed to Add Rule (the button is enabled) because they are a member of the Zscaler Global Administrators group.
  6. Click the Account settings icon in the top-right corner of the dashboard to Sign out.
As Bev: Search → Admin Sign-On Policy. The Add Rule button is enabled, which is the proof of Global Admin rights.

Note: The Add Rule button is only enabled for users with sufficient administrative privileges. As a member of the Zscaler Global Administrators group, Bev has full administrative access, including managing sign-on policies.

3 Validate the service entitlement for Joe through Zscaler Client Connector

  1. On the Corp Client PC, in the Windows taskbar (bottom-right corner), click the Show hidden icons arrow ^.
  2. Select the Zscaler Client Connector icon, then click Open Zscaler.
  3. On the Zscaler Client Connector login page, authenticate with Joe's account:
    • Username: joe@<Student FQDN>
    • Password: Admin-123!
  4. Click Sign in.
  5. In the Zscaler Client Connector console, verify that Zscaler Internet Access is ON for Joe.
  6. After verifying Joe's service entitlement, log out of Zscaler Client Connector. You will log in again later with a different account.
ZCC login. Enter Joe's username to start sign-in.
Zscaler Internet Access is ON for Joe, which proves the ZIA service entitlement works. Log out of ZCC afterwards.
🧠
MENTAL NOTE
Entitlements go to groups, never to people. Administrative Entitlements (Administration > Role Management) = what you can do in the console, always paired with a role. End User Entitlements = whose traffic ZCC protects. Joe = Helpdesk L1 = read-only ZIA + ZDX and ZIA service. Bev = Zscaler Global Administrators = everything. Test authorization (Add Rule) as well as authentication (login).

QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, joe@, bev@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide follows the Nav 2.0 layout: open features from the Search menu.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
SaaS/Cloud App Policy that allows or blocks individual cloud apps (e.g., allow YouTube). It is enforced ahead of URL category rules.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZAgent
AI assistant in the Experience Center (top-right icon). With the Digital Experience agent and Troubleshooting skill, it explains the root cause of a user's poor experience.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
