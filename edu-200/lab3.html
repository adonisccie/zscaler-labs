Lab 3: Forward Traffic with the Zscaler Client Connector

LAB 3

Scenario: As the Zscaler administrator, your next goal is to configure the Zscaler Client Connector (ZCC) to securely forward all user traffic to Zscaler for inspection and protection, whatever the protocol. This enables firewall functionality and secure internet access, and keeps users covered on any platform, both on and off trusted networks.

Objectives: By the end of this lab you will:

  • Configure forwarding options to send all user traffic securely to Zscaler.
  • Set up forwarding profiles and platform settings for Windows devices.
  • Confirm that features such as Private Access, Internet Security and Digital Experience are enabled and working.
  • Confirm the Corp Client PC traffic is forwarded to Zscaler and verify entitlements and settings.
Time: ~20 minutes
Tasks: 3.1 – 3.2
💭 THINK FIRST · FORWARDING PROFILES

A forwarding profile answers one question for every network the laptop might be on: how should traffic get to Zscaler, if at all? The app profile then decides who gets that forwarding profile.

  • The guide insists on Z-Tunnel 2.0 instead of Z-Tunnel 1.0. What traffic would a 1.0 tunnel miss, and which later lab would break because of it?
    Q1 — MODEL ANSWER
    Z-Tunnel 1.0 is essentially a web (HTTP/HTTPS) tunnel. Z-Tunnel 2.0 captures traffic at the network layer, so it carries all ports and protocols, including SSH, ICMP, DNS and non-web apps. Without it, the Cloud Firewall never sees non-web flows, so Lab 4 (allowing SSH/ICMP, blocking WhatsApp) and the DNS controls in Lab 7 would have nothing to act on. That traffic would leave the PC directly and bypass policy.
  • You set VPN-Trusted and Off-Trusted to Same as "On-Trusted Network". In a real company, why might you not want to tunnel everything when the laptop is already on the corporate (trusted) network?
    Q2 — MODEL ANSWER
    An office often already forwards traffic to Zscaler through a GRE/IPsec tunnel from the branch router. Tunnelling from ZCC as well would double-tunnel, adding overhead and latency. For ZPA, a user sitting next to the app on the LAN may be better off reaching it directly. That's why trusted-network detection exists: each network context can have a different action. The lab uses one action everywhere because the Client PC is always "off" a real corporate network and you want consistent behavior for testing.
  • After you click Add on the Windows App Profile, ZCC might still show the old policy. What's actually happening between the console and the client, and how do you speed it up?
    Q3 — MODEL ANSWER
    Saving in the console only updates the cloud's copy of the policy. ZCC pulls its app profile on a schedule (or at login), so there's a short window where the client still runs the previous one. In ZCC, open More → Update Policy to force an immediate fetch, then check that App Policy reads HandsOnLab. Knowing about this pull model also explains many "I changed it but nothing happened" support tickets.
Task 3.1 Configure Traffic Forwarding Options ▾

In this task, you will configure traffic forwarding so that all users send their traffic to Zscaler, whatever the protocol.

1 Log in to the Experience Center

  1. Go to https://console.zscaler.com and authenticate with the student account:
    • Username: student@<Student FQDN>
    • Password: the password you set at your first login in Lab 1.
  2. Click Sign in.

2 Create the Forwarding Profile

  1. Go to Infrastructure > Connectors > Client > Forwarding Profile for Platforms.
  2. Click Add Forwarding Profile.
  3. Name the profile: HandsOnLab
  4. Scroll down. In the Windows Driver Selection section, select Packet Filter Based.
Infrastructure → Connectors → Client → Forwarding Profile for Platforms.
Click + Add Forwarding Profile.

Note: If Zscaler Client Connector version 4.8 or higher is installed on Windows, the app defaults to the packet filter-based driver and ignores the Route-Based configuration option.

3 Set the ZIA forwarding action

  1. In the FORWARDING PROFILE ACTION FOR ZIA section:
    • For On-Trusted Network, select Tunnel.
    • For the Tunnel version selection, use Z-Tunnel 2.0.
  2. For VPN Trusted Network and Off-Trusted Network, tick the box next to Same as “On-Trusted Network”.

Note: Tunnel 2.0 is needed to capture all traffic and tunnel it to ZIA for Firewall functionality.

Profile name HandsOnLab, driver Packet Filter-Based, ZIA On-Trusted = Tunnel with Z-Tunnel 2.0.

4 Set the ZPA forwarding action and save

  1. In the FORWARDING PROFILE ACTION FOR ZPA section:
    • For On-Trusted Network, select Tunnel.
    • For VPN Trusted Network and Off-Trusted Network, select Same as “On-Trusted Network”.
  2. Click Save.
Same as “On-Trusted Network” ticked for VPN-Trusted and Off-Trusted (ZIA and ZPA), ZPA On-Trusted = Tunnel, then Save.

5 Add the Windows App Profile

  1. In the left navigation panel, go to Platform Settings > Windows.
  2. Click Add Windows Policy under the App Profile section.
  3. Configure the following settings (leave any field not listed at its default):
    • Name: HandsOnLab
    • Rule Order: 1
    • Status: Enable
    • Forwarding Profile: select the HandsOnLab profile you created earlier.
    • Install Zscaler SSL Certificate: On
    • User Groups: Select All.
  4. Click Add.
Platform Settings → Windows → App Profiles → + Add Windows Policy.
Name and Forwarding Profile HandsOnLab, Install Zscaler SSL Certificate On, User Groups All Selected, then Add. Installing the certificate here prepares the PC for SSL inspection in Lab 5.
Task 3.2 Sign In to the Zscaler Client Connector and Verify Protection ▾

In this task, you will log in to the Zscaler Client Connector to confirm that the Corp Client PC is now protected by the app.

1 Open the Zscaler Client Connector

  1. On the Corp Client PC, in the Windows taskbar (bottom-right corner), click the Show hidden icons option.
  2. Select the Zscaler Client Connector icon and click Open Zscaler.
  3. In the Zscaler Client Connector console, log in with the student credentials:
    • Username: student@<Student FQDN>
    • Password: the one you set in Lab 1.
  4. Click Sign in.
Hidden icons → Zscaler icon → Open Zscaler.
Sign in to ZCC as the student admin.

2 Verify Private Access settings

  1. On the Private Access page, confirm the following:
    • Service Status: ON.
    • Client and Broker IP addresses: populated.
Private Access: Service Status ON, Broker and Client IPs populated. That means ZPA is connected.

Note: If you don't see ZPA or ZDX in Zscaler Client Connector, your user may not have the correct service entitlements. To check entitlements for the Student Admin user, go to Administration > Users in the portal, select the Student Admin user account and click the Edit icon. In the Edit User pane, go to the Entitlements section and confirm that ZPA and ZDX are assigned. The Broker IP address highlighted in the screenshot is only an example and may differ from the one in your own Zscaler Client Connector.

3 Verify Internet Security settings

  1. On the Internet Security page, confirm the following:
    • Service Status: ON.
    • Username: displays correctly.
    • Total Bytes Sent / Received: these values go up as you load web pages.
Internet Security ON. Bytes Sent/Received increasing is your proof that web traffic now goes through ZIA.

4 Verify Digital Experience settings

  1. On the Digital Experience page, confirm that:
    • Service Status: ON.
    • Authentication Status: Authenticated.
    • Username: displays correctly.
Digital Experience ON and Authenticated. ZDX probes can now report on this user.

5 Verify the applied App Policy

  1. On the More page, confirm that:
    • App Policy: HandsOnLab
More → About: App Policy: HandsOnLab. The Update Policy link is in the same section.

Note: If the updated policy HandsOnLab doesn't show in Zscaler Client Connector (ZCC), click Update Policy under the More tab in ZCC to force a policy refresh. Wait a few seconds and check again.

6 Verify traffic forwarding

  1. Go to https://ip.zscaler.com
  2. Confirm that you are reaching the Internet through a service edge geographically close to the user.
ip.zscaler.com confirms you're "accessing the Internet via Zscaler Cloud" and names the service edge in use.

Note: The Service Edge location in the results will usually be one geographically close to the user.

Troubleshoot — ZCC still shows the old policy or a service is OFF

First use More → Update Policy and wait a few seconds. If App Policy still isn't HandsOnLab, check that the Windows policy is Enabled, has Rule Order 1, uses the HandsOnLab forwarding profile and targets All user groups. If Private Access or Digital Experience is missing, check the Student Admin user's ZPA/ZDX service entitlements as described in the note above.

🧠
MENTAL NOTE
Forwarding Profile = how (Packet Filter driver, Tunnel + Z-Tunnel 2.0 so all protocols reach the firewall). App Profile = who + which profile (Windows policy HandsOnLab, rule 1, all groups, install the SSL cert). Proof it works: ZCC shows Private Access / Internet Security / Digital Experience ON, App Policy HandsOnLab, and ip.zscaler.com says you're behind Zscaler.

LAB PROGRESS
QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, JoeSupport@, BevIT@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This lab uses the Nav 1.0 (Original) layout.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
Application-layer policy that identifies apps by DPI (e.g., WhatsApp) regardless of port. Separate from Firewall Filtering.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZDX Copilot
AI assistant in ZDX that answers natural-language questions and summarizes root cause for a user's experience issue.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
