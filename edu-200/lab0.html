OVERVIEW

Welcome to the Zscaler for Users — Administrator (EDU-200) Hands-on Lab. Throughout the hands-on lab, you will practice skills that you learned during the EDU-200 e-learning. By the end of the hands-on lab, you will be able to:

💭 THINK FIRST · THE LAB ENVIRONMENT

Before you touch the console, think about how this small pod stands in for a real enterprise: one user endpoint, one data center, and a cloud service in between.

  • The Corp Client PC sits at 192.168.1.1 and the data center is 10.0.0.0/24, yet there is no VPN between them. How do you expect the client to reach intranet apps on the Windows Server?
    Q1 — MODEL ANSWER
    Through ZPA. The Client Connector on the PC builds an outbound tunnel to the Zero Trust Exchange, and the Corp App Connector (10.0.0.4) builds its own outbound tunnel from inside the data center. The ZTE stitches the two together per application. Neither side accepts inbound connections, so the data center never has to expose a listening VPN concentrator to the Internet.
  • Every admin and test account in your pod shares the same session password, and all login IDs end in your Student FQDN. Why would a training environment be designed this way, and why would you never do it in production?
    Q2 — MODEL ANSWER
    The FQDN makes each pod a separate, isolated tenant identity, so dozens of students can work in parallel without clashing. One shared password removes friction so the class can focus on Zscaler concepts. In production, shared credentials remove accountability (you can't tell who did what in the audit logs) and turn one leaked password into a breach of every account. That's why real tenants use SSO, unique credentials and MFA.
  • The Corp Win Svr 2025 is the DNS server for the data center, but the Corp Client PC sits outside it and uses public DNS. When the client asks for intranet.patraining.safemarch.com, which side should resolve that name, and why?
    Q3 — MODEL ANSWER
    The data-center side. Public DNS has no idea what the intranet host is, and you wouldn't want internal names published there anyway. Once the domain is defined in a ZPA application segment, the Client Connector recognizes the request and hands back a placeholder (synthetic) address, while the App Connector resolves the real name with the internal DNS server (the Win Svr). Internal addresses never leak to the endpoint or the Internet, and the user still just types the hostname.

Lab Description and Scenario

For these lab exercises, consider the scenario where your organization (Labtenant) has deployed the Zscaler Zero Trust Exchange to protect against Internet security threats, control Internet access, and provide secure access to private resources. Your organization is also interested in the end-user experience, which can be reported on with the Zero Trust Exchange.

You will deploy the Zscaler Client Connector (ZCC) application to end-user devices to control Internet access, provide access to private applications, and to probe, benchmark, and measure the digital experiences for each user within the organization. To support the rollout, you are tasked to:

  • Connect users to the Zero Trust Exchange by deploying ZCC to Windows client devices.
  • Configure SSL inspection.
  • Deploy Zscaler Digital Experience (ZDX) reporting and create an initial set of ZDX applications and probes.
  • Configure user access to both Internet and private applications.
  • Verify Cyberthreat Protection services.
  • Verify Data Protection services.

Lab Setup

You will have access to the Zscaler Zero Trust Exchange (Service Portal (formerly ZIdentity) / ZIA / ZPA / ZDX) and a lab ‘Pod’. For your lab exercises, you will configure the Service Portal, ZIA, ZPA, and ZDX services and explore the end-user experience. You will use a Windows 10 Client PC in the pod to connect to the Zero Trust Exchange.

Lab Topology

Lab topology: the Corp Client PC reaches the Internet through the Zero Trust Exchange, and reaches the Corporate Data Center (10.0.0.0/24: Corp Win Svr 2025 + Corp ZPA Connector) through ZPA. The admin portals (ZIA, ZPA, ZDX) are all reached through the Experience Center / Service Portal.

Virtual Machines

  • Windows Client PC: Corp Client PC
    • Username | Password: student | Admin-123!
  • Windows Server: Corp Win Svr 2025
    • Provides local directory services through Active Directory.
    • Runs HTTP/HTTPS intranet applications and file services.
    • Functions as the DNS server for hosts in the data center.
    • Username | Password: administrator | Admin-123!
  • App Connector: Corp App Connector. A Red Hat Enterprise 9.4 VM, pre-deployed in the network to simulate having already deployed the VM from the OVA/OVF file with the App Connector RPM installed.
    • Username | Password: admin | Zscaler1!

Lab Access Information

For this course, each student gets a unique student ID with a dedicated virtual environment, plus a matching Student FQDN and a set of admin and test user accounts for Zscaler. All user credentials and portal addresses are in the lab access instructions for your assigned training pod. These include:

  • Your Student ID, a unique identifier for your pod (e.g., zs9901).
  • Your Student FQDN, a unique domain for your pod (e.g., zs9901.labtenant.com).
  • Your admin login credentials for the Zscaler portals:
    • The login name uses the format student@<Student FQDN>, where <Student FQDN> is the domain assigned to your pod (for example, student@zsxxxx.labtenant.com).
    • The password is unique to your session and is the same on every configured admin and user account in the pod.

How This Guide Navigates the Experience Center

This revision of the guide is written for the Experience Center Nav 2.0 interface. Instead of long click paths, each step tells you to type a feature name into the Search menu at the top of the console and select the matching result. The Nav 2.0 menu location follows in parentheses, so you also learn where the feature lives. For example: type Firewall Control in the Search menu (Internet Access > Policy).

Note: The main Nav 2.0 menu groups features by outcome: Analytics, Administration, Internet Access, Private Access, Cyberthreat Protection, Digital Experience, Data Security, Infrastructure and Data Explorer. If a menu path in this guide doesn't match your console exactly, search for the feature name instead.

LAB PROGRESS
QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, joe@, bev@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide follows the Nav 2.0 layout: open features from the Search menu.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
SaaS/Cloud App Policy that allows or blocks individual cloud apps (e.g., allow YouTube). It is enforced ahead of URL category rules.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZAgent
AI assistant in the Experience Center (top-right icon). With the Digital Experience agent and Troubleshooting skill, it explains the root cause of a user's poor experience.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
