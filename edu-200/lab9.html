Lab 9: Provision ZPA Infrastructure

LAB 9

Scenario: Safemarch Corporation is preparing to launch internal applications and needs secure, policy-driven connectivity without exposing those applications to the internet. As a Zscaler administrator, you will deploy and provision ZPA App Connectors across data centers and cloud platforms. These App Connectors provide encrypted connectivity through the Zero Trust Exchange (ZTE) while keeping internal apps protected.

Objectives: By the end of this lab you will:

  • Deploy and provision an App Connector using an OAuth-based token.
  • Activate the App Connector so it can communicate securely with the ZPA infrastructure.
  • Validate the connection and make sure the App Connector is working correctly.
Time: ~25 minutes
Tasks: 9.1 – 9.2
💭 THINK FIRST · APP CONNECTORS

The App Connector is ZPA's foothold next to your private apps. It only ever dials out to the Zero Trust Exchange, and nothing dials in.

  • A traditional VPN concentrator sits in the DMZ listening for connections. The App Connector needs no inbound firewall rules at all. What does that change for an attacker scanning the internet?
    Q1 — MODEL ANSWER
    There is nothing to find. No public IP, no open port, no login page to brute-force and no VPN appliance CVE to exploit. The connector makes outbound TLS connections to the ZPA cloud, and user sessions are stitched together inside the ZTE only after policy allows them. Apps become invisible to the internet, which removes the attack surface instead of guarding it.
  • You create an App Connector Group (OnPrem) before enrolling any connector. Why group connectors at all, and why might you put two or more connectors in the same group?
    Q2 — MODEL ANSWER
    Policy and app segments reference a group (through server groups), not individual VMs, so you can add, remove or upgrade connectors without touching any policy. Several connectors in one group, at the same location, give high availability and load sharing: if one goes down or is being updated in its maintenance window, the others keep carrying traffic. The location also helps ZPA choose the closest connector and Service Edge.
  • The enrollment token is short-lived and single-use, and you regenerate it by deleting /opt/zscaler/var/*. Why is that safer than a long-lived shared key baked into an image?
    Q3 — MODEL ANSWER
    A long-lived key that leaks (from a template, a script or a screenshot) lets anyone enroll a rogue connector into your tenant. An OAuth code generated on the device itself and approved by an admin in the console binds enrollment to that specific VM and that moment. If it expires or is used once, it's worthless to an attacker. Clearing the state directory forces a fresh identity and a new code.
Task 9.1 Provision an App Connector ▾

In this task, you set up the App Connector side in the console by creating an App Connector Group to register the connector into the Zero Trust Exchange.

1 Access the Admin Portal

  1. On the Corp Client PC VM, sign in with the following credentials:
    • Username: student
    • Password: Admin-123!

2 Configure the App Connector Group

  1. In the Experience Center, go to Infrastructure > Private Access > App Connector Groups.
  2. Select +Add and enter the following values in Add App Connector Group:
    • Name: OnPrem
    • Status: Enabled
    • Description: optional
    • Signing Certificate: Connector
    • Other Configurations: leave at their defaults
    • App Connector Location: enter your current city
  3. Select Save.
  4. Verify that the App Connector Group was created.

Note: Choose an App Connector location close to where you are.

Infrastructure → Private Access → App Connector Groups.
Name OnPrem, Status Enabled, Signing Certificate Connector.
Scroll down to App Connector Location, enter your city, then Save.

Note: If the maintenance window warning appears, select "I understand" to continue with the configuration.

OnPrem appears in the list, Enabled, with no connectors yet.
Task 9.2 Activate the App Connector ▾

In this task, you activate the App Connector and confirm traffic can flow securely to ZPA.

1 Configure the App Connector

  1. Launch the Corp ZPA Connector VM.
  2. Log in to the Corp ZPA Connector VM by clicking SSH in the left side panel to log in automatically.
  3. Alternatively, use the CON options to sign in to the Corp ZPA Connector VM with these credentials:
    • Username: admin
    • Password: Zscaler1!
  4. To view the token, type: cat /etc/issue
The SSH icon on the connector VM's tab logs you in automatically.
cat /etc/issue prints the OAuth token and the "enter the code … to authenticate" line.

2 Regenerate a new authentication token from the CLI

  1. Stop the ZPA Connector service: sudo systemctl stop zpa-connector
  2. Switch to root user privileges: sudo su
  3. Delete the existing OAuth token files: rm -rf /opt/zscaler/var/*
  4. Restart the ZPA Connector service to generate the new OAuth token: sudo systemctl start zpa-connector
  5. To view the token, type: cat /etc/issue
The full sequence: stop → sudo su → clear /opt/zscaler/var/* → start → cat /etc/issue shows a new token.

Caution: rm -rf /opt/zscaler/var/* wipes the connector's enrollment state. Type it carefully (use Actions → Send Text) and run it only on the Corp ZPA Connector VM.

3 Enter the token in the App Connector to deploy it

  1. In the Experience Center landing page (Corp Client PC), go to Infrastructure > Private Access > App Connectors.
  2. Select Add.
    • Group: OnPrem (the App Connector Group you created in Task 9.1)
    • Enrollment Tokens: add the token generated in Task 9.2, Step 2 (for example, RPSTV-QZLJM).
    • Select Add.
    • Select Save.
  3. Confirm that the App Connector appears in the list.
  4. Select the App Connector name to view its details, including Host OS, PSE, Location, IP addresses and Uptime.
App Connectors → Add: Group OnPrem, paste the token, click Add, then Save.

Note: If the generated token doesn't work or has expired, repeat the previous steps (Step 2).

The connector appears in OnPrem and turns Connected.

Note: The App Connector Connection Health may take about 30 seconds to change from Disconnected to Connected. Continue with the next lab task and check the status again shortly.

Connector details: host platform, software version, location, public/private IP and uptime.

QUICK REFERENCE ▲
Student FQDN
Your unique tenant domain, e.g. zs9901.labtenant.com. Used in all login IDs (student@, JoeSupport@, BevIT@).
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This lab uses the Nav 1.0 (Original) layout.
Service Portal
Formerly ZIdentity. The identity layer where users, groups, departments and entitlements are managed and where admins and users authenticate.
ZCC
Zscaler Client Connector, the endpoint agent that tunnels traffic to the Zero Trust Exchange.
Z-Tunnel 2.0
Network-layer tunnel that captures all IP protocols, not just web traffic. Required for Cloud Firewall.
Service Entitlement
Lets a user or group use a Zscaler service (ZIA, ZPA, ZDX) through ZCC.
Admin Entitlement
Lets a user or group administer a service in the console, scoped by a role (e.g. Executive Insights App, ZDX Read-only Admin).
SyncZPA
Additional user attribute (optional value, e.g. 123) that the lab uses to sync the user into ZPA for policy use.
Forwarding Profile
Sets the tunnel type/version and forwarding action for each network context (on-trusted, off-trusted, VPN-trusted).
Cloud App Control
Application-layer policy that identifies apps by DPI (e.g., WhatsApp) regardless of port. Separate from Firewall Filtering.
SSL Inspection
Trusted man-in-the-middle: ZIA decrypts, inspects and re-encrypts traffic using the Zscaler CA. The endpoint must trust the Zscaler Root CA.
Cert Pinning Bypass
A "Do Not Inspect" SSL rule for apps that check the server certificate fingerprint. It must sit above the Inspect All rule.
DLP Engine
Defines what sensitive content looks like (dictionaries + thresholds). Paired with a DLP rule that sets the action.
App Connector
ZPA software in the data center that builds outbound TLS tunnels to the ZPA cloud. No inbound firewall rules needed.
Enrollment Token
OAuth-based one-time code shown on the App Connector console (cat /etc/issue). Entered in App Connectors → Add to enroll the connector into a group.
App Segment
ZPA object that defines a private resource by domain/IP and port. Combined with an access policy, it grants ZPA access.
SIPA
Source IP Anchoring. Sends selected ZIA traffic out through a ZPA App Connector so the destination sees your organization's own egress IP.
ZDX Score
0–100 measure of end-to-end digital experience. Below 50 = Poor, 50–79 = Okay, 80 and above = Good.
Y-Engine (Analyze Score)
ZDX root-cause engine. Click a point on ZDX Score Over Time → Analyze Score to see the ranked factors (Wi-Fi, DNS, latency…) and their confidence.
ZDX Copilot
AI assistant in ZDX that answers natural-language questions and summarizes root cause for a user's experience issue.
ZDX Probe
Synthetic test run by ZCC in the background that continuously measures DNS time, TCP connect, server response and page fetch time.
