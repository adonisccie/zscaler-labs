Lab 2: Automate ZIA Policies with the Zscaler Python SDK

LAB 2

Scenario: Your organization is moving repetitive ZIA policy work — creating URL filtering rules, tagging them, ordering them, and creating SSL inspection rules — out of the console and into reusable Python automation. As the automation engineer, you use the official zscaler-sdk-python package to query URL categories and cloud applications, create rule labels, build URL filtering and SSL inspection rules, reorder them, and verify the results in Experience Center.

  • Set up a Python virtual environment in VS Code and install the official Zscaler Python SDK
  • Use breakpoints to step through and inspect SDK calls
  • Query ZIA URL categories and cloud applications through the SDK
  • Create rule labels and associate them with policy rules
  • Create, reorder, and delete URL filtering and SSL inspection rules through the SDK
  • Verify all changes in the Experience Center
Time: ~50 minutes
Tools: VS Code, Python 3.14, zscaler-sdk-python

Note: This lab is interactive. The script prompts you in the terminal at several points — for credentials, and for yes/no decisions at each stage. Keep the terminal panel visible while you work.

Task 2.2 Set Breakpoints in main.py ▾

In this task, you set breakpoints so the script pauses at each significant SDK call — letting you inspect what the SDK is doing before it runs.

  1. In the Explorer pane, expand URL Filtering Rule and open main.py.
  2. Set a breakpoint on the line that looks up URL categories (line 396) — click in the gutter to the left of the line number; a red dot appears, indicating an active breakpoint.
  3. Set a breakpoint on the line that creates the rule label (line 416).
A red breakpoint dot on line 396 pauses execution right before the URL categories lookup call.
A second breakpoint on line 416 pauses execution right before the rule label is created.

Task 2.5 Create a Rule Label ▾
  1. At the Create a rule label? prompt, type Y and press Enter.
  2. The debugger pauses at the rule label breakpoint. Select Continue to let the SDK create the label.

Note: Rule labels do not change rule behavior. They make rules easier to find, filter, and govern when you manage many rules through automation.

Execution paused right before the SDK call that creates the rule label — select Continue to let it run.
Verify: the terminal output confirms the rule label was created and shows its ID.
Task 2.6 Create Three URL Filtering Rules ▾
  1. At the Create URL filtering rules? prompt, type Y and press Enter.
  2. The debugger pauses at the URL filtering rule breakpoint inside the creation loop. Select Continue three times to let the SDK create three URL filtering rules with the Block action.
  3. Verify that all three URL filtering rules were created successfully.
The breakpoint fires once per loop iteration — Continue three times to create all three rules.
  1. In the Experience Center dashboard, navigate to Policies > URL Control > URL Filtering > URL Filtering Policy and verify the rules' status.
  2. When prompted to display a topology diagram of how the URL filtering rules are wired up, type Y and press Enter.
All three URL filtering rules appear in Experience Center with the Block action.
The topology diagram visualizes how the rule label and URL categories tie into each of the three rules.
Task 2.7 Invert the Rules' Evaluation Order ▾
  1. When the terminal displays "Invert the rules' evaluation order (1,2,3 → 3,2,1)?", type Y and press Enter.
  2. When the terminal displays the follow-up prompt "Invert the rules' order now?", type Y and press Enter to execute the reorder.
Confirm the reorder in two steps — the intent prompt, then the execution prompt.
  1. When the terminal displays "Re-render the topology with the new order?", type Y and press Enter.
  2. When the terminal displays "Delete the rules and label you just created and finish?", type Y and press Enter to delete and clean up.
  3. Click the Stop button (the red square) on the debug toolbar to terminate the active debugging session.
The re-rendered topology confirms the rules now evaluate in reverse order.
Cleanup deletes the three URL filtering rules and the rule label, returning the tenant to its starting state.

Task 2.8 Create and Reorder SSL Inspection Rules ▾

Note: A ZIA SSL inspection rule determines how TLS traffic is handled when it matches specified categorization criteria. The rule action can decrypt, pass through, or block the matching session. SSL inspection rules execute before other policies in the pipeline.

1 Open the script and set breakpoints

  1. In VS Code, expand the SSL Inspection Rules folder and select main.py to open it in the editor.
  2. Locate the run_lab function (line 347).
  3. Set a breakpoint on the line that calls the cloud application lookup (line 453).
  4. Set a breakpoint on the line that creates the SSL inspection rule (line 516).
Open the SSL Inspection Rules project's main.py.
The run_lab function at line 347 orchestrates the entire SSL inspection rule flow.
Breakpoint on line 453 — the cloud application lookup call.
Breakpoint on line 516 — the SSL inspection rule creation call.

2 Start the debugger and authenticate

  1. Confirm main.py under SSL Inspection Rules is active, then select Run > Run and Debug.
  2. When prompted, select Python Debugger and then Python File.
  3. Supply your credentials when prompted: <Client ID>, <Client Secret>, then <Vanity Domain>.
Launch the debugger for the SSL Inspection Rules script.
Authenticate with the same API client credentials used throughout the course.

3 Inspect URL category and cloud application lookups

  1. When the script prompts you to query URL categories, enter Y.
  2. The debugger pauses at the cloud application lookup breakpoint — select Continue (or press F5) to resume execution.

Note: The returned cloud application IDs will be used alongside the URL category IDs when creating the SSL inspection rule.

URL categories resolved — the script moves on toward the cloud application lookup breakpoint.
The debugger pauses at the cloud application lookup — the returned IDs (e.g. for ChatGPT) will pair with the URL category IDs.

4 Create the shared rule label and the three SSL inspection rules

  1. When prompted to create the shared rule label, enter Y. Verify the terminal shows [OK] Rule Label '<label_name>' created (id=<label_id>).
  2. When prompted for the rule action, enter BLOCK. Enter Y when prompted for Create three SSL Inspection rules.
  3. The debugger pauses at the breakpoint inside the creation loop — select the play button to create each rule; the loop executes three times.
The shared rule label ties all three SSL inspection rules together for later cleanup and filtering.
The creation loop pauses on each iteration — resume three times to create rules A, B, and C with the Block action.

5 Review the relationship diagram and verify in Experience Center

  1. After all three rules are created, examine the visualization the script outputs. Answer Y when prompted for Show a diagram of how these rules are wired up?
  2. Confirm that cloud applications are associated with URL categories, and URL categories are associated with the SSL inspection rules.
  3. Switch to the Experience Center portal and select SSL/TLS Inspection under Policies > Common Configuration.

Verify: Three new SSL inspection rules appear with rule order A = 1, B = 2, and C = 3. The action is Block, and each rule references the expected cloud application (for example, ChatGPT).

The relationship diagram shows cloud applications feeding into URL categories, which feed into the three SSL inspection rules.
Rules A, B, C appear in Experience Center with order 1, 2, 3 and the Block action confirmed.

6 Reorder the rules and verify again

  1. Return to VS Code, resume execution, and confirm the reorder operation with Y.
  2. Switch back to the Experience Center portal and select Refresh on the SSL inspection rules page.

Verify: The rule order is now inverted — C = 1, B = 2, A = 3.

Confirm the reorder in the terminal to proceed.
After Refresh, the rule order shows C = 1, B = 2, A = 3 — confirming the SDK's reorder call took effect.

7 Re-render the topology and clean up

  1. Answer Y when prompted for Re-render the topology with the new order.
  2. Return to VS Code. When prompted to delete the created rules and labels, enter y.
  3. Allow the script to complete.
Cleanup removes the three SSL inspection rules and the shared label — the tenant returns to its starting state.
