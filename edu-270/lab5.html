Lab 5: Working with ZIA Rules Using the Zscaler Terraform Provider

LAB 5

Scenario: You've learned to use the Zscaler Python SDK and are now ready to automate ZIA configuration with Terraform. In this lab, you use the Zscaler Terraform provider for ZIA to deploy and manage rules — including URL filtering and SSL inspection rules — then clean up the environment by destroying the resources you created.

  • Explain how Terraform manages cloud and SaaS resources through provider APIs
  • Describe the role of HCL, JSON data files, and locals.tf in a Zscaler Terraform project
  • Configure environment variables to authenticate the Zscaler Terraform provider for ZIA
  • Initialize a Terraform working directory and review an execution plan
  • Apply a Terraform plan to create ZIA resources, verify them, then destroy them
Time: ~25 minutes
Tools: VS Code, Terraform, zscaler/zia provider
Task 5.1 Open the Lab Folder in Visual Studio Code ▾

In this task, you open the ZIA lab folder in VS Code to review the Terraform files.

  1. In the Corp: Client PC, go to C:\Labs\Lab 5-6.
  2. Right-click the ZIA folder to Open with Code.
  3. Enable the checkbox and trust the authors.
Navigate to the ZIA Terraform project inside Lab 5-6.
Open the ZIA folder with VS Code.
Trust the authors, then confirm all the Terraform files are visible under ZIA.
  1. Click on versions.tf to view provider information.
  2. Open locals.tf and review the contents of the file.

Note: versions.tf declares the Zscaler ZIA Terraform provider that this project depends on. The required_providers block names the provider locally as zia and points its source to zscaler/zia — the official Zscaler publisher on the Terraform Registry.

versions.tf pins the zscaler/zia provider version and source.

Note: locals.tf loads the JSON data files into variables and defines associations between resources — for example, labels to rules, URL categories to rules.

locals.tf is where rule data (from JSON) gets wired into the resource blocks that create ZIA rules.
Task 5.2 Configure Environment Variables for Authentication ▾

In this task, you set the environment variables required by the ZIA Terraform provider for authentication.

  1. Open a new terminal window and enter each environment variable command:
    • $Env:ZSCALER_CLIENT_ID= <Client ID>
    • $Env:ZSCALER_CLIENT_SECRET= <Client Secret>
    • $Env:ZSCALER_VANITY_DOMAIN= <Vanity Domain>

Note: Values should be quoted, e.g. $Env:ZSCALER_CLIENT_ID= "iqenSub1706g3".

Terraform's ZIA provider reads these three environment variables at init/plan/apply time — no credentials live in the .tf files.
  1. Verify the environment was set by running echo $Env:ZSCALER_CLIENT_ID.
Echo the variable back to confirm it was captured correctly before running terraform init.
Task 5.3 Initialize and Plan the Terraform Deployment ▾

In this task, you initialize the Terraform working directory and generate an execution plan.

  1. Initialize Terraform: terraform init
  2. Verify Terraform is successfully initiated.
terraform init downloads the zscaler/zia provider and initializes the working directory.
  1. Generate an execution plan: terraform plan -out=tfplan
Generate and save the execution plan to the tfplan file.
The plan output lists every resource Terraform intends to create — review it before applying.
Task 5.4 Apply the Terraform Plan and Verify Resources ▾

In this task, you apply the saved plan to deploy resources to ZIA and verify them in the Admin Portal.

  1. Apply the plan: terraform apply tfplan

Note: Wait for the deployment to complete. Terraform calls the underlying ZIA APIs to create each resource — this process may take several minutes.

terraform apply tfplan executes exactly the plan you reviewed — no surprises.
  1. Navigate to Policies > Access Control > Internet & SaaS > URL Control > URL Filtering and confirm the new rules appear.
  2. Navigate to URL Categories and confirm custom URL categories were created.
  3. Navigate to Policies > Common Configuration > SSL/TLS Inspection > SSL/TLS Inspection Policy and confirm the new rules appear.
URL filtering rules deployed by Terraform now appear in Experience Center.
Custom URL categories created by the same apply — Terraform manages both categories and rules together.
SSL/TLS Inspection rules deployed alongside the URL filtering rules in the same apply.
Task 5.5 Destroy Terraform-Managed Resources ▾

In this task, you use Terraform to remove all resources created in the previous task.

  1. In the Terminal, execute: terraform destroy
terraform destroy removes every resource Terraform created — the tenant returns to its starting state.

Terraform Provider
A plugin (zscaler/zia) that translates HCL resources into OneAPI calls.
HCL
HashiCorp Configuration Language — the declarative syntax used to define Terraform resources.
versions.tf
Declares which providers a project depends on and their version constraints.
locals.tf
Loads external data (e.g. JSON) into variables and defines resource associations.
terraform init
Downloads the declared providers and initializes the working directory.
terraform plan
Previews what will be created, changed, or destroyed — without making changes.
terraform apply
Executes a plan, calling the provider's API to create the declared resources.
terraform destroy
Removes every resource Terraform manages in the current state.
