Lab 1: Exploring Zscaler APIs with Postman and ZIdentity Automation

LAB 1

Scenario: As an automation engineer at your organization, you've been asked to provision a new API client that downstream Python and Terraform automations will use to call Zscaler APIs. In this lab you use Postman to import a provided collection, configure environment variables, retrieve a ZIdentity access token, look up the correct service and scope IDs, create the new API client, generate its client secret, and confirm the client can authenticate successfully.

  • Import a Postman collection and configure collection variables for ZIdentity
  • Create a ZIdentity access token using client credentials
  • Create a new API client through ZIdentity
  • Add a client secret to the new API client
  • Verify the new client by requesting an access token and confirming the configuration in Postman
Time: ~30 minutes
Tools: Postman, Experience Center
Task 1.1 Exploring APIs — Getting Started With Postman ▾

In this task, you sign in to Postman and import the lab collection into your student workspace.

1 Sign in and open Postman

  1. Sign in to Corp: Client PC using the credentials assigned to you. Refer to your lab access instructions.
  2. Open the Postman application from the desktop.
  3. Click Sign In.
The Postman desktop app on Corp: Client PC — click Sign In to authenticate before importing any collection.

2 Authenticate with your assigned Postman account

  1. The Sign In option opens a browser window — enter your username and password.
  2. Sign in with the Postman username and password assigned to you for this lab in your lab access instructions.
    • Select the checkbox to verify you are human.
Postman's browser-based sign-in — enter the username and password from your lab access instructions.
Select the checkbox to verify you are human before Postman completes the sign-in.

Note: Selecting the Zscaler Student xx tile prompts you to open the Postman application.

Choosing your assigned Zscaler Student tile hands control back to the Postman desktop app, now signed in.

3 Find the Zscaler OneAPI collection

  1. On the Postman Home page, click the Home icon and select Public API Network.
  2. Search Zscaler OneAPI and select the verified Zscaler OneAPI collection. Then fork the collection using right-click and select the Fork option.
Public API Network is Postman's catalog of published collections — this is where the verified Zscaler OneAPI collection lives.
Search for Zscaler OneAPI, right-click the verified collection, and choose Fork to copy it into your own workspace.

4 Complete the fork

  1. Rename it to Zscaler OneAPI Student and then select the Fork Collection button.
  2. The collection is now forked to your workspace.
Rename the fork to Zscaler OneAPI Student so it's easy to identify among your own collections.
The forked Zscaler OneAPI Student collection now lives in your workspace, ready for its own variables and environment.
Task 1.2 Configure Collection Variables ▾

In this task, you create an API client in Experience Center and import its values into your Postman student workspace.

1 Open API Client Configuration

  1. To create an API client, browse to https://console.zscaler.com and enter your Experience Center credentials to log in.
  2. Navigate to Administration > API Configuration > OneAPI > API Clients.
  3. Click the Add API Client button.
Log in to Experience Center — this admin portal is where API clients for automation are registered.
Administration → API Configuration → OneAPI → API Clients is the home for every OAuth2 client in the tenant.
Select Add API Client, then the Client tab, to begin naming the new client.

2 Name and configure the client

  1. Name the API client <Student ID>-APIClient — e.g. if your Student ID is zs5101, the API client name is zs5101-APIClient.
  2. Add a Description (optional).
  3. Enable the Status.
  4. Set Access Token Validity to 300 minutes.
  5. Select the Secret tab for generating the Client Secret key.
The Client tab: name it <Student ID>-APIClient, enable Status, and set Access Token Validity to 300 minutes.

3 Generate and save the client secret

  1. Copy the Client Secret and paste it into your Client VM machine's Notepad.
  2. Select the Resources tab and provide Super admin or custom role access to all resources. Select Save.

Warning: The Client Secret will not be displayed again after saving the API Client — copy it to Notepad immediately.

The Secret tab reveals the Client Secret exactly once — copy it now, then paste it into the Lab Configuration panel above.
The Resources tab controls what this client can touch — grant Super admin (or a custom role) across all resources, then Save.

4 Collect the Client ID and Customer ID

  1. After saving, you'll see the Client ID on the API client's summary.
  2. To get the Customer ID, navigate to Administration > Account Management > Private Access Tenant.
Copy the Client ID shown here into the Lab Configuration panel — it identifies this specific API client.
Private Access Tenant lists the ZPA Customer ID you'll need for Lab 4 and Lab 6's ZPA automations.

5 Add the values as Postman collection variables

  1. In the workbench pane, click on the Zscaler OneAPI Student environment and navigate to the Variables tab to add the values above.
The environment's Variables tab now holds your Client ID, Client Secret, Customer ID, and vanity domain — every request in the collection reads from here.
Task 1.3 Create a ZIdentity Access Token ▾

In this task, you create an access token and store it in a collection variable for reuse.

  1. Select the Zscaler OneAPI collection, then select the Authorization tab. Scroll down and select Get new access token to generate the new access token.
  2. Rename the token to <Student ID>-Access-Token and click Use Token to generate the access token for your POD.
  3. Validate the current token.
The collection's Authorization tab drives the OAuth2 client-credentials flow — Get new access token exchanges your Client ID/Secret for a bearer token.
Rename the token to <Student ID>-Access-Token before selecting Use Token — this keeps tokens identifiable across a shared tenant.
A generated access token — validate it here before moving on to the first real API call.

Success: A valid access token confirms your Client ID, Client Secret, and vanity domain are all correctly wired into the Postman environment — the same three values Lab 2's Python script and Lab 5's Terraform provider will ask for.

Task 1.4 Make the First API Call ▾

In this task, you call OneAPI to list all the URL categories available in the ZIA OneAPI collection.

  1. Select Zscaler Internet Access (ZIA) under the Zscaler OneAPI collection.
  2. Scroll down and select URL Categories to send the GET request. Click Send.
  3. Send the request and verify the response status is successful.

Note: Make sure the current environment is set to Zscaler OneAPI Student before sending — otherwise the request has no Client ID/Secret to authenticate with.

The ZIA folder inside the collection groups every ZIA endpoint — URL Categories is one of dozens available.
The URL Categories GET request — Send fires it using the access token generated in Task 1.3.
A 200 OK response with a JSON list of URL categories — proof the API client, token, and OneAPI collection all work end-to-end.

QUICK REFERENCE ▲
OneAPI
Zscaler's unified API gateway — one base URL and OAuth2 flow in front of ZIA, ZPA, and ZDX.
ZIdentity
Zscaler's identity platform; issues OAuth2 access tokens to API clients for OneAPI calls.
API Client
An OAuth2 client registered in ZIdentity with a Client ID/Secret and scoped resource access.
Client Credentials Flow
OAuth2 grant type where a Client ID + Secret (no human user) exchange for an access token.
Access Token
A short-lived OAuth2 bearer token generated from client credentials, used on every API call.
Access Token Validity
How long (in minutes) a generated token remains usable before it must be refreshed.
Customer ID
Identifies your ZPA tenant; found under Account Management > Private Access Tenant.
Postman Fork
A private, editable copy of a shared collection — lets you add variables without touching the original.
