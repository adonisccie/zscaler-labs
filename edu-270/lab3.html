Lab 3: Automating ZCC App Profiles, Devices, and Forwarding Profiles with the Python SDK

LAB 3

Scenario: In this lab, you automate ZCC app profiles, forwarding profiles, and device reporting by using the Python SDK. You use the SDK environment to create and validate profiles, and to retrieve device information.

  • Create a ZCC app profile by using the Python SDK
  • Create a ZCC forwarding profile by using the Python SDK
  • Retrieve device reporting information by using the Python SDK
Time: ~30 minutes
Tools: VS Code, zscaler-sdk-python, PowerShell
Task 3.1 Automate a ZCC App Profile with the Python SDK ▾

In this task, you create a Windows app profile by using the Python SDK and verify it in the Experience Center. In the SDK and API context, the ZCC app profile is often referred to as a web policy — it instructs the Zscaler Client Connector how to behave on an endpoint, with associated policies for items such as DNS and SSL inspection.

Note: Web profiles differ by operating system. Each platform — Windows, macOS, Android, and Linux — has its own separate profile.

1 Open the ZCC project in VS Code

  1. Go to the Corp: Client PC and open File Explorer > Local Disk (C:).
  2. Open the Labs folder and select the Labs 2-4 folder.
  3. Open the ZCC folder, right-click it, and choose Open with Code.
Open the ZCC project folder in VS Code to begin setting up the debugger.

2 Create the virtual environment

  1. As an alternate option, create the virtual environment directly from PowerShell:
    • Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
    • python -m venv .venv
    • .\.venv\Scripts\Activate.ps1
  2. Ensure the Python SDK is installed in the environment: run pip install zscaler-sdk-python in the Terminal.
These three PowerShell commands are a faster alternate path to creating and activating .venv.
Install the Zscaler SDK into the newly activated environment.

Note: After you initialize the environment, start a new terminal — select the trash icon to close and reopen it. Do not use an external terminal.

Close and reopen the integrated terminal so it picks up the new .venv environment.

3 Review and run the app profile script

  1. Open the app profile in Explorer and review its properties — several are coded directly in the Python script.
  2. Select Run and Debug and choose Python File.

Note: During run and debug, breakpoints are set at key SDK calls so you can inspect specific actions before they execute. Documentation for these properties and values is available in the Automation Hub and Zscaler Help portal.

The app profile script's hardcoded properties define exactly what the created profile will look like.
Start the debugger with Python File to run the currently active app profile script.
Go to Terminal and review the requested authentication details.

4 Authenticate and select the OS type

  1. In the Terminal, provide: <Client ID>, <Client Secret>, <Vanity Domain>.
  2. Select the OS type for the app profile — enter 1 to create the Windows app profile.
  3. The debugger pauses at your breakpoint — select Continue (or press F5) to resume execution.
Provide the Client ID, Client Secret, and vanity domain from your API client in Lab 1.
Enter 1 to target the Windows app profile — the debugger will pause at the SDK call that creates it.
Confirm that the new app profile is created — a success message appears in the terminal.

5 Verify and stop

  1. Go to the Experience Center, use the search feature in the upper-right corner, type App Profile, then select Windows.
  2. Verify that the profile created by the Python code appears.
  3. Go to Actions and edit the policy to review the parameters added to the app profile.
  4. Stop the debugger.
The new profile appears in the Windows App Profile list in Experience Center.
Editing the profile confirms every parameter the script set — DNS, SSL inspection hooks, and related settings.
Task 3.2 Automate ZCC Forwarding Profiles with the Python SDK ▾

In this task, you create a forwarding profile by using the Python SDK and verify it in the Experience Center. The forwarding profile in ZCC determines how traffic is forwarded for each network type — trusted networks, off-trusted VPNs, and similar conditions.

1 Run the forwarding profile script

  1. Return to the Python SDK environment used in the previous task.
  2. Select Forwarding Profile in the left pane.
  3. Select Run and Debug; if prompted, select the current Python file.
Select the Forwarding Profile script in the left pane before starting the debugger.

2 Authenticate and create the profile

  1. Provide: <Client ID>, <Client Secret>, <Vanity Domain>.
  2. Enter 1 to create the forwarding profile.
  3. The debugger pauses at your breakpoint — select Continue (or press F5) to resume execution.
Enter 1 to create the forwarding profile after supplying credentials.
Confirm the new forwarding profile is created — a success message appears in the terminal.

3 Verify the forwarding profile

  1. Go to the Experience Center and use the search feature to type Forwarding Profile.
  2. Verify that the profile created by the Python code appears.
  3. Go to Actions and edit the profile to review the parameters added.
Search for Forwarding Profile in Experience Center to locate the new object.
The profile's parameters — tunnel type/version and per-network forwarding action — match what the script set.

Verify: Confirm that the forwarding profile appears in the Experience Center and includes the expected parameters.

Task 3.3 Automate ZCC Device Reporting with the Python SDK ▾

In this task, you use the Python SDK to retrieve device information and filter device results. Organizations commonly need a device inventory — Zscaler provides APIs that return device information, and the SDK makes it easier to work with device listings, especially when paging through many devices. You can also filter results by type, such as Windows or Mac devices, based on your reporting needs.

1 Open the devices project

  1. Stop debugging from the previous session.
  2. In the Python SDK environment, select Devices in the left pane.
Stop the forwarding profile debug session, then select the Devices script.
The Devices script is ready to run — it queries device reporting endpoints via the SDK.

2 Run the device report

  1. Select Run and Debug. When prompted, provide: <Client ID>, <Client Secret>, <Vanity Domain>.
  2. Enter 1 to fetch the current page details — the script returns the device details.
Authenticate, then enter 1 to fetch and print the current page of device details.
  1. Go to the Experience Center, use the search feature to type Device Overview.
  2. Review all 7 listed devices.
Device Overview in Experience Center lists all 7 devices — cross-check the count against the script's terminal output.
