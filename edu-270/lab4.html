Lab 4: Automating ZPA Access Policy and Application Segment with the Python SDK

LAB 4

Scenario: In this lab, you automate the creation of ZPA application segments and access policies by using the Python SDK. You use the SDK environment to create the supporting groups, build an application segment, and apply an access policy. You then validate the objects in Experience Center and toggle the policy from deny to allow.

  • Create a ZPA App Connector Group by using the Python SDK
  • Create a ZPA segment group and a ZPA server group by using the SDK
  • Create a ZPA application segment and an access policy by using the SDK
  • Retrieve and verify ZPA object relationships by using the SDK
Time: ~40 minutes
Tools: VS Code, zscaler-sdk-python

Task 4.3 Create an App Connector Group ▾

In this task, you create the App Connector Group that the server group will reference.

  1. Answer Y to create the App Connector Group.
  2. Execute to the first breakpoint — the lab calls the SDK function lookup_enrollment_cert_id to find the existing certificate.
  3. Continue to the next breakpoint to create the App Connector Group, using a name and geographic information (the lab uses a sample name and San Jose as demo values).
  4. Verify the App Connector Group was created.

Note: You retrieve the existing enrollment certificate that the application segment requires.

The App Connector Group is created — its ID becomes the reference for the server group in Task 4.5.
Task 4.4 Create the Segment Group ▾

In this task, you create the segment group that the application segment will join.

  1. Continue execution to the next breakpoint — the lab calls the SDK segment_groups function to add a new group.
  2. Answer Y to create the Segment Group.
  3. Verify the segment group was created.
The segment group — independent of the App Connector Group — is created and ready for the application segment to join.
Task 4.5 Create the Server Group ▾

In this task, you create the server group and associate it with the App Connector Group.

  1. Continue execution to the next breakpoint — the server group references the App Connector Group ID created earlier.
  2. Answer Y when prompted to create the Server Group.
  3. Verify the server group was created.
The server group's payload references the App Connector Group ID from Task 4.3 — this is the chain in action.
Task 4.6 Create the Application Segment ▾

In this task, you create the application segment that ties the segment group, server group, and internal domain together.

  1. Continue executing the script to the next breakpoint.
  2. When prompted for the Domain or FQDN, press Enter to accept the auto-generated internal domain (formatted as app-<random-number>.lab.example.com).
  3. When prompted for the TCP port, press Enter to accept the default value of 443.
  4. Type Y and press Enter to confirm the creation of the application segment.

Verify: The terminal displays an [OK] message confirming the application segment was created.

The application segment now references both the segment group and server group IDs.
Task 4.7 Create the Access Policy ▾

In this task, you attach an access policy rule to the application segment you just created.

  1. Continue executing the script to create an Access Policy Rule.
  2. When prompted for the Rule action, type allow and press Enter.
  3. Type Y when prompted for Create the Access Policy rule (action=allow)? and press Enter.

Verify: The terminal displays an [OK] message confirming the Access Policy rule was successfully created.

The access policy rule, action=allow, is the final link — it grants access to the application segment.
Task 4.8 Review the Resource Hierarchy ▾

In this task, you display the parent-child relationships among the resources you created.

  1. When prompted to show a diagram of how these resources are connected, select Y.
  2. Review the relationships shown:
    • An App Connector Group is related to a server group.
    • An application segment is related to both a server group and a segment group.
    • An access policy is associated with an application segment.
The full composition chain visualized — this is the same dependency order Task 4.2's breakpoints stepped through.
Task 4.9 Verify the Resources in the Experience Center ▾

In this task, you confirm the new resources in the ZPA Experience Center UI.

  1. To view the application segments, go to Policies > Private Applications > App Segments and locate the new application segment.
  2. Confirm associations — verify the application segment is associated with the expected segment group and server group.
  3. Go to Policies > Access Policy and locate the new lab access rule that allows access to the application segment.
The new application segment appears under Policies → Private Applications → App Segments.
The segment's detail view confirms its associated segment group and server group.
The new access policy rule with action=allow appears, granting access to the application segment.
Task 4.10 Clean Up the Lab Resources ▾

In this task, you delete the resources you created so the tenant returns to its original state.

  1. Continue script execution. When prompted to toggle the rule action between allow and deny, enter N.
  2. When prompted to delete the resources, select Y.
  3. Confirm the deletions:
    • Access policy rule
    • Application segment
    • Server group
    • Segment group
    • App Connector Group
Cleanup deletes all five objects in reverse dependency order — access policy first, App Connector Group last.

App Connector Group
ZPA object grouping App Connectors by location; referenced by a server group.
Segment Group
Logical container that groups related application segments.
Server Group
Maps App Connector Groups to backend servers for an application segment.
Application Segment
Defines a private application by domain/FQDN + port; references a segment group and server group.
Access Policy
ZPA rule that grants or denies access to an application segment.
Enrollment Certificate
Existing cert an application segment references to establish trust for connectors.
ZPA Customer ID
Identifies your ZPA tenant — the fourth credential ZPA automation needs beyond Client ID/Secret/Vanity Domain.
