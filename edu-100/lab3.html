Lab 3: Configure SSL Inspection Policies

OVERVIEW

Scenario: Nearly all of Labtenant's web traffic is encrypted, and ZIA can only apply URL, threat, and data protection controls to traffic it can inspect. With the Zscaler root certificate already installed on the Corp Client PC, you record which certificate the browser receives for an HTTPS site, create an inspection rule, and confirm that the site is then served a certificate signed by Zscaler.

By the end of this lab, you will be able to:

  • Identify the certificate issuer for an HTTPS site before inspection is enabled.
  • Create and activate an SSL/TLS inspection rule with the Inspect action.
  • Confirm that inspected HTTPS sessions present a certificate signed by Zscaler.

Success criteria

  • ☐ You recorded the original certificate issuer for www.wikipedia.org.
  • ☐ Rule SSL Inspect All exists at Rule Order 1 with Action Inspect, and the change is activated.
  • ☐ In a new Incognito window, the certificate for www.wikipedia.org is signed by Zscaler.

Watch out for

  • ⚠ Save alone doesn't apply the rule. You must also Activate the change.
  • ⚠ Close or refresh the Incognito window after activating, or the browser may reuse the old session.
  • ⚠ If the issuer already shows Zscaler before you start, review the existing SSL inspection rules first.

💭 THINK FIRST · SEEING INSIDE HTTPS

SSL/TLS inspection is the switch that makes most other ZIA controls effective. Think about what ZIA can and can't see before you turn it on, and what turning it on changes for the browser.

  • Without inspection, what can ZIA still see about an HTTPS request, and what can't it see?
    Q1 — MODEL ANSWER
    It can still see where the connection is going (the destination domain and IP), so domain-level decisions are possible. It can't see the full URL path, the headers or the content, so it can't filter on the exact page, scan downloaded files for malware or check uploads for sensitive data. That's why the scenario says ZIA can only apply URL, threat and data protection controls to traffic it can inspect.
  • After you activate the rule, the certificate's issuer changes from the site's own CA to Zscaler. Why does that happen, and why doesn't the browser show a warning?
    Q2 — MODEL ANSWER
    ZIA terminates the encrypted session, inspects the traffic, and then re-encrypts it toward the browser with a certificate it issues through the Zscaler intermediate CA. So the browser now sees Zscaler as the issuer. There's no warning because the Lab 2 app profile installed the Zscaler root certificate on the Corp Client PC, so the browser trusts the chain.
  • This lab inspects all destinations. In production, why might you exempt some destinations, and what's the cost of each exemption?
    Q3 — MODEL ANSWER
    Some applications use certificate pinning and break when they're handed any certificate other than their own, and some categories (for example health or finance) may be exempted for privacy or regulatory reasons. Zscaler ships predefined exemption rules for destinations that can't be inspected. The cost is visibility: exempted traffic gets only domain-level control and no content scanning, so every exemption should be deliberate and as narrow as possible.
Purpose: In this task, you will enable SSL inspection for all encrypted traffic.
  • Verify the current SSL inspection status:
    • On the Corp Client PC, open a Chrome browser window in Incognito Mode.
    • Navigate to www.wikipedia.org
    • Click the site information icon to the left of the URL.
    The View site information icon sits to the left of the address. Its menu shows Connection is secure.
    • Click Connection is secure > Certificate is valid.

    Note: The certificate should be issued by the website's own certificate authority, not by Zscaler. Record the certificate issuer before changing the SSL inspection policy. If the issuer indicates Zscaler inspection, review the existing SSL inspection rules before continuing; the tenant may already inspect this traffic.

    Before inspection: Issued By is the site's own CA (Let's Encrypt in this example). Record what you see.
  • Enable SSL inspection:
    • In the Portal, use the Search menu to find SSL/TLS Inspection and select the appropriate option (Internet Access > Policy).
    • On the SSL Inspection Policy tab, click +Add Rule.
    Search SSL/TLS Inspection, then select Add Rule. The tenant may already list other rules, such as the Smart Isolation rule shown here.
    • Configure the rule as follows:
    ADD SSL/TLS INSPECTION RULE
    FieldValue
    Rule Order1
    Rule NameSSL Inspect All
    CriteriaLeave the defaults, so that the rule applies to all destinations
    ActionInspect
    Actions: Inspect. Leave Override Default Intermediate CA Certificate at No, so the Zscaler intermediate CA signs inspected sessions.
    • Click Save and Activate.
    To activate, open the cloud icon in the top bar and select Activate.
  • Verify the inspection status:
    • Close the Incognito browser or refresh it (to ensure the new policy is applied).
    • Re-open a browser window in Incognito Mode, and visit www.wikipedia.org
    • Click the site information icon to the left of the URL > Connection is secure > Certificate is valid.

    Result: You will see that you have received a server certificate signed by Zscaler. Compare it with the issuer you recorded in step 1.

🧠
MENTAL NOTE
Before: the issuer is the site's own CA. Rule: SSL Inspect All, Rule Order 1, default criteria (all destinations), Action Inspect. After: the issuer is Zscaler. ZIA changes take effect only after Activate, and the browser trusts the new chain only because the Zscaler root certificate was installed in Lab 2.

QUICK REFERENCE ▲
SSL/TLS inspection
ZIA decrypts HTTPS, applies policy to the content, then re-encrypts it toward the user.
Certificate issuer
The CA that signed the certificate the browser receives. It changes to Zscaler once traffic is inspected.
Inspect action
Rule action that decrypts matching traffic. The other actions are Do Not Inspect and Block.
Intermediate CA certificate
Signs the certificates ZIA presents to browsers; by default the Zscaler Intermediate CA Certificate.
Rule order
Rules are evaluated in ascending order; the first matching rule wins.
Activate
Pushes saved ZIA changes live. Saved but unactivated changes have no effect.
Certificate pinning
An app that accepts only its own certificate. Inspecting it breaks the app, so it's usually exempted.
