Lab 2: Forward Traffic with the Zscaler Client Connector

OVERVIEW

Scenario: As the Zscaler administrator, your goal is to configure the Zscaler Client Connector (ZCC) to securely forward all user traffic, regardless of protocol, to Zscaler for inspection and protection. By doing so, you enable firewall functionality, secure internet access, and ensure multi-platform compatibility for users both on and off trusted networks. Before configuring traffic forwarding, you use the Zscaler read-only tenant to explore the ZCC download portal and review available client versions for each platform.

  • Configure forwarding options to send all user traffic securely to Zscaler.
  • Set up forwarding profiles and platform settings for Windows devices.
  • Confirm Private Access, Internet Security, and Digital Experience are enabled and functioning.
  • Confirm the Corp: Client PC traffic is forwarded to Zscaler and verify entitlements and settings.
Time: ~20 minutes
Environment: Task 2.1 read-only tenant · Tasks 2.2–2.3 simulated tenant

Note: This lab uses both the simulated lab environment and the Zscaler tenant. You begin with the Zscaler tenant for Task 2.1, then switch to the simulated environment for Tasks 2.2–2.3.

In this task, you familiarize yourself with the ZCC download portal and review available versions before configuring traffic forwarding. User credentials are contained in the lab access instructions provided to you via email by the instructor.

  1. In your browser, navigate to https://console.zscaler.com and authenticate with the read-only Zscaler tenant credentials:
    • Username: <Admin_User_ID>
    • Password: <Session_Password>
    Navigate to Infrastructure > Common Resources > Deployment > Client Connector Deployment > Platform Releases.
    Infrastructure > Common Resources > Deployment > Client Connector Deployment > Platform Releases.

    New Releases — ZCC builds for Windows, macOS, and Linux with EXE/MSI and 32/64-bit download links.

Task 2.2 Configure Traffic Forwarding Options ▾

In this task, you configure traffic forwarding so all users send traffic — regardless of protocol — to Zscaler.

  1. Sign in to the Experience Center in the simulated lab environment at https://console.zscaler.com using:
    • Username: student@<Student FQDN>
    • Password: the password you configured at initial login in Lab 1.
  2. Create Forwarding Profile. Navigate to Infrastructure > Connectors > Client > Forwarding Profile for Platforms.
    Infrastructure > Connectors > Client > Forwarding Profile for Platforms.
  3. Select Add Forwarding Profile. Name the profile HandsOnLab. Scroll down — in the Windows Driver Selection section, select Packet Filter Based.
    Add Forwarding Profile — Name: HandsOnLab, Windows Driver: Packet Filter Based.

    Note: If Zscaler Client Connector (version 4.8 or higher) is installed on Windows, the application defaults to the packet filter-based driver, ignoring the Route-Based configuration option.

  4. In the Forwarding Profile Action for ZIA section:
    • On-Trusted Network: Tunnel
    • Tunnel version: Z-Tunnel 2.0
    • VPN Trusted Network and Off-Trusted Network: check Same as "On-Trusted Network"
    ZIA forwarding action — Tunnel, Z-Tunnel 2.0.

    Note: Tunnel 2.0 is necessary to intercept all traffic to tunnel to ZIA for Firewall functionality.

  5. In the Forwarding Profile Action for ZPA section: On-Trusted Network: Tunnel; VPN Trusted Network and Off-Trusted Network: Same as "On-Trusted Network". Select Save.
    ZPA forwarding action — Tunnel, then Save.
  6. Add Windows App Profile. Use the left navigation panel to go to Platform Settings > Windows and select Add Windows Policy under the App Profile section.
    Platform Settings > Windows — Add Windows Policy.
  7. Configure (leave unspecified fields at default):
    • Name: HandsOnLab
    • Rule Order: 1
    • Status: Enable
    • Forwarding Profile: the HandsOnLab profile created earlier
    • Install Zscaler SSL Certificate: On
    • User Groups: Select All
    Select Add.
    Windows App Profile — SSL certificate install enabled, all user groups, ready to Add.

Task 2.3 Sign In to the Zscaler Client Connector and Verify Protection ▾

In this task, you log in to ZCC to confirm the Corp: Client PC is now protected.

  1. Open the Zscaler Client Connector. On the Corp: Client PC, in the Windows Task Bar (bottom-right corner), select Show hidden icons, then the Zscaler Client Connector icon, then Open Zscaler.
    Open Zscaler Client Connector from the taskbar.
  2. Log in using the student credentials:
    • Username: student@<Student FQDN>
    • Password: as set in Lab 1.
    Select Sign in.
    ZCC sign-in — Student.
  3. Verify Private Access settings — on the Private Access page, confirm Service Status: ON and Client/Broker IP addresses are populated.
    Private Access — Service Status ON, Client/Broker IPs populated.

    Note: If you do not see ZPA or ZDX in ZCC, your user may be missing service entitlements. Verify under Administration > Users, Edit the Student Admin user, and check the Entitlements section for ZPA and ZDX. The Broker IP shown is an example and may not match yours.

  4. Verify Internet Security settings — confirm Service Status: ON, Username displays correctly, and Total Bytes Sent/Received increment as you load web pages.
    Internet Security — Service Status ON, byte counters incrementing.
  5. Verify Digital Experience settings — confirm Service Status: ON, Authentication Status: Authenticated, Username displays correctly.
    Digital Experience — Service Status ON, Authenticated.
  6. Verify Applied App Policy — on the More page, confirm App Policy: HandsOnLab.
    More page — Applied App Policy: HandsOnLab.

    Note: If the updated policy isn't reflected in ZCC, select Update Policy in the ZCC More tab to force a policy refresh, wait a few seconds, and re-verify.

  7. Verify Traffic Forwarding — navigate to https://ip.zscaler.com and confirm you are accessing the internet via a service edge geographically close to you.
    ip.zscaler.com — confirms traffic is being forwarded through a nearby Zscaler service edge.

    Note: The Service Edge location shown will typically reflect a location geographically close to the user.
