Lab 2: Forward Traffic with the Zscaler Client Connector

OVERVIEW

Scenario: The Corp Client PC currently reaches the Internet directly, so the Zero Trust Exchange cannot inspect or protect its traffic. You create a forwarding profile that tunnels ZIA traffic with Z-Tunnel 2.0 and ZPA traffic on every network type, attach it to a Windows app profile that also installs the Zscaler root certificate, and sign in to Zscaler Client Connector to confirm that each service is active.

By the end of this lab, you will be able to:

  • Create a forwarding profile that tunnels ZIA traffic with Z-Tunnel 2.0 and ZPA traffic on trusted, VPN-trusted, and off-trusted networks.
  • Create a Windows app profile that applies the forwarding profile and installs the Zscaler SSL certificate.
  • Confirm that Private Access, Internet Security, and Digital Experience are ON in Zscaler Client Connector.
  • Verify that the HandsOnLab app profile is applied and that traffic exits through a nearby Zscaler service edge.

Success criteria

  • ☐ Forwarding profile HandsOnLab saved: Tunnel with Z-Tunnel 2.0 for ZIA, Tunnel for ZPA, on every network type.
  • ☐ Windows app profile HandsOnLab added: Rule Order 1, Enabled, Install Zscaler SSL Certificate On.
  • ☐ Private Access, Internet Security and Digital Experience all show ON in Zscaler Client Connector.
  • ☐ More shows App Policy: HandsOnLab, and ip.zscaler.com shows a Zscaler cloud.

Watch out for

  • ⚠ Sign in to Zscaler Client Connector as the student admin, not the user you created in Lab 1.
  • ⚠ ZPA or ZDX missing in Zscaler Client Connector? Check the Student Admin's service entitlements (see the note in Task 2.2).
  • ⚠ App Policy still shows another profile? Use More > Update Policy and check again.

💭 THINK FIRST · GETTING TRAFFIC TO ZSCALER

Every ZIA and ZPA policy in the rest of the course depends on what you configure here. Before you start, think about what each profile controls and why the lab picks these options.

  • The forwarding profile decides how traffic leaves the device. The app profile decides who gets that forwarding profile. Why does Zscaler keep these as two separate objects?
    Q1 — MODEL ANSWER
    So that the same forwarding behavior can be reused. One forwarding profile can be attached to many app profiles: different platforms, user groups or rule orders. The app profile adds the targeting (platform, users and groups, rule order) and device settings such as installing the Zscaler SSL certificate. If you need to change how traffic is forwarded, you edit one forwarding profile and every app profile that uses it picks up the change.
  • The lab chooses Z-Tunnel 2.0. What traffic would bypass ZIA if you chose Z-Tunnel 1.0 instead?
    Q2 — MODEL ANSWER
    Z-Tunnel 1.0 behaves like a traditional proxy: it forwards proxy-aware or port 80/443 web traffic only. Anything else, such as other ports and protocols used by non-web applications, would leave the device directly and never reach ZIA. Z-Tunnel 2.0 sends packets over DTLS or TLS, so it can carry all ports and protocols. That's why the guide notes it forwards traffic on all ports and protocols, not only web traffic.
  • The app profile installs the Zscaler SSL certificate now, but SSL inspection isn't enabled until Lab 3. Why install it ahead of time?
    Q3 — MODEL ANSWER
    When ZIA inspects HTTPS, it presents the browser with a certificate signed by Zscaler instead of the site's own certificate. The browser only accepts that if the Zscaler root certificate is already trusted on the device. Installing it now through Zscaler Client Connector means no manual certificate rollout, and no certificate warnings for users the moment inspection is switched on.
Purpose: In this task, you will configure traffic forwarding so that all users send traffic, regardless of protocol, to Zscaler.

  • Click Add Forwarding Profile.
Search for Forwarding Profile, open the result, then select + Add Forwarding Profile.

Purpose: In this task, you will log in to the Zscaler Client Connector to confirm that the Corp Client PC is now protected by the app.
  • Open the Zscaler Client Connector:
    • On the Corp Client PC, in the Windows taskbar (bottom-right corner), click the Show hidden icons option.
    • Select the Zscaler Client Connector icon and click Open Zscaler.
    System tray: Zscaler Client Connector icon > Open Zscaler.
    • In the Zscaler Client Connector console, sign in using the student credentials:
      • Username: student@<Student FQDN>
      • Password: <Student Password> (as provided in the Lab Access Instructions)
    • Click Sign in.
    Sign-in page: Log in to your Authentication Service account with the student Login ID and password.
  • Verify Private Access settings. On the Private Access page, confirm:
    • Service Status: ON
    • Client and Broker IP addresses: populated
    Private Access: Service Status ON with Broker and Client addresses filled in. Your Broker IP will differ from the example.

    Note: If you do not see ZPA or ZDX in Zscaler Client Connector, your user may not have the correct service entitlements. To verify entitlements for the Student Admin user, navigate to Administration > Users in the portal, select the Student Admin user account, and click the Edit icon. In the Edit User pane, go to the Entitlements section and confirm that ZPA and ZDX are assigned to the user. The Broker IP address highlighted in the screenshot is an example and may not match the IP address you see in your own Zscaler Client Connector.

  • Verify Internet Security settings. On the Internet Security page, confirm:
    • Service Status: ON
    • Username: displays correctly
    • Total Bytes Sent / Received: these values increment as you load web pages
    Internet Security: Service Status ON, and Tunnel Version v2.0 confirms Z-Tunnel 2.0 is in use. Bytes Sent/Received grow as you browse.
  • Verify Digital Experience settings. On the Digital Experience page, confirm:
    • Service Status: ON
    • Authentication Status: Authenticated
    • Username: displays correctly
    Digital Experience: Service Status ON and Authenticated.
  • Verify the applied app policy. On the More page, confirm:
    • App Profile: HandsOnLab
    More > About: App Policy: HandsOnLab. Update Policy is on the same row.

    Note: If the updated policy, HandsOnLab, is not reflected on Zscaler Client Connector, click Update Policy under the More tab to force a policy refresh. Wait a few seconds and then re-verify.

  • Verify traffic forwarding:
    • Navigate to https://ip.zscaler.com
    • Confirm that you are accessing the Internet via a service edge geographically close to the user.
    ip.zscaler.com: "You are accessing the Internet via Zscaler Cloud", followed by the service edge name. The example shows Chennai; yours shows the edge nearest to you.

    Note: The Service Edge location shown in results will typically reflect a location that is geographically close to the user.

QUICK REFERENCE ▲
Forwarding profile
Tells Zscaler Client Connector how to treat ZIA and ZPA traffic in each network state.
On-Trusted / VPN-Trusted / Off-Trusted
The network states a device can be in. The lab applies the same action to all three.
Z-Tunnel 2.0
DTLS/TLS tunnel that carries all ports and protocols to ZIA. Z-Tunnel 1.0 carries web traffic only.
Packet Filter-Based driver
Windows driver option for tunnel mode; the default on Zscaler Client Connector 4.8 and later.
App profile (Windows policy)
Rule that gives matching users a forwarding profile and device settings. Lowest rule order wins.
Zscaler SSL certificate
Root certificate the device must trust so that inspected HTTPS sites don't show certificate errors.
Broker
The ZPA cloud address Zscaler Client Connector connects to, shown on the Private Access page.
ip.zscaler.com
Page that confirms whether your traffic is going through Zscaler and which service edge it uses.
