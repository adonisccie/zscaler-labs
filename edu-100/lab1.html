LAB 1 · IDENTITY

Configure User and Administrator Access Entitlements

Every policy you write in the labs that follow only matters if the right people can — or can't — reach the console. Here you build the identity foundation: departments, groups, two very differently-privileged users, and the entitlements that make role-based access actually work.

Lab 1: Configure User and Administrator Access Entitlements

OVERVIEW

Scenario: You work in a Zscaler tenant that is already provisioned and focus on establishing a clean foundation for who can sign in and what they can access in labtenant.com. You onboard two new users: JoeSupport (support/helpdesk) and BevIT (IT/admin) so they are placed into the correct departments and user groups and inherit the appropriate Zscaler entitlements. JoeSupport should have limited, read-only access suitable for Tier 1 support, while BevIT should have full administrative access. You validate both experiences by signing in as each user and confirming what they can and cannot do. You also review how IdP integration using the OIDC protocol is configured in the Zscaler tenant.

Note: The usernames JoeSupport and BevIT are just examples — you may use any other usernames you wish, as long as you apply them consistently across every task and screen in this lab.

  • Create the required organizational structure (departments and groups).
  • Provision users and place them correctly so policies and entitlements apply.
  • Configure entitlements and verify they are applied to the correct identities and groups.
  • Validate access via role-based UI restrictions and service status.
Time: ~45 minutes

Note: This lab uses both the simulated lab environment and the Zscaler tenant. You complete Tasks 1.1–1.4 in the simulated environment, following the in-lab guided steps (the instructions below are for reference only). You then switch to the Zscaler tenant for Task 1.5.

Task 1.1 Create Departments and User Groups ▾

In this task, you create the Support and IT departments, then create the Helpdesk L1 user group that JoeSupport will be placed into.

  1. In the simulated lab environment, navigate to console.zscaler.com, where you are prompted to enter your assigned username. After entering your username and password, access the Zscaler Admin Console and select the Administration tab. Go to Identity > Departments.
    Administration > Identity > Departments — the entry point for organizational structure.
  2. Create the Support department. Select Add Department and enter:
    • Department Name: Support
    • Description: Support Department
    Select Save.
    Add Department — Name: Support, Description: Support Department.
  3. Create the IT department. Select Add Department and enter:
    • Department Name: IT
    • Description: IT Department
    Select Save, then confirm that IT and Support both appear in the Departments section.
    Departments list — IT and Support both present, confirming both were saved.
  4. Create the Helpdesk L1 user group. In the Experience Center Dashboard, select the Administration tab and go to Identity > User Groups. Select Add User Group and enter:
    • User Group Name: Helpdesk L1
    Select Save.
    Add User Group — Name: Helpdesk L1.
    User Groups list — Helpdesk L1 confirmed saved.

Task 1.2 Create Users ▾

In this task, you create users JoeSupport and BevIT and map them to the departments and user groups you created in Task 1.1.

  1. Create user JoeSupport. From the left navigation panel, go to Users.
    Left navigation — Users.
  2. Select Add User and set:
    • Login ID: joesupport@<Student FQDN>
    • Name / First Name: JoeSupport
    • Same As Login ID: Enabled
    • Primary Email: joesupport@<Student FQDN>
    • Department: Support
    • Assign Groups: Helpdesk L1
    Add User — JoeSupport, Department: Support, Group: Helpdesk L1.
  3. Select the Security Settings tab and configure:
    • Password option: Set By Administrator
    • Password / Confirm Password: Admin-123!
    • Prompt for Password change after initial log in: Unchecked
    • Multi-Factor Bypass — Skip Second Factor Authentication: Enabled, Skip until: as far out as allowed

    Note: For the purposes of this lab, the second factor of authentication is skipped. Zscaler recommends enabling Multi-Factor Authentication (MFA) for all users.

  4. Navigate to the Additional Attributes pane. Under the INFORMATION section, set SyncZPA: Zscaler, then select Save.
    Additional Attributes — SyncZPA: Zscaler.

    Note: Setting SyncZPA to Zscaler tells the lab environment to sync this user with ZPA so later ZPA labs and the lab-reset scripts function correctly.

  5. Create user BevIT. Select Add User and set:
    • Login ID: bevit@<Student FQDN>
    • Name / First Name: BevIT
    • Same As Login ID: Enabled
    • Primary Email: bevit@<Student FQDN>
    • Department: IT
    • Assign Groups: Zscaler Global Administrators
  6. Select the Security Settings tab and repeat the same password / MFA bypass configuration as JoeSupport (Password: Admin-123!). Navigate to Additional Attributes and set SyncZPA: Zscaler, then select Save.

Task 1.3 Add Administrative and Service Entitlements ▾

In this task, you assign administrative entitlements and service entitlements to the Helpdesk L1 group so JoeSupport inherits them.

  1. Assign administrative entitlement for ZIA (Helpdesk L1). From the Experience Center Dashboard, navigate to Administration > Admin Management > Role Based Access Control > Administrative Entitlements. Select Zscaler Internet Access.
    Administrative Entitlements — select Zscaler Internet Access.
    Zscaler Internet Access — Administrative pane, select Assign Groups.
  2. In the Zscaler Internet Access - Administrative pane, select Assign Groups, check Helpdesk L1, choose role Executive Insights App from the Role dropdown, then select Next and Assign.
    Assign Groups — Helpdesk L1, Role: Executive Insights App.

    Note: For simplicity, this lab uses the predefined Executive Insights App role, which conveniently provides read-only access to the Zscaler portal — the intended permission level for this user. In production, you can create a custom role under Administration > Admin Management > Role Based Access Control > Roles.

    Assignment confirmed for Zscaler Internet Access.
  3. Assign administrative entitlement for ZDX (Helpdesk L1). Select Back next to Assign Groups, then select Zscaler Digital Experience.
    Back to Administrative Entitlements list.
    Select Zscaler Digital Experience.
  4. In the Zscaler Digital Experience - Administrative pane, select Assign Groups, check Helpdesk L1, choose role ZDX Read-only Admin, then select Next and Assign.
    Assign Groups — Helpdesk L1, Role: ZDX Read-only Admin.

    Note: The ZDX Read-only Administrator role is a pre-built role.

  5. Assign service entitlement for ZIA (Helpdesk L1). Navigate to Administration > Entitlements > End User Entitlements > Service Entitlements and select Zscaler Internet Access.
    Service Entitlements — select Zscaler Internet Access.
  6. In the Zscaler Internet Access - Service pane, select Assign Groups, check Helpdesk L1, then select Next and Assign.
    Service entitlement — Helpdesk L1 assigned to Zscaler Internet Access.
  7. Verify the entitlements for user JoeSupport. Navigate to Administration > Identity > Users and select the Edit (pencil) icon for JoeSupport.
    Users list — edit JoeSupport.
  8. In the Edit User pane, navigate to the Entitlements tab and verify that both the administrative and service entitlements are assigned to JoeSupport. Select Cancel to exit.
    JoeSupport's Entitlements tab — ZIA and ZDX administrative + ZIA service entitlement confirmed.
    Select Cancel to exit without changes.

    Note: You can verify the entitlements for BevIT the same way — Administration > Identity > Users, Edit BevIT, review the Entitlements tab.

Task 1.4 Validate Entitlement Access for Users ▾

In this task, you sign in to the Experience Center to validate administrative entitlements and access for users JoeSupport and BevIT.

  1. Validate administrative entitlements for JoeSupport. On the Corp: Client PC, open a new incognito Chrome window and navigate to https://console.zscaler.com/. Authenticate with:
    • Username: joesupport@<Student FQDN>
    • Password: Admin-123!
    Select Sign in.
    Sign in as JoeSupport.
  2. In the Experience Center Dashboard, observe that the Administration and Policy tabs are more restrictive than they were for the Student user. Confirm that JoeSupport cannot access Admin Management, Sign-On Policies, or other administrative configuration areas, and can only view existing Digital Experience data.
    JoeSupport's dashboard — restricted Administration/Policy navigation compared to the Student admin.
    ZDX data is view-only for JoeSupport — no create/modify controls.

    Note: The Helpdesk Level 1 group has read-only privileges for ZIA and ZDX. JoeSupport inherits this read-only access, which removes access to core administrative areas (Policies, Admin Management) and limits him to view-only analytics and experience data.

    Select the Account settings icon (top right) to sign out.
  3. Validate administrative entitlements for BevIT. In the same incognito window, navigate to https://console.zscaler.com/ and authenticate with:
    • Username: bevit@<Student FQDN>
    • Password: Admin-123!
    Navigate to Administration > Admin Management > Sign-On policies.
    Admin Sign-On Policy — Add Rule is enabled for BevIT.
  4. Confirm that in the Admin Sign-On Policy window, BevIT is allowed to Add Rule (button enabled) because she is part of the Zscaler Global Administrators group. Select the Account settings icon to sign out.
    Sign out via the Account settings icon.

    Note: The Add Rule button is only enabled for users with sufficient administrative privileges. As a Zscaler Global Administrator, BevIT has full administrative access, including managing sign-on policies.

  5. Validate service entitlement for JoeSupport via Zscaler Client Connector. On the Corp: Client PC, in the Windows taskbar (bottom-right), select the Show hidden icons arrow, then the Zscaler Client Connector icon, then Open Zscaler.
    Taskbar — open Zscaler Client Connector.
  6. From the ZCC login page, authenticate with:
    • Username: joesupport@<Student FQDN>
    • Password: Admin-123!
    Select Sign in.
    ZCC sign-in — JoeSupport.
  7. Verify JoeSupport's service entitlement access for Zscaler Internet Access — in the ZCC console, confirm Zscaler Internet Access is ON for JoeSupport. After verifying, log out of ZCC (you sign in again later with a different account).
    ZCC — Zscaler Internet Access is ON for JoeSupport, confirming his ZIA service entitlement.

Task 1.5 Review IdP Integration Using OIDC ▾

In this task, you log in to the Experience Center using the read-only Zscaler tenant to review IdP integration using the OIDC protocol. User credentials are contained in the lab access instructions provided to you via email by the instructor.

  1. In your browser, navigate to https://console.zscaler.com and authenticate with the read-only Zscaler tenant credentials:
    • Username: <Admin_User_ID>
    • Password: <Session_Password>
  2. Go to Administration > Identity > ZIdentity > IDP Configuration > External Identities.
    External Identities — Okta IdP listed as Primary Identity Provider, Type OIDC, Status Enabled.

    Note: What you see is a simplified view of the Okta IdP configuration within Zscaler. A real-world environment involves significantly more setup on the IdP side — OIDC app registration, redirect URIs, SCIM provisioner setup, attribute mapping, and group sync policies. See the Zscaler and Okta Deployment Guide for the full integration walkthrough.

  3. Observe that Okta IdP is listed as the Primary Identity Provider with Type set to OIDC and Status set to Enabled. Select the eye icon to open the Okta IdP configuration and review the Basic tab — note the Identity Vendor (Okta), Protocol (OIDC), and Login ID Attribute (email).
    Okta IdP — Basic tab: Vendor Okta, Protocol OIDC, Login ID Attribute email.
  4. Scroll down to review the OIDC Configuration section — note the Metadata URL, Redirect URI, and endpoint details. Then select the Provisioning tab to review SCIM Provisioning settings.
    OIDC Configuration — Metadata URL, Redirect URI, and endpoint details.
    Provisioning tab — SCIM Provisioning settings.
  5. Close the Okta IdP panel and navigate to Administration > Identity > ZIdentity > Passwords & Authentication > Authentication Session. Note the Administrator Inactivity Timeout Duration configured for the tenant — this controls how long an admin session remains active without interaction.
    Authentication Session — Administrator Inactivity Timeout Duration.
    Passwords & Authentication configuration overview.
    Timeout duration is configured in minutes and applies tenant-wide.
