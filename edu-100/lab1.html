Configure User Access Entitlements

Every Zscaler service starts with one question: who is allowed to use it? You answer it here with a group, a user and a service entitlement, then prove it from the user's own device.

Lab 1: Configure User Access Entitlements

OVERVIEW

Scenario: Labtenant's support team is growing, and in this course you model a new Tier 1 helpdesk agent in the lab tenant. You create a user using your own first and last name, you create the Helpdesk L1 user group, assign the ZIA service entitlement to the group, and confirm the account can sign in to Zscaler Client Connector with ZIA enabled.

By the end of this lab, you will be able to:

  • Create the Helpdesk L1 user group.
  • Create a user account with your first and last name, and assign it to the Helpdesk L1 group.
  • Assign the ZIA service entitlement to the Helpdesk L1 group, and review your user's entitlements.
  • Validate the service entitlement by signing in to Zscaler Client Connector.

Success criteria

  • ☐ The Helpdesk L1 user group exists.
  • ☐ Your user exists and is a member of Helpdesk L1.
  • ☐ Your user's entitlements list Zscaler Internet Access as a service entitlement.
  • ☐ Zscaler Client Connector shows Internet Security ON for your user.

Watch out for

  • ⚠ The screenshots show an example user, Joe Web. Type your own first and last name.
  • ⚠ Leave Prompt for Password Change After the Initial Login unchecked, or the new user is asked to change the password at first sign-in.
  • ⚠ Log out of Zscaler Client Connector at the end. Lab 2 signs in with the student account.

💭 THINK FIRST · WHO GETS WHICH SERVICE

An account on its own doesn't grant access to anything. Before you build one, think about where access is actually decided and why the lab attaches it to a group.

  • The lab assigns the ZIA service entitlement to the Helpdesk L1 group, not to your user. What changes when the helpdesk grows from one agent to fifty?
    Q1 — MODEL ANSWER
    Because the entitlement lives on the group, access becomes a membership decision. A new agent added to Helpdesk L1 gets ZIA straight away, and an agent who leaves the team loses it when they leave the group. Assigning ZIA to each user works for one person, but at fifty you repeat the same change fifty times, audit it fifty times, and sooner or later miss someone. The same group can also be reused wherever Zscaler lets you target user groups.
  • The Student Admin and your new user live in the same directory. What decides that one can configure ZIA while the other can only be protected by it?
    Q2 — MODEL ANSWER
    The entitlements, not the account. An administrative entitlement gives admin access to a service with a role defined in that service. A service entitlement makes the user an end user of the service, so they can authenticate to it (for ZIA, through Zscaler Client Connector). Your user receives only the ZIA service entitlement, through Helpdesk L1, so it's an end user: its traffic is protected, but it has no admin role.
  • Suppose you skip Task 1.3 and go straight to Task 1.4. The account exists and the password is correct. What would you expect in Zscaler Client Connector, and what does that tell you about authentication versus authorization?
    Q3 — MODEL ANSWER
    Expect ZIA not to come up for that user: the sign-in fails or Internet Security doesn't show ON, because the user isn't assigned to the service. A valid password only answers who you are (authentication). The service entitlement answers what you may use (authorization). Lab 2 relies on the same idea: if a service is missing in Zscaler Client Connector, check the user's service entitlements first.

MENTAL NOTE
Group → user → entitlement. The ZIA service entitlement sits on Helpdesk L1, and your user inherits it through membership. Service entitlement = use a service; administrative entitlement = manage it. Check both ends: the user's entitlements in the console, and Internet Security: ON in Zscaler Client Connector. Log out of ZCC before Lab 2.

QUICK REFERENCE ▲
Authentication Service
Zscaler's identity service (formerly ZIdentity) where users, groups and entitlements are managed. The lab guide also calls it the Service Portal.
User group
A logical set of users. Entitlements assigned to a group apply to every member.
Service entitlement
Assigns users or groups to a Zscaler service (e.g., ZIA) as end users.
Administrative entitlement
Gives a user or group admin access to a service with a specific role. Not used in this lab.
Login ID
Username plus domain in email format. The domain must belong to your organization.
SyncZPA
A user attribute already created in the lab tenant. Set it to 123 for your user.
Skip Until
The date until which the user can skip second-factor authentication. After it, they must set up MFA.
Zscaler Client Connector (ZCC)
Endpoint agent that forwards user traffic to the Zero Trust Exchange. ZIA appears on its Internet Security page.
