Lab 6: Add a Corporate Application

OVERVIEW

Scenario: Labtenant's intranet site, intranet.patraining.safemarch.com, must be available only to authorized users. Now that the App Connector is connected, you define the site as a ZPA application segment, associate it with a segment group and a server group, and create an access policy that allows only the student user to reach it. You then test access from the Corp Client PC through Zscaler Client Connector.

By the end of this lab, you will be able to:

  • Create an application segment for the intranet application on TCP port 80.
  • Create the CorpApps segment group and associate the CorpServers server group with the application segment.
  • Create an access policy rule that allows only the student user to reach the intranet application.
  • Verify access to the application and confirm that the traffic counters increment in Zscaler Client Connector.

Success criteria

  • ☐ Application segment Intranet covers intranet.patraining.safemarch.com on TCP 80.
  • ☐ Segment group CorpApps and server group CorpServers are attached to it.
  • ☐ Access rule Allow Intranet allows the Intranet segment for loginname = the student user.
  • ☐ The intranet page loads and the Private Access byte counters increase.

Watch out for

  • ⚠ Stay signed in to Zscaler Client Connector as the student admin (Lab 2). The rule only allows that user.
  • ⚠ After you save the segment, the wizard opens the policy step. Use Edit Policy, or go to Policy > Access Policy.
  • ⚠ The segment only covers TCP 80, so open the site over http://.

💭 THINK FIRST · APP-LEVEL ACCESS

In ZPA, defining an application and allowing someone to use it are two separate acts. Think about why, and how you'd know the traffic really took the ZPA path.

  • ZPA's access policy is deny by default. Why does it matter that saving the application segment doesn't, by itself, give anyone access?
    Q1 — MODEL ANSWER
    It separates describing an application from authorizing people to use it. You can define apps safely, and access exists only where a rule explicitly grants it, so a mistake in a segment doesn't silently expose anything. That's the opposite of a VPN, where being on the network is often enough to reach a server.
  • The rule matches a single loginname. Why is that fine for a lab but awkward in production, and what would you match on instead?
    Q2 — MODEL ANSWER
    Per-user rules don't scale: every joiner, mover and leaver means editing policy, and rules multiply quickly. In production you'd match on attributes that come from identity, such as groups (like the Helpdesk L1 group from Lab 1) or departments, often combined with conditions on the device. Then access follows a person's role automatically.
  • When the intranet loads, you check the byte counters on the Private Access page rather than Internet Security. Why do those counters prove the request went through ZPA?
    Q3 — MODEL ANSWER
    Zscaler Client Connector keeps separate statistics per service. The Private Access counters only move when traffic is sent through ZPA, which happens when the destination matches an application segment the user is allowed to use. If the request had gone to the Internet through ZIA, the Internet Security counters would move instead. So the counters show the request was brokered by ZPA to the App Connector in the data center.
Purpose: In this task, you will create a dedicated application segment to provide more granular access control that limits intranet access to the student user.
  • Configure the Intranet application segment:
    • On the Experience Center home page, type Application Segments in the search bar and select the appropriate option (Private Access > Private Applications).
    • Click Add Application Segment and enter:
    DEFINE APPLICATIONS
    FieldValue
    NameIntranet
    StatusEnabled
    Source IP AnchorDisabled
    DescriptionAdd a suitable description
    Applications · Enter a domain or IP addressintranet.patraining.safemarch.com
    Client Connector Access · TCP Port Ranges80
    Other settingsLeave as default
    Define Applications: Name Intranet, Status Enabled, Source IP Anchor Disabled.
    Scroll down: add the intranet domain under Applications and set TCP Port Ranges to 80 (the range shows 80 to 80). Then select Next.
    • Click Next.
    • Add a segment group: Name CorpApps, Status Enabled, then click Next.
    Segment Group: choose Add Segment Group, name it CorpApps, keep it Enabled.
    • Add a server group: Name CorpServers (select the existing server group), then click Next.
    • Click Save.
    Server Groups: use Select Server Group and pick the existing CorpServers. Continue, then Save on the Review step.

    Note: After saving the application segment, you will be redirected to the Edit Policy page. From there, you can add a policy for the Intranet application segment. Alternatively, you can navigate directly to the Policies > Access Policy page from the left-hand menu.

    Policies step: select Edit Policy to add your rule. An existing rule may already be listed.
  • Add the access policy:
    • Click Add to configure a new policy and set the following:
    ADD ACCESS POLICY RULE
    FieldValue
    Rule NameAllow Intranet
    Rule ActionAllow Access
    App Connector Selection MethodKeep All App Connector Groups
    Criteria · ApplicationsClick Add Criteria > Applications, choose the Intranet application segment
    Criteria · User and Session AttributesClick + to add User Attributes, select loginname and choose student@<Student FQDN>
    • Click Add Rule.
    Add Rule: Intranet under Applications AND loginname = student@… under User and Session Attributes; Action Allow Access; then Add Rule.
  • Test the policy:
    • Open a web browser on the Corp Client PC and the Zscaler Client Connector side by side.
    • Navigate to http://intranet.patraining.safemarch.com using the provided bookmark.
    • Ensure that the intranet page loads successfully for the Student user.
    • Refresh the page and confirm that the Total Bytes Sent/Received counters in Zscaler Client Connector increment.
    The intranet loads, and the Private Access page's Total Bytes Sent/Received increase when you refresh.

MENTAL NOTE
Define: segment Intranet = intranet.patraining.safemarch.com, TCP 80 → segment group CorpApps → server group CorpServers. Allow: rule Allow Intranet = Application Intranet AND loginname = student, Allow Access. No rule, no access. Prove: the page loads and the Private Access byte counters climb.

QUICK REFERENCE ▲
Application segment
The domains or IPs and ports that make up a private application, e.g. the intranet on TCP 80.
Segment group
A set of application segments that policy rules can target together. Each segment belongs to one group.
Server group
Links the application to the App Connector groups that can reach its servers.
Access policy
Rules that decide who may reach which applications. Without an Allow rule, access is denied.
loginname
User attribute that matches one user's login ID in an access rule.
App Connector Selection Method
Which App Connector groups may carry the traffic. The lab keeps all groups for the application.
Private Access counters
Total Bytes Sent/Received on the ZCC Private Access page, showing traffic sent through ZPA.
