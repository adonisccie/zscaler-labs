Lab 5: Provision ZPA Infrastructure

OVERVIEW

Scenario: Labtenant hosts its intranet applications in an on-premises data center and wants users to reach them without exposing the applications to the Internet or maintaining a VPN. ZPA brokers this access through App Connectors, which make outbound-only connections to the Zero Trust Exchange. A Red Hat Enterprise Linux VM with the App Connector package is already deployed in the data center. You create an App Connector group, generate a new enrollment token on the VM, and enroll the App Connector with ZPA.

By the end of this lab, you will be able to:

  • Create an App Connector group for the on-premises data center.
  • Generate a new OAuth enrollment token on the App Connector VM.
  • Enroll the App Connector with the token, and confirm that its connection health is Connected.

Success criteria

  • ☐ App Connector group OnPrem exists, Enabled, with Enrollment Certificate Connector.
  • ☐ A fresh OAuth token was generated on the Corp App Connector VM.
  • ☐ The App Connector is enrolled in OnPrem and its Connection Health is Connected.

Watch out for

  • ⚠ sudo asks for the admin password (Zscaler1!).
  • ⚠ Enrollment tokens expire. If Add fails, generate a new token and try again.
  • ⚠ Connection Health can show Disconnected for about 30 seconds before it changes to Connected.

💭 THINK FIRST · INSIDE-OUT CONNECTIVITY

ZPA turns the usual remote-access model around: the data center reaches out to Zscaler, not the other way round. Think about what that buys you before you build it.

  • The App Connector only makes outbound connections to the Zero Trust Exchange. Why is that safer than publishing the app on the Internet or running a VPN concentrator?
    Q1 — MODEL ANSWER
    Nothing in the data center listens for inbound connections, so there's no public IP or open port for an attacker to find and probe. ZPA brokers each session between the user and the App Connector. A VPN puts the user on the network, where they can reach far more than the one app they need; with ZPA, users reach only the applications a policy allows.
  • Why does ZPA put every App Connector in an App Connector group instead of managing each connector on its own?
    Q2 — MODEL ANSWER
    Groups give you high availability and scale. Connectors in the same location share a group, so you can add a second connector to OnPrem for redundancy or capacity without changing any application or policy configuration. Settings such as location, certificate and software update schedule are managed once per group, and server groups and applications point at the group rather than at individual connectors.
  • You read a short-lived token on the VM's console and paste it into the portal. What does that exchange prove, and why should the token expire?
    Q3 — MODEL ANSWER
    It proves that the same administrator controls both the VM (they could read its console) and the tenant (they could add it in the portal), and it binds that specific connector to the OnPrem group. A token that expires limits the damage if it's seen or leaked: once the window closes it can't be used to enroll a rogue connector into your tenant.
Purpose: In this task, you create an App Connector group for the on-premises data center.
  • Configure the App Connector group:
    • On the Experience Center home page, type App Connector Groups in the search bar and select the appropriate option (Private Access > Private Infrastructure > App Connector Groups).
    • Select +Add and enter the following values in Add App Connector Group:
    ADD APP CONNECTOR GROUP
    FieldValue
    NameOnPrem
    StatusEnabled
    DescriptionOptional
    Enrollment CertificateConnector
    Other ConfigurationsLeave as default
    App Connector LocationEnter the city closest to you
    Top of the form: Name OnPrem, Status Enabled, Enrollment Certificate Connector. Leave the other options at their defaults.
    Scroll down to App Connector Location and search for your nearest city (the example uses Mumbai), then Save.

    Note: If the maintenance window warning appears, select I understand to proceed with the configuration.

    • Select Save.
    • Verify that the App Connector group is created.
    OnPrem is listed and Enabled. App Connector Count is 0 until you enroll the connector in Task 5.2.
Purpose: In this task, you enroll the App Connector with ZPA and confirm that it connects.
  • Configure the App Connector:
    • Launch the Corp App Connector VM.
    • Log in to the Corp App Connector VM by clicking CON in the left panel, using the following credentials:
      • Username: admin
      • Password: Zscaler1!
    Select the App Connector VM tab (named Corp ZPA Connector here), then CON, and log in at the zpa-connector login: prompt. The course name in the example header differs from yours.
    • To view the current token, type:
    Corp App Connector VM · console
    $cat /etc/issue
    EXPECTEDAn OAuth Token line, for example 3PBHR-5FJCT.
    cat /etc/issue prints the current OAuth Token. You'll replace it with a fresh one next.
  • Use the CLI to generate a new enrollment token by running the following commands:
    Corp App Connector VM · generate a new OAuth token
    # Stop the ZPA Connector service
    $sudo systemctl stop zpa-connector
    # Delete the existing OAuth token files
    $sudo find /opt/zscaler/var -mindepth 1 -delete
    # Start the ZPA Connector service to generate a new OAuth token
    $sudo systemctl start zpa-connector
    # View the new token
    $cat /etc/issue
    EXPECTEDA new OAuth Token value, different from the one you saw before. Note it down for the next step.
    After the restart, cat /etc/issue shows a new OAuth Token. The example clears the files with an older equivalent (sudo su, then rm -rf /opt/zscaler/var/*); use the commands above.
  • Enroll the App Connector with the new token:
    • In the Experience Center (Corp Client PC), type App Connectors in the Search menu and select the appropriate option (Private Access > Private Infrastructure > App Connectors).
    • Select Add, then enter:
      • Group: OnPrem (the App Connector group created in Task 5.1)
      • Enrollment Token: enter the token that you generated in the previous steps (for example, RPSTV-QZLJM)
      • Select Add.
      • Select Save.
    Group OnPrem, paste the token, select Add next to the token field, then Save.

    Note: If the generated token does not work or has expired, repeat the steps to generate a new token.

    • Confirm that the App Connector appears in the list and that its Connection Health is Connected.
    Connection Health: Connected, Status: Enabled.

    Note: The App Connector Connection Health may take about 30 seconds to update from Disconnected to Connected. Continue with the next step and check the status again after a short time.

    • Select the App Connector name to view details, including Host OS, PSE, Location, IP addresses, and Uptime.
    App Connector Details: host OS (Red Hat Enterprise Linux), the Public Service Edge it connects to, location, public and private IP (10.0.0.4) and uptime.

QUICK REFERENCE ▲
App Connector
Lightweight VM next to your apps that makes outbound-only connections to ZPA.
App Connector group
Connectors in one location, managed together for availability and scale.
Enrollment token (OAuth 2.0)
Short-lived code shown on the connector console and entered in the portal to enroll it.
Enrollment certificate
Certificate used to sign the connector's identity. The lab uses Connector.
zpa-connector
The App Connector service on the VM, controlled with systemctl.
Connection Health
Whether the connector currently has a working connection to ZPA (Connected / Disconnected).
Public Service Edge
The Zscaler cloud node the connector is attached to, shown in App Connector Details.
