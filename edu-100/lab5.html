Firewall and SSL policy protect the pipe; now you shape what flows through it. Lab 5: Configure Content Filtering & Access Control

OVERVIEW

Scenario: As the Zscaler administrator, your goal is to improve users' browsing experience by allowing access only to safe and appropriate content. In this lab, you explore how Zscaler Internet Access (ZIA) enforces content filtering and access control to protect against threats such as phishing, malware, and data leakage. You verify existing threat protection configurations, analyze risk reports, and test policy behavior to see how ZIA enforces organizational baselines for URL filtering, content categories, and cloud application controls. Finally, you use the Zscaler read-only tenant to review a live Cloud App Control rule that demonstrates granular, per-action enforcement for AI and ML applications.

  • Explore ZIA's threat protection configurations and analyze risk reporting.
  • Configure and validate a URL Filtering Policy to block risky websites (e.g., gambling, adult, shopping).
  • Test the effect of URL Filtering control on end-user experience.
  • Create and verify a Cloud App Control policy to allow access to specific apps (e.g., YouTube) while restricting others in the same category.
Time: ~25 minutes
Environment: Tasks 5.1–5.4 simulated tenant · Task 5.5 read-only tenant

Note: This lab uses both the simulated lab environment and the Zscaler tenant. You complete Tasks 5.1–5.4 in the simulated environment (the instructions below are for reference only; you perform them within the simulated lab), then switch to the Zscaler tenant for Task 5.5.

Task 5.1 View Threat Protection Reports ▾

In this task, you review current threat protection reports in the ZIA Admin Portal, examining Malware Protection, Advanced Threat Protection, and the Page Risk Score Index.

  1. View Malware Protection settings — go to Policies > Cybersecurity > Malware Protection. Compare the current settings with the Recommended Policy settings and note that Malware Protections are enabled.
    Malware Protection — current settings vs. Recommended Policy.

    Note: Malware protection defends against spyware, botnets, malicious active content, and more.

  2. View Advanced Threat Protection settings — use the left navigation panel to go to Advanced Threat Protection, or Policies > Cybersecurity > Advanced Threat Protection. Compare current settings with the Recommended Policy settings and note which protections are enabled.
    Advanced Threat Protection — current settings vs. Recommended Policy.

    Note: Advanced protections include settings against Command-and-Control Traffic, Phishing, Crypto mining, Tunneling, Cross-Site Scripting (XSS), and more.

  3. Review the Page Risk Score Index (Suspicious Content Protection — Page Risk™), which calculates a score upon user access, dynamically analyzing the page's threat level.

Task 5.2 Configure Content Filtering Controls ▾

In this task, you create a URL Filtering Policy to block risky URL categories such as gambling, adult content, and video streaming.

  1. Test high-risk URL access before configuration — open a browser on the Corp: Client PC and attempt to visit a risky website, such as 888.com (a gambling site). Verify the site is currently accessible.
    888.com is accessible before the URL Filtering rule is created.
  2. Create a URL Filtering Policy — go to Policies > Access Control > Internet and SaaS > URL Control > URL Filtering. On the URL Filtering Policy tab, select Add URL Filtering Rule.
    Add URL Filtering Rule.
  3. Configure:
    • Rule Order: 1
    • Rule Name: Risky URL Categories
    • URL Categories: Adult Materials, Shopping and Auctions, Gambling, Video Streaming
    URL Categories — Adult Materials, Shopping and Auctions, Gambling, Video Streaming.
  4. Request Methods and Protocols: ensure all options are selected. Action: select Block. Select Save and Activate.
    Action: Block, then Save + Activate.

Task 5.4 Configure Cloud App Control ▾

The Cloud App Control Policy provides granular control over how users access specific cloud applications and websites. In this task, you create a rule to allow access to YouTube while restricting other entertainment and recreation websites.

  1. Add a Cloud App Control Policy — go to Policies > Access Control > Internet & SaaS > SaaS Application Control > Policies, or use the left navigation panel. Select the Add dropdown and select Streaming Media.
  2. Create the Cloud App Control rule:
    • Rule Order: 1
    • Rule Name: Allow YouTube
    Under Criteria, select the drop-down for Cloud Applications and select YouTube, then select Done.
    Rule Name: Allow YouTube, Cloud Applications: YouTube.
  3. Action — Application Access: Allow. Add Description: Allow only YouTube. Select Save and Activate.
    Action: Allow, Description: Allow only YouTube.
    Rule saved and activated.
  4. Verify the Cloud App Control policy — ensure the new rule appears in the Streaming Media Rules List. Confirm on the Corp: Client PC that you can access YouTube.com, but other streaming sites like Netflix.com remain blocked.
    Allow YouTube rule appears in the Streaming Media Rules List.
    YouTube.com now loads; Netflix.com stays blocked.

    Note: SaaS Application policies are enforced with higher priority than URL category-based policies — that's why the specific YouTube allow overrides the broader Video Streaming block.

Task 5.5 Review Cloud App Control Granularity ▾

In this task, you review the ChatGPT_NoUpload rule under the AI & ML Applications category to understand the granular, per-action control that Cloud App Control provides. User credentials are contained in the lab access instructions provided to you via email by the instructor.

  1. In a browser window, go to https://console.zscaler.com and authenticate with the read-only Zscaler tenant credentials:
    • Username: <Admin_User_ID>
    • Password: <Session_Password>
  2. Navigate to Policies > Access Control > Internet & SaaS > SaaS Application Control > Policies. In the AI & ML Applications category, locate the rule named ChatGPT_NoUpload and select the eye icon to open and review its configuration.
    AI & ML Applications — ChatGPT_NoUpload rule.
    Per-action control — Uploading: Blocked; Access, Sharing, Downloading, Deleting, Inviting, Chatting: Allowed.

    Note: Zscaler provides granular, per-action control for cloud applications — for example, Uploading is Blocked while Application Access, Sharing, Downloading, Deleting, Inviting, and Chatting remain Allowed.
