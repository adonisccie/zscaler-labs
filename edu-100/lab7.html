Lab 7: Configure Cloud Application Monitoring

OVERVIEW

Scenario: Remote Labtenant users report that webmail is slow at certain times of the day. The Service Desk can see that the users are connected, but cannot tell whether the degradation is caused by the user's Wi-Fi or ISP, an intermediate network hop, or the application itself. To monitor the service continuously and isolate where degradation occurs, you use Zscaler Digital Experience (ZDX) to create an end user collection, define the webmail service (mail.google.com) as a custom application, and attach a Web probe and a Cloud Path probe to it.

By the end of this lab, you will be able to:

  • Create an end user collection that applies probes to all users, locations, departments, and devices.
  • Create a custom application named Mail Server for a business-critical SaaS destination.
  • Configure a Web probe to measure the availability and page fetch performance of the application.
  • Configure a Cloud Path probe to measure hop-by-hop latency, packet loss, and path health to the application.

Success criteria

  • ☐ End user collection Custom Application is listed.
  • ☐ Application Mail Server sits under it and is now Enabled.
  • ☐ Probes Mail Server_Web and Mail Server_Cloud are both listed under Mail Server.
  • ☐ Mail Server appears in Applications Overview once its first results arrive.

Watch out for

  • ⚠ Create Mail Server as Disabled, and enable it only after you add the Web probe.
  • ⚠ Metrics can take 15–30 minutes to appear. An empty dashboard right after setup is normal.
  • ⚠ Some probe screens show OS where the guide says Devices. Set it to All (or None for exclusions).

💭 THINK FIRST · FINDING WHERE IT'S SLOW

The user is connected, yet webmail is slow. Before you build the probes, think about what each one measures and why the lab pairs them.

  • The Service Desk can see the users are connected. Why can't a connected/disconnected status tell them where the slowness comes from?
    Q1 — MODEL ANSWER
    Connected is a yes/no answer; slow is a question of where time is lost. The delay could be the user's Wi-Fi or ISP, a hop in between, or the application itself. You need measurements at different layers, taken continuously from the user's device: a Web probe for how the application responds, and a Cloud Path probe for latency and loss at each hop. Together they show where the degradation starts.
  • Why does the lab create Mail Server disabled, add the Web probe, and only then enable the application?
    Q2 — MODEL ANSWER
    It's the build-then-switch-on pattern. The application is configured completely before it starts monitoring, so you don't collect data from a half-finished setup. When you enable the application, ZDX enables its Web probe automatically, so the application and its probe go live together.
  • The Cloud Path probe follows the Web probe. What does that pairing give you when you investigate a slow page?
    Q3 — MODEL ANSWER
    Both probes measure the same destination, so you can line them up. A spike in page fetch time from the Web probe can be matched with latency or packet loss at a specific hop in the Cloud Path probe, such as the home Wi-Fi, the ISP or the far end. The Web probe form even notes that changing the URL's protocol or port updates the Cloud Path probes that follow it, which keeps the two in step.

Purpose: In this task, you will create a custom application.

Purpose: In this task, you configure probes for the custom application you created in Task 7.2.

    Note: After you enable the custom application, ZDX enables the Web probe associated with it automatically. Depending on your organization's ZDX plan, it can take 15–30 minutes for metrics to appear for a newly onboarded application. Check back later to verify the metrics.

Verify in Applications Overview

  • In the left panel, click Applications Overview (Digital Experience > Applications > Applications Overview) and verify that the Mail Server application is now included in the reports.
    Applications Overview lists Mail Server with its ZDX Score and active users. If it isn't listed yet, wait for the first probe results and refresh.
  • Click the application to view more detailed information related to the Web probe and the Cloud Path probe.

MENTAL NOTE
Collection Custom Application (all users, no exclusions) → application Mail Server (Custom, created Disabled) → Web probe Mail Server_Web (https://mail.google.com, every 5 min) → enable the app → Cloud Path probe Mail Server_Cloud (mail.google.com, ICMP, follows the Web probe). Web probe = how the app responds; Cloud Path = where on the path time is lost. Allow 15–30 minutes for data, then find Mail Server in Applications Overview.

QUICK REFERENCE ▲
ZDX
Zscaler Digital Experience: measures application, network and device performance from users' devices.
End user collection
A container for monitored applications, with probing and exclusion criteria that its probes inherit.
Probing / exclusion criteria
Which users, groups, locations, departments and devices run the probes, and which are left out.
Custom application
An application you define yourself (here, webmail) so ZDX can monitor it.
Web probe
Fetches the app's URL with GET to measure availability and page fetch performance.
Cloud Path probe
Measures hop-by-hop latency, packet loss and path health from the device to the app.
Follow Web Probe
Ties a Cloud Path probe to a Web probe for the same destination, so the two views line up.
Run frequency
How often each probe runs. The lab uses every 5 minutes.
Applications Overview
ZDX dashboard (Digital Experience > Applications) that lists each monitored application with its ZDX Score and active users.
