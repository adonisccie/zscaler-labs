LAB 7 · PRIVATE ACCESS

Add a Corporate Application

Your App Connector is live but has nothing to publish yet. Here you segment access two different ways — a broad wildcard segment for general discovery, and a narrow, user-scoped segment for one specific app — then enable ICMP just for troubleshooting, and only for the app that needs it.

Lab 7: Add a Corporate Application

OVERVIEW

Scenario: Safemarch Corporation needs secure, scalable access to multiple internal applications that share a common domain pattern. To simplify access management and enforce reliable Zero Trust policies, you configure a wildcard application segment for general access and a dedicated application segment for more granular user and application access. You also implement ICMP access for troubleshooting.

  • Configure a wildcard application segment for internal applications (e.g., *.patraining.safemarch.com).
  • Configure user-specific access to defined internal applications.
  • Enable ICMP access for troubleshooting in the ZPA Admin Portal.
Time: ~30 minutes
Environment: Simulated tenant

Note: All tasks in this lab (7.1–7.3) are completed using the simulated lab exercises. The instructions below are for reference only; you perform the steps within the simulated lab environment.

Task 7.1 Configure a Wildcard Application Segment for Internal Applications ▾

In this task, you configure a wildcard application segment to discover internal applications matching a domain pattern and allow general access for all users.

  1. Add a Wildcard Application Segment — from the Experience Center, navigate to Policies > Access Control > Private Applications > App Segments. Select +Add Application Segment.
    Policies > Access Control > Private Applications > App Segments — Add Application Segment.
  2. At the Define Applications step > General Information:
    • Name: Discovery
    • Status: Enabled
    • Source IP Anchor: Disabled
    • Add a suitable description
    General Information — Name: Discovery.
  3. Applications — in the "Enter a domain or IP address" field, specify *.patraining.safemarch.com. Client Connector Access — define Port Ranges:
    • TCP Port Ranges: 2-52 and 54-65535
    • UDP Port Ranges: 1-52 and 54-65535
    • TCP Keepalive: Disabled
    Common Configuration: leave defaults.
    Domain: *.patraining.safemarch.com, TCP/UDP port ranges configured, TCP Keepalive: Disabled.
    Common Configuration — left at defaults.
  4. At the Additional Configuration step, leave unchanged: Double Encryption: Disabled; Bypass: Use Client Forwarding Policy; ICMP Access: Disabled. Select Next.
    Additional Configuration — defaults left unchanged, ICMP Access: Disabled.

    Note: ICMP Access is typically disabled unless ICMP connectivity is required for application troubleshooting or testing.

  5. At the Segment Group step, select Add Segment Group:
    • Name: Discovered Apps
    • Status: Enabled
    Select Next.
    Segment Group — Discovered Apps.
  6. Add Server Group:
    • Name: CorpServers
    • Status: Enabled
    • Dynamic Server Discovery: Enabled
    • App Connector Groups: OnPrem
    Select Next.
    Server Group — CorpServers, Dynamic Server Discovery Enabled, App Connector Group: OnPrem.
  7. At the Review step, confirm the configuration and select Save.
    Review — Discovery App Segment summary.
    Discovery App Segment saved.
  8. Configure Access Policies — go to Policies > Access Policy. Select Add:
    • Name: Discovered Apps
    • Rule Action: Allow Access
    • App Connector Selection Method: All App Connector Groups for the Application
    Select Add Criteria, select Applications, and choose the Discovered Apps Segment Group. Do not add additional criteria. Select Save.
    Access Policy — Criteria: Applications = Discovered Apps Segment Group.
    Discovered Apps access rule saved.
    Access Policy list — Discovered Apps, Allow Access.
  9. Test the Access Policy — on the Corp: Client PC, open a web browser window and the Zscaler Client Connector side-by-side. Load http://intranet.patraining.safemarch.com (a bookmark is provided). Confirm the Intranet page loads correctly, then refresh and verify the Total Bytes Sent/Received counters in ZCC increment.
    Intranet page loads; ZCC traffic counters increment.

Task 7.2 Configure User-Specific Access to an Intranet Application ▾

In this task, you create a dedicated application segment to provide more granular access control that limits intranet access to the "Student" user.

  1. Review recently accessed private applications — from the Experience Center, type applications in the search bar to navigate into Analytics > Private Applications. Scroll to Applications Discovered in the past 14 days to identify recently accessed applications.
    Analytics > Private Applications — Applications Discovered in the past 14 days.
    intranet.patraining.safemarch.com appears in the discovered applications list.
  2. Configure the Intranet Application Segment — select Add Application Segment, select the application intranet.patraining.safemarch.com, and select Define Selected Applications. Alternatively, navigate to Policies > App Segment.
    Define Selected Applications — intranet.patraining.safemarch.com.
  3. At the Define Applications step:
    • Name: Intranet
    • Status: Enabled
    • Source IP Anchor: Disabled
    • Add a suitable description; leave other settings default
    Select Next.
    Intranet App Segment — Name: Intranet.
    Remaining settings left at default.
  4. Add Segment Group:
    • Name: CorpApps
    • Status: Enabled
    Select Next.
    Segment Group — CorpApps.
  5. Add Server Group: Name CorpServers (selected from the existing wildcard application segment). Select Next, then Save.
    Server Group — reuse existing CorpServers.
    Saved — redirected to the Edit Policy page.

    Note: After saving the Application Segment, you're redirected to the Edit Policy page. From there you can add a policy for the Discovery App Segment, or navigate directly to Policies > Access Policy from the left-hand menu.

  6. Add Access Policy — navigate to Policies > Access Policy, select Add, and configure:
    • Rule Name: Allow Intranet
    • Rule Action: Allow Access
    • App Connector Selection Method: All App Connector Groups
    Access Policy — Allow Intranet, Allow Access.
  7. Define the Criteria — select Add Criteria, select Applications, and choose the Intranet Application Segment. Add additional criteria for User and Session Attributes: select the + icon, select loginname, and choose the user Student@<FQDN>. Select Save.
    Criteria — Applications: Intranet.
    User Attributes — add loginname criteria.
    loginname — Student@<FQDN> selected.
    Allow Intranet rule — scoped to Student.
    Allow Intranet rule saved.
  8. Test the policy — open a web browser on the Corp: Client PC and ZCC side-by-side. Navigate to http://intranet.patraining.safemarch.com using the provided bookmark. Ensure the intranet page loads successfully for the Student user; refresh and confirm the Total Bytes Sent/Received counters in ZCC increment.
    Intranet loads for Student; ZCC counters increment.

Task 7.3 Enable ICMP Access ▾

In this task, you enable ICMP access on an application segment so you can use ping to troubleshoot reachability to an internal application.

  1. Verify ICMP accessibility — on the Corp: Client PC, open Command Prompt and enter:
    ping intranet.patraining.safemarch.com
    Ping fails — ICMP Access is still disabled on the Intranet segment.

    Note: If ICMP Access is disabled in the Application Segment, the internal application does not respond to ping requests or reachability checks over ICMP.

  2. Enable ICMP Access in the ZPA Admin Portal — navigate to Policies > Access Control > Private Applications > App Segments, locate the Intranet segment, and select Edit. In the Edit Application Segment window, select Next to reach the ICMP Access field, set it to Enabled, and select Save.
    ICMP Access — set to Enabled on the Intranet segment.
    Intranet segment saved with ICMP Access enabled.
  3. Test ICMP connectivity — return to the Corp: Client PC, reopen Command Prompt, and enter:
    ping intranet.patraining.safemarch.com
    Ping now succeeds — ICMP traffic is allowed.

    Expected Result: The internal application now responds to ping requests, confirming ICMP traffic is allowed.

    Caution: Enable ICMP Access only when ICMP connectivity is required for troubleshooting. Do not use ICMP Access for general application testing.
