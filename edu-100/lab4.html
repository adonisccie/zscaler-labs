LAB 4 · SSL INSPECTION

Configure SSL Inspection Policies

Firewall rules can't see inside an encrypted session — and neither can most threats hide there without SSL inspection turned on. Here you enable inspection for all destinations, watch the certificate chain change under your own eyes, then review how privacy-sensitive categories get a deliberate bypass in the real-world tenant.

Lab 4: Configure SSL Inspection Policies

OVERVIEW

Scenario: As the Zscaler administrator, you are tasked with enabling SSL/TLS inspection to monitor and enforce policies on users' encrypted web traffic. Since most modern threats hide within HTTPS traffic, enabling SSL inspection provides visibility into encrypted sessions and allows policies to be enforced effectively. You configure SSL inspection for all destinations and define exemptions for trusted or privacy-sensitive categories. You also use the Zscaler read-only tenant to review pre-configured bypass rules for privacy-sensitive traffic categories, and examine SSL inspection logs to distinguish between inspected and bypassed HTTPS sessions.

  • Enable and configure SSL inspection policies for all encrypted traffic.
  • Analyze SSL inspection logs and identify inspection or bypass events.
Time: ~15 minutes
Environment: Task 4.1 simulated tenant · Tasks 4.2–4.3 read-only tenant

Note: This lab uses both the simulated lab environment and the Zscaler tenant. You complete Task 4.1 in the simulated environment (the instructions below are for reference only), then switch to the Zscaler tenant for Tasks 4.2–4.3.

Task 4.1 Enable SSL Inspection for All Destinations ▾

In this task, you enable SSL inspection for all encrypted traffic.

  1. Verify the current SSL Inspection status. On the Corp: Client PC, open a Chrome browser window in Incognito Mode and navigate to www.wikipedia.org. Select the site information (filter) icon in the URL field.
    Site information icon in the address bar.
  2. Select Connection is secure > Certificate is valid.
    Certificate is issued by the destination web server — SSL inspection is not yet active.

    Note: You should see that the certificate was issued by the destination web server. The site information icon resembles "three horizontal lines connected by dots" and is sometimes shown as a padlock, typically to the left of the URL.

  3. Enable SSL Inspection. In the Zscaler Experience Center, navigate to Policies > Common Configuration > SSL/TLS Inspection > SSL/TLS Inspection Policy. On the SSL Inspection Policy tab, select +Add SSL Inspection Rule. Configure:
    • Rule Order: 1
    • Rule Name: SSL Inspect All
    Add SSL Inspection Rule — Order 1, Name: SSL Inspect All.
    Rule criteria — left at defaults so the rule applies broadly.
  4. Scroll down to the ACTION section and select Inspect under Action.
    Action: Inspect.
  5. Select Save and Activate.
    SSL Inspect All rule saved and activated.
  6. Verify inspection status — close or refresh the Incognito browser (to ensure the new policy applies), re-open an Incognito window, and visit www.wikipedia.org again. Select the site information icon > Connection is secure > Certificate is valid.
    Certificate is now signed by Zscaler — SSL inspection is active.

    Note: You will see that you have received a server certificate signed by Zscaler.

Task 4.2 Review SSL Inspection Bypass Rules ▾

In this task, you review the SSL/TLS Inspection Policy to understand that not all traffic needs to be inspected — certain categories are configured with a bypass rule. User credentials are contained in the lab access instructions provided to you via email by the instructor.

  1. In a browser window, go to https://console.zscaler.com and authenticate with the read-only Zscaler tenant credentials:
    • Username: <Admin_User_ID>
    • Password: <Session_Password>
    Go to Policies > Common Configuration > SSL/TLS Inspection > SSL/TLS Inspection Policy.
    SSL/TLS Inspection Policy — read-only tenant rule list.
  2. Observe the pre-configured bypass rule "No Inspect Finance & Health" with the action Do Not Inspect. Review the Criteria: URL Categories — Finance, Health.
    No Inspect Finance & Health — Do Not Inspect, URL Categories: Finance, Health.

    Note: This rule is configured to bypass SSL inspection for privacy-sensitive traffic categories. This illustrates that Zscaler allows you to define specific traffic that does not require decryption and inspection.

Task 4.3 Review SSL Inspection Logs ▾

In this task, you review SSL/TLS inspection logs and identify which sessions were inspected by Zscaler and which were bypassed based on configured policy rules.

  1. Go to Analytics > Web > Web Insights > Logs.
    Analytics > Web > Web Insights > Logs.
  2. In the Logs view, apply the following filters:
    • Timeframe: Last 15 Minutes
    • SSL/TLS Inspected: On (toggle enabled)
    • SSL/TLS Policy Reason: Inspected
    • Display: selected
    • Number of Records Displayed: 1k
    Logs filter — SSL/TLS Inspected: On, Policy Reason: Inspected, 1k records.
  3. Review the resulting log entries and compare how traffic is handled — identify sessions with Action Inspect (SSL decrypted and inspected) versus Action Do Not Inspect (bypassed, not decrypted). For each entry, note the URL Category, Destination, and Matched Policy Rule.
    Log results — Inspect vs. Do Not Inspect, with URL category, destination, and matched rule.
