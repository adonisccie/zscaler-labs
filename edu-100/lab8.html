Navigate the Incident, Self-Service & Application Overview Dashboards

Policy tells you what's allowed; ZDX tells you what it actually feels like to use. In this final lab you tour the dashboards a Zscaler administrator lives in day-to-day — Performance, Incidents, Self-Service, Application, and User Overview — learning to trace a bad experience down to a specific hop.

Lab 8: Navigate the Incident, Self-Service, Application Overview Dashboards

OVERVIEW

Scenario: As the Zscaler administrator, you know that your organization relies on Zscaler Digital Experience (ZDX) to monitor and improve user experiences across endpoints, networks, and applications. Your role is to analyze signals provided by ZDX dashboards — Incident, Self-Service, Application Overview, and User Overview — and use this data to identify the root cause of user experience issues. By understanding and interpreting key performance trends and metrics, you make informed decisions to enhance the digital experience across the organization.

  • Navigate and analyze ZDX's dashboards, including Performance Overview, Incidents, Self-Service, Application Overview, and User Overview.
  • Analyze root cause indicators for application, network, and user issues.
  • Troubleshoot key performance problems and plan corrective actions.
Time: ~30 minutes
Environment: Read-only tenant (all tasks)

Note: All tasks (8.1–8.4) in this lab use only the Zscaler read-only tenant.

Task 8.1 View ZDX Performance Dashboard ▾

In this task, you take the role of a Zscaler administrator and explore the ZDX Performance Dashboard, including Most Impacted Applications, Regions by ZDX Score, and ZDX Score. User credentials are contained in the lab access instructions provided to you via email by the instructor.

  1. In your browser, navigate to https://console.zscaler.com and authenticate with the read-only Zscaler tenant credentials:

    Go to Analytics, then select "Switch to Existing Reports", then navigate to Analytics > Digital Experience > Applications > Mapview — or in the Search option, type Map View.

    Digital Experience > Applications > Mapview.
  2. At the top of the Performance Dashboard, select 24 Hours from the dropdown to set the reporting interval.
    Reporting interval — 24 Hours.
  3. Explore key dashboard features — review the Most Impacted Applications list and select an application (e.g., "ZPA Application") to drill into its performance metrics. In the Regions by ZDX Score map, select a location to view its ZDX Score and total users; use the +/- controls to zoom.
    Regions by ZDX Score — select a location for score and user count.
  4. Select Draw Fence, use your mouse to select a geographic area, then select Filter Selection and review the fenced region's performance metrics.
    Draw Fence — select a geographic area.
    Filter Selection — fenced region metrics.
  5. Select any location to view the ZDX Score and total users. Select Reset (top-right of the map) to clear applied settings if needed.
    Location detail — ZDX Score and total users.
    Reset — clears applied map filters.
    Map view after Reset.
  6. Review ZDX Score details for selected applications — scroll down to view the ZDX Score for the selected application. Select Add Another Application at the bottom to compare ZDX scores of additional applications.
    ZDX Score detail for the selected application.

Task 8.2 View Incidents and Self Service Dashboards ▾

In this task, you analyze incident trends and use self-service insights to identify key issues affecting user application performance.

  1. Explore the Incidents Dashboard — on the left navigation panel, go to the Incident Dashboard, or type Incident Dashboard in the Search option. Review the information for the various incident areas.
    Incident Dashboard — overview of incident areas.
  2. Scroll down to the Incidents by Epicenters map, select a marker, and select one of the incidents. Select View incidents Details and review the collected metrics.
    Incidents by Epicenters — select a marker for incident details.

    Note: If you see "Try again later. If this persists, contact Zscaler Support" while viewing the Incidents By Epicenters dashboard, refresh the page and try again.

  3. Explore the Self Service Dashboard — navigate to Dashboard > Self Service Dashboard and explore the summary graphs about notifications in the selected timeframe.
    Self Service Dashboard — notification summary graphs.

Task 8.3 View Application Overview Dashboard ▾

In this task, you investigate predefined and custom application metrics to identify problem patterns and potential root causes for user or device issues.

  1. Navigate to Applications Overview — in the left navigation panel, go to Applications, or type Applications in the Search option.
    Applications Overview — monitored application list.
  2. Identify the lowest score — sort the applications table by ZDX Score Trend and select the application with the lowest ZDX Score.

    Note: Different applications show different dashboard views — for example, UCAAS applications do not show a Page Fetch Time tab.

  3. Scope a time period — in the ZDX Score Over Time graph, drag your mouse to zoom in on a time period with a significant change. Select Zoom out to return.
    ZDX Score Over Time — zoomed to a period of significant change.
  4. View impact dimensions — scroll down to view impacted Meetings, Regions, and Zscaler Locations, and view the application's configured Probe Status.
    Impact dimensions — Meetings, Regions, Zscaler Locations, Probe Status.

Task 8.4 View User Overview Dashboard ▾

In this task, you analyze user-specific metrics and explore reports to troubleshoot and improve user experiences.

  1. Navigate the Users Overview Dashboard — from the navigation bar, select Users. Scope by application: select an application from the dropdown and select Apply.
    Users Overview — scope by application.
  2. Find impacted users — apply filters in the ZDX Score dropdown (Poor, Okay, Good) to filter the users table. Select a user with Poor or Okay performance for deeper analysis.
    Users table — filtered by ZDX Score (Poor/Okay/Good).
  3. Review user/device context — review OS type, IP address information, and other device-specific metrics. Select View for a user, then View More Device Details.
    User/device context — OS, IP, device metrics.
  4. Analyze details under the Hardware, Network, and Software tabs, then select Done. Review application performance for this user — view the selected application's ZDX Score Over Time graph.
    Hardware / Network / Software tabs, plus this user's ZDX Score Over Time.
  5. Review Web Probe Metrics — scroll to the Web Probe Metrics graphs. Select/unselect graphs as needed, and select anywhere on a graph for more detail about spikes in Page Fetch Time, Server Response Time, and similar metrics.
    Web Probe Metrics — spike detail on Page Fetch Time / Server Response Time.
  6. Review Cloud Path Metrics — scroll to the Cloud Path Probe Metrics graphs and view Latency and Packet Loss. Select/unselect Cloud Path legs as needed.
    Cloud Path Metrics — Latency and Packet Loss.
    Cloud Path legs — select/unselect to isolate a leg.
  7. Scroll to the Hop View and expand the leg with the highest differential latency (shown in orange). Mouse-over a hop for more information.
    Hop View — leg with highest differential latency (orange).
  8. Select the Command Line View and identify hops with high packet loss and/or latency.
    Command Line View — hop-by-hop packet loss and latency.

Note: ZDX probes are small tests that collect application performance data. Predefined applications include built-in probes, while custom applications require you to configure probes manually. Because troubleshooting in ZDX is probe-driven, understanding how probes work is essential for interpreting ZDX metrics and finding the root cause of issues.
