Lab 9: Contain an Attack with the Ransomware Kill Switch

OPTIONAL LAB

In an incident, one change of Kill Switch mode enforces pre-staged rules across every branch in seconds.

Scenario: During a security event, the organization must stop lateral SSH between private subnets immediately — without editing policies under pressure.

In this lab you will:

  • Stage an SSH allow rule (Green) and an SSH block rule (Orange).
  • Switch to Orange and watch SSH get refused.
  • Switch back to Green.

Success criteria — tick when done

  • ☐ SSH works in Green and is refused in Orange.
  • ☐ Kill Switch back to Green.

Watch out for

  • ⚠ SSH still works in Orange — check the block rule has Kill Switch Orange and was committed.
  • ⚠ Host-key prompt — type yes on the first SSH connection.

💭 THINK FIRST · RANSOMWARE KILL SWITCH

During an attack nobody wants to write policy under pressure.

  • Why stage the block rule before the incident?
    Q1 — MODEL ANSWER
    With the Kill Switch you stage rules per mode in advance, so during an incident you only change the mode.
  • Why prove SSH works in Green first?
    Q2 — MODEL ANSWER
    It shows that a later failure in Orange is caused by the Kill Switch rule and nothing else.
  • Why switch back to Green at the end?
    Q3 — MODEL ANSWER
    The mode applies to the whole site until changed; leaving Orange would keep blocking traffic in later labs.
  • Kill Switch modes run from Green (normal) to Red (most restrictive). Rules tagged with a mode apply when the site is in that mode.
Kill Switch modes run from Green (normal) to Red (most restrictive). Rules tagged with a mode apply when the site is in that mode.
