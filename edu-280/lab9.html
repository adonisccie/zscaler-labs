Configure Ransomware Kill Switch Policy

Contain an attack with one click: build an Allow-SSH policy (green mode) and a cloned Block-SSH policy (orange mode), then flip the Kill Switch to orange and watch SSH between private subnets get cut — even though the block rule sits second in the list.

Lab 9: Configure Ransomware Kill Switch Policy

RANSOMWARE KILL SWITCH

The Zscaler Ransomware Kill Switch is a one-click attack-surface-reduction tool built into Zero Trust Device Segmentation. It instantly blocks vulnerable protocols and access to critical networks with pre-set severity levels — acting as a multi-layer enforcement point that halts lateral movement when a machine is infected, using escalation paths like "virtual fuses" (Defcon levels).

You'll create two policies and flip between modes:

  • Allow SSH from Windows Server (VLAN10) to OT (VLAN30) — Green mode
  • Block SSH for the same source/destination — Orange mode — then validate

The Kill Switch acts as a tiered enforcement point — flipping modes (e.g. green → orange) changes which pre-staged policies are enforced.
  • Go to Infrastructure › Connectors › Edge › Zero Trust Branch › Sites and select POD##-Student-Lab.
  • Select Policies [1] › Configure [2], then Add Policy.
Open your POD site.
Policies › Configure.
Add Policy.
  • Action: Accept [1]
  • Name: POD##-Allow-ssh [2]
  • Source Zone: LAN_ZONE | LAN Zone [3] · Destination Zone: LAN_ZONE | LAN Zone [4]
  • Source: Network › Private Subnets [5] · Destination: Network › Private Subnets [6]
  • Ports: Custom Port [7] · Value tcp:22 [8] (search tcp:22 → select ssh → Add)
  • Ransomware Kill Switch: Green [9]
  • Click Add [10] to save.
Accept rule: Private Subnets, tcp:22 (ssh), Kill Switch = Green.
  • Click Commit (takes effect in a few seconds).
  • Validate: in the Student Portal open the Windows Server (VLAN10).
Commit the Allow-ssh policy.
Open the Windows Server (VLAN10).
  • From Command Prompt: ssh zscaler@10.1.30.10, password Zscaler123!. After authentication you're logged into the VLAN30 host — close the window. (If prompted to trust the host, type yes.)
  • Confirm the policy Hit Count increased from 0. Now clone this policy to build the block.
ssh zscaler@10.1.30.10 succeeds under the green Allow rule.
Hit Count climbs on the Allow-ssh rule.
  • Select the gear icon [1] of the Allow-ssh policy and choose Clone [2].
Clone the Allow-ssh policy as a starting point.
  • Action: Reject [1]
  • Name: POD##-Block-ssh [2]
  • Source/Destination Zone: LAN_ZONE · Source/Destination: Network › Private Subnets
  • Ports: Custom Port › tcp:22 (select ssh → Add)
  • Ransomware Kill Switch: Orange [3]
  • Click Clone [4] to create the policy.
Reject rule: same source/dest/port, Kill Switch = Orange.
  • Click Commit (takes effect in a few seconds).
Commit the Block-ssh policy.
  • Click Reorder, drag POD##-Block-ssh to position 2 [1], then Save Policy Order [2].
Click Reorder.
Block-ssh moved to #2 → Save Policy Order.
Policies reordered — note the block is second, below the allow.
  • Navigate to Policies › Access Control › Segmentation › Zero Trust Branch › Kill Switch [1]. Ensure your POD is selected [2], click the Switch [3], type orange [4], then Confirm [5].
Kill Switch → select POD → type orange → Confirm.
  • Validate the mode via Sites › your site › Overview — a pop-up indicates the Ransomware Kill Switch is ON.
Site Overview confirms the Kill Switch is ON (orange).
  • Open the Windows Server Command Prompt and retry ssh zscaler@10.1.30.10 — the connection is now refused. The block is effective even though it's in position 2, because the Kill Switch mode changes enforcement/precedence.

Recommended: switch back to the normal Green Kill Switch mode once you've completed this task.

ssh zscaler@10.1.30.10 → connection refused. Orange mode enforces the block.
  • Confirm the Block-ssh policy Hit Count increased above 0.
Hit Count climbs on the Block-ssh rule — the Kill Switch works.

MENTAL NOTE
Ransomware Kill Switch = one-click, tiered containment. Rules are tagged with a mode: Green Allow-ssh, Orange Block-ssh (both tcp:22, Private Subnets, VLAN10→VLAN30). Flipping the switch to orange (Kill Switch › select POD › type orange › Confirm) enforces the block regardless of list order — position 2 still wins. Validate: ssh zscaler@10.1.30.10 goes from success → connection refused. Cutting SSH between private subnets stops lateral movement. Switch back to green when done.
