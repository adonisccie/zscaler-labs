Lab 8: Troubleshoot with Admin Console Diagnostics

OPTIONAL LAB

Work from the outside in: Appliance Admin Console status first, then Linux tools for interfaces, containers, HA and policy hits.

Scenario: A user reports intermittent problems. You collect the evidence a support engineer would ask for.

In this lab you will:

  • Read interfaces and routes with the Appliance Admin Console.
  • Inspect neighbours, ZPA mappings, containers and VRRP.
  • Capture live traffic and confirm policy hits at the data plane.

Success criteria — tick when done

  • ☐ All commands return the expected data on the Active unit.

Watch out for

  • ⚠ Both units MASTER — VRRP split-brain — check the ge4 HA link.
  • ⚠ Command rejected in the Admin Console — the Appliance Admin Console accepts show/run/config; use the Console tab for Linux tools.
Time: 30 min
Type: Optional
Before you start: Lab 5
You’ll use: Appliance Admin Console, Console tab, Server

💭 THINK FIRST · ADMIN CONSOLE DIAGNOSTICS

A user reports intermittent problems. Collect the evidence a support engineer would ask for.

  • Why start with show ip before looking at policy?
    Q1 — MODEL ANSWER
    An interface with a missing or wrong address explains most connectivity problems before you need to look any deeper.
  • A host is missing from ip neighbour. What does that suggest?
    Q2 — MODEL ANSWER
    It has never reached the gateway, which points to a LAN or VLAN problem rather than a policy problem.
  • A PBR rule is Active in the portal but shows zero packets. What is the likely cause?
    Q3 — MODEL ANSWER
    The wrong source subnet. ge6 = Subnet10, ge7 = Subnet20, ge8 = Subnet30.
