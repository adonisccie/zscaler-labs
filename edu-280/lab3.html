Lab 3: Secure Internet and Private Access

CORE LAB

DTLS runs over UDP 443 and outperforms IPSec on lossy links. ZPA gives users zero trust access to branch servers without exposing them to the internet.

Scenario: With segmentation in place, you must confirm that branch devices reach the internet securely through Zscaler, that branch users can open private apps through ZPA, and that a remote user can RDP to the branch server.

In this lab you will:

  • Switch the ZIA tunnels from IPSec to auto-provisioned DTLS (Z-Tunnel).
  • Validate internet security and ZPA web access from the branch.
  • Create an internal DNS policy and RDP to the branch server through ZPA.
  • Find the RDP session in Private Diagnostics.

Success criteria — tick when done

  • ☐ zia0/zia1 DTLS Up; Default ZIA Rule uses ZIA-DTLS on both appliances.
  • ☐ ip.zscaler.com, pings, 888.com block and dcweb.ztwan.lab as expected.
  • ☐ RDP to pod##-winserver.ztwan.lab works and appears in Private Diagnostics.

Watch out for

  • ⚠ No internet after the switch — check the Default ZIA Rule on both appliances and Commit.
  • ⚠ dcweb does not load — use http:// — https:// is not published.
  • ⚠ 888.com not blocked — try http://888.com, lottery.com or casino.com.

💭 THINK FIRST · INTERNET & PRIVATE ACCESS

Two security paths meet at the branch: ZIA for internet traffic and ZPA for private apps. Think about what changes when the tunnel type changes.

  • Switching to Z-Tunnel builds the DTLS tunnels. Why must you also edit the Default ZIA Rule?
    Q1 — MODEL ANSWER
    Building the tunnels does not move any traffic. The Forwarding Policy decides which tunnel carries which traffic, so the Default ZIA Rule must point to ZIA-DTLS — otherwise traffic keeps looking for the old IPSec tunnels.
  • Why do the three pings (10.1.10.1, 8.8.8.8, cnn.com) each test something different?
    Q2 — MODEL ANSWER
    10.1.10.1 proves the local LAN/VLAN gateway, 8.8.8.8 proves routing and the tunnel to the internet by IP, and cnn.com adds name resolution — so you can tell exactly which layer failed.
  • RDP is not a web app. What does RDP working through ZPA prove?
    Q3 — MODEL ANSWER
    ZPA brokers any TCP application, not just web traffic, while the server stays invisible to the internet. The App Connector makes outbound-only connections, so no inbound ports are opened at the branch.
Purpose: Release 8.1.x creates DTLS tunnels to ZIA automatically — one per WAN link, with TLS fallback and automatic certificate renewal — once you switch the site to Z-Tunnel.
  • In your site open Connectivity [1] > Internet & SaaS [2] and click Switch to Z-Tunnel [3].
In your site open Connectivity [1] > Internet & SaaS [2] and click Switch to Z-Tunnel [3].

Why: DTLS runs over UDP, so, like IPSec, it avoids the slowdown of carrying TCP inside TCP, and it can fall back to TLS when UDP is blocked. Auto-provisioning also removes manual tunnel and credential setup.
