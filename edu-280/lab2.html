Lab 2: Segment East-West Traffic

CORE LAB

ZTB firewall policies work at layer 3/4 on subnets and ports; application controls happen in ZIA. By default the branch allows traffic between its VLANs, so segmentation starts here.

Scenario: Security has asked you to reduce lateral movement inside the branch. The Windows Server segment must not reach IoT devices, while a business exception allows OT devices to reach IoT at this site only.

In this lab you will:

  • Prove that VLANs can reach each other by default.
  • Block Subnet10 → Subnet20 with a macrosegmentation rule and verify it with hit counts.
  • See what the Skip action does.
  • Override a global block with a site-level allow rule for OT → IoT.

Success criteria — tick when done

  • ☐ Subnet10 → Subnet20 times out with the Drop rule; Hit Count > 0.
  • ☐ With Skip, the ping replies again.
  • ☐ OT1 → 10.1.20.10 replies with POD##-Allow-OT-to-IoT; Hit Count > 0.

Watch out for

  • ⚠ Rule not taking effect — ICMP ID reuse — close the prompt, wait up to 5 minutes, retry.
  • ⚠ Hit Count is 0 after commit — expected; it resets on every commit.

💭 THINK FIRST · SEGMENT EAST-WEST TRAFFIC

By default the branch allows traffic between its VLANs. Security wants less lateral movement — but one site needs an exception.

  • Why does the Subnet10 → Subnet20 ping work before you add any rule?
    Q1 — MODEL ANSWER
    The default System-All-Networks rule permits traffic between VLANs. Segmentation starts only when you add policy above that rule.
  • A global rule blocks OT → IoT for every site. Why create a site rule instead of editing the global rule?
    Q2 — MODEL ANSWER
    Global rules apply to every site, so changing one would affect all branches. Policies are evaluated site first, then template, global and system, with first match wins — a site Accept rule overrides the global block for this site only.
  • What does the Skip action do, and when would you use it instead of deleting a rule?
    Q3 — MODEL ANSWER
    Skip turns a rule off without allowing or blocking anything — evaluation moves to the next matching rule. It lets you keep the rule for later while its traffic is handled by the next rule (here the default allow).

MENTAL NOTE
Order of evaluation: site → template → global → system, first match wins. Changes are staged until Commit, and Hit Counts reset on every commit. Drop = silent block, Skip = ignore rule, Accept in a site rule beats a global block.
