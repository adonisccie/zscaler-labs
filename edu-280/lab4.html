Lab 4: Microsegment OT Devices

CORE LAB

Legacy OT devices cannot run agents. ZTB isolates them from each other on the same VLAN, using its built-in firewall, without re-addressing the network.

Scenario: Two OT controllers share Subnet30. If one is compromised, it must not be able to reach the other.

In this lab you will:

  • Find the OT2 address with Asset Intelligence.
  • Prove that OT1 can reach OT2 by default.
  • Block traffic inside Subnet30 and verify it with hit counts.

Success criteria — tick when done

  • ☐ OT1 → OT2 replies before the rule.
  • ☐ POD##-Block-IntraOT committed; OT1 → OT2 fails; Hit Count > 0.

Watch out for

  • ⚠ Ping still works — ICMP ID reuse — stop the ping, wait up to 5 minutes, retry.
  • ⚠ OT2 not in Asset Intelligence — run arp -a in the site Console tab.

💭 THINK FIRST · MICROSEGMENT OT DEVICES

Legacy OT devices cannot run agents, and two of them share one subnet.

  • Why can the gateway enforce a rule between two hosts on the same subnet?
    Q1 — MODEL ANSWER
    Subnet30 uses Device (/32) segmentation, so every host gets a 255.255.255.255 mask and all of its traffic passes through the gateway, where policy applies.
  • Why look up the OT2 address in Asset Intelligence instead of guessing?
    Q2 — MODEL ANSWER
    OT devices get DHCP addresses that can change. Asset Intelligence discovers devices passively from their traffic so you always test against the current address.
  • Why use Reject here instead of Drop?
    Q3 — MODEL ANSWER
    Reject answers the sender immediately, so OT1 learns quickly that the path is closed instead of waiting for a timeout.
