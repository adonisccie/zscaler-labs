Lab 4: Configure Microsegmentation Policy

MICROSEGMENTATION

Zero Trust Branch enables microsegmentation — granular access control that isolates applications, workloads, and devices within the branch, so communication is authenticated and authorised even between hosts on the same VLAN. This prevents lateral movement and limits the blast radius of a compromise.

  • Confirm two OT endpoints on VLAN30 can reach each other by default
  • Locate OT2's DHCP-assigned /32 address via Assets (or the console)
  • Create a Reject rule blocking OT1 → OT2 and validate the block

  • Go to Infrastructure › Connectors › Edge › Zero Trust Branch › Assets [1], filter for your site [2], and identify the 10.1.30.x host with a DHCP-assigned IP [3]. Record it — you'll ping it from OT1. (It may be 10.1.30.20, 10.1.30.21, etc.)

Note: If OT2 isn't on the Assets page, run in the POD console: ip neighbour | grep 'ge8' | awk '{print $1}', or list everything with arp -a.

Assets › filter your site → find OT2's DHCP 10.1.30.x address.
  • Validate OT2's IP and subnet mask with ifconfig — note the /32 (255.255.255.255) netmask.
ifconfig — OT2 has a /32 netmask, the basis for host-level microsegmentation.
  • In Skytap, open OT1 (VLAN30).
  • Ping the secondary OT endpoint (10.1.30.x) — by default the packets succeed, confirming east-west connectivity.
Open OT1 (VLAN30).
Default: OT1 → OT2 ping succeeds.
  • Go to Infrastructure › Connectors › Edge › Zero Trust Branch › Sites and select POD##-Student-Lab.
  • Select Policies [1] › Configure [2], then Add Policy.
Open your POD site.
Policies › Configure.
Add Policy.
  • Action: Reject [1]
  • Name: POD##-Block-OT1-to-OT2-Traffic [2]
  • Source Zone: LAN_ZONE | LAN Zone [3] · Destination Zone: LAN_ZONE | LAN Zone [4]
  • Source: Network › Subnet/Host [5] › 10.1.30.10/24 [6] › Add [7]
  • Destination: Network › Subnet/Host [8] › 10.1.30.20/24 [9] › Add [10] (use OT2's actual IP from 4.1)
  • Ports: All [11] › click Add [12] to save.
Reject rule: OT1 (10.1.30.10) → OT2 (10.1.30.20), all ports.
  • Click Commit to apply.
  • Confirm the Hit Count initialises to 0.
Commit the policy changes.
Hit Count resets to 0.
  • In Skytap, select OT1 (VLAN30).
  • From the terminal, ping 10.1.30.20 (OT2) — you'll observe packet loss: the Reject rule is working.
  • Confirm the policy Hit Count increased from 0.
Open OT1 (VLAN30).
OT1 → OT2 ping now fails — microsegmentation blocks same-VLAN traffic.
Hit Count climbs on the Reject rule, confirming the match.

Done: Host-to-host microsegmentation verified within VLAN30. Next, configure DNS Policies.

🧠
MENTAL NOTE
Microsegmentation = control traffic within a VLAN (host-to-host), vs macro = between VLANs. Each OT host gets a /32 so its flows route through the ZT800 and hit policy. Find OT2's DHCP IP via Assets or ip neighbour | grep 'ge8' / arp -a. Rule action Reject actively refuses (vs Drop which silently discards). Same Commit → Hit-Count-0 → validate flow as Lab 2.
