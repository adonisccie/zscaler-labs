Lab 1: Deploy the HA Branch Site

CORE LAB

ZTB gateways run as an Active/Standby pair using VRRP: the Active unit carries all branch traffic, and the Standby takes over within seconds if the Active unit fails.

Scenario: The branch needs two gateways for high availability, two internet links, three LAN segments with DHCP, and access to private applications through ZPA. A provisioning template, vm-ha-edu280, has already been prepared for you.

In this lab you will:

  • Create the site from the vm-ha-edu280 template.
  • Activate both gateways from their consoles and verify them with the Appliance Admin Console.
  • Apply site settings: debug logs, NAT, HA, DNS and DHCP.
  • Connect a ZPA App Connector to the site.
  • Add the three LAN VLANs and the second WAN link on both gateways.

Success criteria — tick when done

  • ☐ ZTB-1 Active, ZTB-2 Standby; show version reports 8.1.2.
  • ☐ NAT, HA on ge4, DNS and DHCP Server set.
  • ☐ App Connector pod##StudentAppC Connected.
  • ☐ Subnet10, Subnet20, Subnet30 and both GE2 links enabled.

Watch out for

  • ⚠ Activation fails — run show configuration and compare the IP and gateway with the table.
  • ⚠ Admin Console login fails — use the password you set at first login, not a!rg@p.
  • ⚠ GE2 address not shown — wait a few minutes, refresh, and check the WAN Zone filter.

💭 THINK FIRST · DEPLOY THE HA BRANCH SITE

You are about to give two gateways a WAN address and an activation code. Think about what must exist locally and what can safely come from the cloud.

  • Why does a new gateway need only a WAN IP, a default gateway and DNS before activation? Where does the rest of its configuration come from?
    Q1 — MODEL ANSWER
    To reach the Zscaler cloud it needs a routable address, a way out (default gateway) and a way to resolve names (DNS). Once activated it downloads VLANs, policies, HA and software from the cloud, so nothing else has to be typed locally. This is also why a wrong IP or gateway is costly — the gateway cannot reach Zscaler and you need console access again.
  • Why is the HA link moved to its own interface (ge4) instead of staying on the WAN?
    Q2 — MODEL ANSWER
    VRRP heartbeats must keep flowing even if LAN or WAN trouble occurs. If the heartbeats are lost, each unit assumes the other is dead and both may become Active — split-brain. A dedicated HA interface protects the pair from that.
  • Why must the second WAN (GE2) be added once per gateway, while LAN VLANs are added once for the pair?
    Q3 — MODEL ANSWER
    WAN addresses belong to one appliance — each gateway has its own IP on the ISP link (10.130.1.1 and 10.130.1.2). LAN VLANs use a shared virtual IP so either unit can be the default gateway after a failover.

$config network wan ge1 static -i 10.120.1.1/24 -g 10.120.1.254 -n 1.1.1.1, 8.8.8.8

Why: A new gateway has no network settings. It needs a WAN IP address, a default gateway and DNS servers to reach and resolve the Zscaler cloud. Everything else — VLANs, policies, HA — is downloaded from the cloud after activation, so this is the only configuration you type locally.
