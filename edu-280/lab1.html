Lab 1: Zero Trust Branch Device Interface Configuration

PROVISIONING

Zero Trust Branch devices — physical or virtual — leverage the Zscaler Zero Trust Exchange (ZTE) to forward branch traffic to Zscaler services. In this lab you edit the configuration of two virtual ZTB devices through Experience Center. (Physical and virtual configuration is identical.)

You'll complete the Zero Trust Branch Provisioning Template:

  • Templates — the default template is cloned as vm-ha-edu280 for all sites
  • Sites — onboard the Active and Standby units
  • Device Details — System Settings, WAN DNS, App Connector; configure the GE2 WAN interface and the GE6/GE7/GE8 LAN interfaces
  • App Connector — partially pre-provisioned; a key already exists for your POD

LAB PROGRESS
QUICK REFERENCE ▲
Site
Experience Center object for your branch (POD##-Student-Lab) — holds the ZTB devices, interfaces, and policy.
Template (vm-ha-edu280)
Cloned provisioning template applied to all sites; defines the HA VM device layout.
Activation Code
Per-device code (Envelope icon) pasted into the ZTB console to activate the Airgap Gateway.
Active / Standby
ZTB-1 forwards traffic; ZTB-2 waits to take over. Status goes Post-update → Active/Standby (~15 min).
VRRP (ge4)
Virtual Router Redundancy on the HA interface — lets the standby assume the gateway IP on failover.
GE1 / GE2 (WAN)
The two DIA WAN uplinks, both using DHCP for IP and nameservers.
GE6 / GE7 / GE8 (LAN)
LAN ports mapped to VLAN10 / VLAN20 / VLAN30 respectively.
VLAN IPs
10.1.10.1 (VLAN10), 10.1.20.1 (VLAN20), 10.1.30.1 (VLAN30) — each /24, on-box DHCP .20–.30.
NAT
Enabled at the site so LAN subnets egress to the Internet via the WAN uplinks.
App Connector Key
Pre-created provisioning key for your POD; pasted when adding pod##StudentAppC under Settings › ZPA.
IPSec Tunnel
ZIA forwarding tunnel from the branch; must show Established/Up under ZIA › IPSec Tunnels.
arp -a
Console command to confirm the configured interfaces are live on the device.
