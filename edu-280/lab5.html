Configure DNS Policies

Control resolution itself: build a DNS Override that redirects google.com from VLAN30 to 8.8.8.8, and a DNS Reject that blocks *.whatsapp.com from VLAN20 — proving both before and after with ping, nslookup, and the browser.

Lab 5: Configure DNS Policies

DNS SECURITY

In a Zero Trust architecture, DNS policies give fine-grained control over how requests to specific domains are handled — redirecting traffic for enforcement/monitoring, blocking risky domains, and reducing the attack surface by restricting resolution per user group, subnet, and zone.

You'll perform two tasks:

  • Redirect Google traffic from 10.1.30.0/24 to override IP 8.8.8.8 (DNS Override)
  • Block WhatsApp from 10.1.20.0/24 with error code 5 – Query Refused (DNS Reject)

Platform: Skytap + Zscaler Experience Center

5.1.1 · Validate before configuring

  • In Skytap, open the Ubuntu host OT1, and from the terminal confirm google.com resolves normally (ping returns Google's default IPs).
Open OT1 (VLAN30).
Baseline: ping google.com resolves to Google's default IPs.

5.1.2 · Create the Google domain object

  • Navigate to Policies [1] › Access Control › Segmentation › Zero Trust Branch › Objects & Groups [2]. Click Add [3] › Domains [4].
Objects & Groups › Add › Domains.
  • Rule Name: POD##-Google [1]
  • Domains: google.com [2] › Add [3]
  • Click Add [4] to save the object.
Create the POD##-Google domain object for google.com.

5.1.3 · Configure the Override DNS policy

  • Go to Infrastructure › Connectors › Edge › Zero Trust Branch › Sites [1], select POD##-Student-Lab, open the DNS Policies tab [2], click Configure [3], then Add Policy.
Site › DNS Policies › Configure.
Add Policy.
  • Rule Name: POD##-Override-Google [1]
  • Sources: Subnet/Host [2] › 10.1.30.0/24 [3] › Add [4]
  • Destination Domains: POD##-Google [5]
  • Action: Override [6] · Override IP: 8.8.8.8 [7]
  • Click Add [8], then Commit to enforce.
Override rule: source 10.1.30.0/24 → Google object → Override IP 8.8.8.8.
Commit to activate the policy.

5.1.4 · Validate after

  • In Skytap, reopen OT1 and run ping google.com. It now resolves to 8.8.8.8 instead of Google's default IPs — the redirection works.
Reopen OT1.
google.com now resolves to the overridden 8.8.8.8.

5.2.1 · Validate before configuring

  • In Skytap, open the Ubuntu host IoT (VLAN20).
  • Confirm web.whatsapp.com resolves: nslookup web.whatsapp.com or ping web.whatsapp.com.
  • In a browser on the same machine, load web.whatsapp.com — the login page appears.
Open the IoT host (VLAN20).
Baseline: web.whatsapp.com resolves to a valid IP.
The WhatsApp login page loads successfully.

5.2.2 · Create the WhatsApp domain object

  • Navigate to Policies [1] › Access Control › Segmentation › Zero Trust Branch › Objects & Groups [2]. Click Add [3] › Domains [4].
Objects & Groups › Add › Domains.
  • Rule Name: POD##-Whatsapp [1]
  • Domains: *.whatsapp.com [2] › Add [3] (wildcard covers all subdomains)
  • Click Add [4] to save.
Wildcard object *.whatsapp.com blocks the whole domain family.

5.2.3 · Configure the Reject DNS policy

  • Go to Infrastructure › … › Sites [1], select POD##-Student-Lab, open DNS Policies [2], click Configure [3], then Add Policy.
Site › DNS Policies › Configure.
Add Policy.
  • Rule Name: POD##-Block-Whatsapp [1]
  • Sources: Subnet/Host [2] › 10.1.20.0/24 [3] › Add [4]
  • Destination Domains: POD##-Whatsapp [5]
  • Action: Reject [6] · Error Code: 5 – Query Refused [7]
  • Click Add [8], then Commit to enforce.
Reject rule: source 10.1.20.0/24 → WhatsApp object → error 5 (Query Refused).
Commit to activate the policy.

5.2.4 · Validate after

  • Reopen the IoT VM and run ping web.whatsapp.com — resolution fails (e.g. Name or service not known).
  • In a browser on the VLAN20 machine, load web.whatsapp.com — it shows This site can't be reached.
Reopen the IoT host (VLAN20).
Resolution now fails — DNS Reject in effect.
Browser: This site can't be reached — the DNS block works.

Done: DNS Override and Reject both verified — selective, name-based Zero Trust control. Next, validate all the policies end-to-end.

🧠
MENTAL NOTE
DNS policy acts on name resolution, not IP/port. Override = redirect a domain to a chosen IP (google.com → 8.8.8.8 from VLAN30). Reject = fail the lookup with an error code (5 – Query Refused) for *.whatsapp.com from VLAN20. Two-step build: create a Domain object (Objects & Groups › Domains) then a DNS Policy (Site › DNS Policies). Use *. wildcards to catch all subdomains. Validate with ping/nslookup + browser, before and after.

QUICK REFERENCE ▲
DNS Policy
Rule controlling how a branch resolves specific domains — by source subnet, zone, and destination domain object.
Domain Object
Named list of domains (Objects & Groups › Domains) referenced as the Destination in a DNS policy.
Action: Override
Redirects a domain to a specified Override IP (e.g. google.com → 8.8.8.8).
Action: Reject
Fails resolution with a DNS error code (5 – Query Refused), blocking access.
Override IP
The IP that a matched domain is forced to resolve to under an Override policy.
Error Code 5
Query Refused — the DNS response code returned by the Reject action.
*.whatsapp.com
Wildcard domain matching every subdomain, so the block can't be bypassed via an alternate host.
nslookup / ping
Client tools used to verify resolution before and after applying the policy.
Sources (subnet)
The subnet the policy applies to — 10.1.30.0/24 for Google override, 10.1.20.0/24 for WhatsApp block.
