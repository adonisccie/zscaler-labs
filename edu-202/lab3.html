LAB 3 · ZPA

ZPA Log Streaming

The ZPA Log Streaming Service (LSS) exports private-access telemetry, such as user activity, to any syslog-based SIEM. In this lab you deploy a dedicated Log Streaming Connector, configure a Log Receiver pointing at the SIEM server, and verify that user activity logs arrive in real time.

Lab 3: ZPA Log Streaming

LAB 3

Scenario: You're an IT Engineer tasked with centralising security monitoring by streaming private application access logs to an on-premises security information and event management (SIEM) system. Because the SIEM consumes syslog data from local hosts, you provision a dedicated App Connector and configure the Log Streaming Service (LSS) to send real-time user activity events to a local syslog server.

  • Provision a dedicated App Connector to establish a high-performance path for log traffic.
  • Configure a log receiver to define log types and the destination syslog server.
  • Enable secure SSH access to the SIEM server for administrative verification.
  • Verify the log feed by monitoring the live syslog file on the destination server.
Time: ~20 minutes
Service: Zscaler Private Access (ZPA)
Task 3.1 Provision a Dedicated App Connector for Log Streaming ▾

In this task, you create a dedicated Log Streaming App Connector by creating a Log Streaming App Connector Group.

Note: This task gives high-level instructions because you performed these steps in Lab 2. If you need detailed guidance, refer to Task 2.1 and Task 2.2.

  1. Configure the App Connector Group.
    1. In the Experience Center, type App Connector Groups in the Search menu and select the matching option.
    2. Select Add and enter Name Log Streaming. Follow the remaining steps as in Task 2.1, then select Save.
  2. Configure the App Connector.
    1. Launch the Corp Log Streaming Connector VM.
    2. Log in to the Corp Log Streaming Connector VM by selecting CON in the left side panel, using these credentials:
      • Username: admin
      • Password: Zscaler1!
    3. To view the token, type: cat /etc/issue
      cat /etc/issue on the Log Streaming Connector.
  3. Use the CLI to regenerate a new authentication token by running the following commands:
    1. Stop the ZPA Connector service: sudo systemctl stop zpa-connector
    2. Switch to root user privileges: sudo su
    3. Delete the existing OAuth token files: rm -rf /opt/zscaler/var/*
    4. Restart the ZPA Connector service to see the new OAuth token: sudo systemctl start zpa-connector
    5. View the new token: cat /etc/issue
    Regenerate the token, then read the new one from /etc/issue.
  4. Update the token in the App Connector to deploy it.
    1. In the Experience Center landing page (Corp Client PC 1), type App Connectors in the Search menu and select the matching option (Private Access > Private Infrastructure > App Connectors).
    2. Select Add, then enter:
      • Group: Log Streaming (the App Connector Group created in Step 1)
      • Enrollment Tokens: add the token generated in Step 3 (for example, DVQXP-NF69H), then select Add
      Select Save.
      Group Log Streaming, paste the token, select Add, then Save.

      Note: If the generated token is not working or has expired, repeat Step 3 to generate a new one.

    3. Confirm that the App Connector appears in the list.
      The Log Streaming connector is listed and Connected.

Task 3.2 Add a Log Receiver ▾

In this task, you create a log receiver to stream User Activity logs to the syslog server in the data center.

  1. Access the log streaming settings. In the Experience Center home page, type Log Receivers in the Search menu and select the matching option (Data Explorer > Log Streaming > Private Log Streaming).
    Log Receivers lives under Data Explorer › Log Streaming › Private Log Streaming.
  2. Configure the log receiver.
    1. Select Add on the Log Receivers page.
    2. Enter the following settings on the Log Receiver tab:
      • Name: Syslog-UserActivity
      • Domain or IP Address: siem.patraining.safemarch.com
      • TCP Port: 514
      • App Connector Groups: Log Streaming
    3. Select Next.
      Receiver: siem.patraining.safemarch.com, TCP 514, through the Log Streaming connector group.
    4. Enter the following settings on the Log Stream tab:
      • Log Type: User Activity
      • Log Template: CSV
      • Log Stream Content: leave at the default values
    5. Select Next.
      Log Type User Activity, Log Template CSV.
  3. Filter specific logs and save the receiver. You can add Policy Criteria to stream only some logs; leave it empty to stream all User Activity.
    1. On the Review page, review the configuration, then select Save.
      Review the receiver and stream, then select Save.

Task 3.3 Add SSH Access to the SIEM Server ▾

In this task, you create an application segment and access policy to allow SSH access to the SIEM server for log verification.

Note: Use the skills you practised in Lab 2 to complete this configuration.

  1. Configure an application segment for SSH access.
    1. On Corp Client PC 1, in the Experience Center home page, type Application Segments in the Search menu and select the matching option (Private Access > Private Applications).
    2. Create a segment with the following settings:
      • Name: SSH to SIEM
      • Applications: siem.patraining.safemarch.com
      • Default Port Ranges: SSH
      Name SSH to SIEM and the SIEM domain.
      Default Port Ranges SSH fills in TCP 22–22.
    3. Select Next.
    4. Segment Group: CorpApps
    5. Server Group: CorpServers
      Review: SSH to SIEM → CorpApps → CorpServers.
    6. Select Save.
  2. Configure an access policy. Select Edit Policy and create a rule that allows SSH access to the SIEM server for your user account (for example, Rule Name Allow SSH to SIEM, Rule Action Allow Access, Applications SSH to SIEM).
    The Allow SSH to SIEM rule in the Access Policy.

Task 3.4 Verify the Log Feed ▾

In this task, you monitor the syslog file on the SIEM server to verify that the Zscaler log feed is active.

  1. Sign in to Zscaler Client Connector (ZCC).
    1. On Corp Client PC 1, in the Windows taskbar (bottom-right corner), select the Show hidden icons arrow ^.
    2. Select the Zscaler Client Connector icon, then select Open Zscaler.
      System tray › Zscaler icon › Open Zscaler.
    3. On the Zscaler Client Connector login page, authenticate with the student credentials: student@<Student FQDN> and your session password.
      Zscaler Client Connector login page.
    4. Select Sign in.
    5. Verify the service entitlement access for Internet Security and Private Access.
      Client Connector shows the services as ON.
  2. Establish an SSH connection to the SIEM server.
    1. On Corp Client PC 1, open a command prompt.
    2. Connect to the SIEM server: ssh zscaler@siem.patraining.safemarch.com
    3. When prompted, enter the password: Zscaler123!
    4. If prompted, enter yes to accept the host key.
  3. Monitor the log feed.
    1. Enter the following command to view the live syslog feed: tail -f /var/log/syslog
      SSH in through ZPA, then follow the syslog file.
    2. Verify that log entries appear that include User Activity zpa-lss after the time field.
      CSV User Activity records arriving from LSS.

Note: If no entries appear, generate user activity by refreshing the HVAC application page you tested in Lab 2.

Note: Type exit in the command prompt to close the connection to the SIEM server.

QUICK REFERENCE ▲
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide uses the new navigation: open features from the Search menu.
Search menu
The search box in the Experience Center top bar. Type a feature name (e.g. App Connector Groups) and pick the result; each result shows its menu path.
Service Portal
Formerly ZIdentity. Zscaler's authentication service, reached from the Experience Center menu.
Student FQDN
Your pod's unique domain (e.g. zs000834.labtenant.com). Used in every login ID: student@, hvac@.
CloudShare
The virtual lab platform that hosts your VMs. Use Actions › Send Text or Send Password to paste into a VM.
App Connector
A lightweight VM in the data center that makes outbound-only connections to ZPA, so private apps are reachable without inbound firewall ports.
App Connector Group
A set of App Connectors that share a location and settings. Server groups point to it.
Enrollment token
The OAuth code shown by cat /etc/issue on a connector. Add it under App Connectors to enroll the connector; it expires after two hours.
Application Segment
Defines a private app (domain or IP plus ports) and how it is reached: Client Connector, Browser Access or Privileged Remote Access.
Segment / Server Group
A segment group bundles segments for policy; a server group maps segments to App Connector groups.
Browser Access
Clientless ZPA access to a web app through its External Domain, with no Client Connector or VPN.
Access Policy
ZPA rules, default deny, that allow access to segments when criteria such as Applications and Client Types match.
Log Streaming Service (LSS)
Streams ZPA logs (e.g. User Activity) through an App Connector to a syslog receiver such as a SIEM.
Log Receiver
The LSS destination: host, TCP port, App Connector group, log type and template (e.g. CSV).
Privileged Remote Access (PRA)
Clientless, browser-based RDP and SSH to servers through a privileged portal, with session recording and credential vaulting.
Privileged Portal / Console
The portal is the web page users open; each console on it is one server (protocol, host, port).
Privileged Credentials
Vaulted usernames and passwords that a credentials policy injects into a console, so users never see them.
AppProtection
Inline web-application firewall in ZPA: OWASP CRS, ThreatLabZ, WebSocket and API controls on private app traffic.
Paranoia level
How wide a net the OWASP controls cast: higher levels catch more but raise false positives.
Isolation Profile
Settings for Browser Isolation of private apps, e.g. render-only with View Office Files in Isolation.
End User Collection
A ZDX container that sets which users and devices run the probes of the applications inside it.
Web / Cloud Path probe
A Web probe times page fetches to a URL; a Cloud Path probe traces hop-by-hop latency, loss and jitter to the host.
SDC
Solutions Demo Center: a shared, read-only tenant with pre-populated data, used for the reporting and Workflow Automation labs.
