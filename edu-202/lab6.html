LAB 6 · ZPA

ZPA Zero Trust Browser

Zero Trust Browser brings browser isolation to ZPA: clientless users get a rendered-only view of private applications through a secure cloud browser, and copy, paste, upload, download and print are controlled by the isolation profile. In this lab you create a render-only profile and isolate the DVWA app for clientless users.

Lab 6: ZPA Zero Trust Browser

LAB 6

Scenario: You are an IT engineer responsible for enabling secure, browser-based access to sensitive internal web applications for users who may not be connected through Zscaler Client Connector. You use browser isolation in Zscaler Private Access (ZPA) to reduce data exposure by limiting user actions such as downloading, uploading, copying and pasting, and printing.

  • Create an Isolation Profile configured for render-only access.
  • Create an Isolation Policy that applies the profile to a specific application segment.
  • Validate that users can view content in isolation, but cannot perform restricted actions.
Time: ~20 minutes
Service: Zscaler Private Access (ZPA) — Browser Isolation
Prerequisite: DVWA application segment from Lab 5

Before you start: Before applying the isolation policy, open the DVWA application and note how copy and paste work: try pasting anything into a DVWA feature such as XSS (Stored) or SQL Injection. Also try File Upload, where you can upload any file. After you apply the policy, repeat the same actions during final testing and compare the behaviour.

Before isolation: pasting into DVWA works normally.
Task 6.1 Creating Isolation Profiles ▾

In this task, you create an isolation profile for render-only access.

  1. Create the isolation profile.
    1. In the Experience Center home page, type Isolation Profile in the Search menu and select the matching option (Zero Trust Browser > Browser Isolation Private Apps).
    2. Select + Add.
      Isolation Profile page: select Add.
    3. Configure the isolation profile: Name render_only_profile.
      General Information: render_only_profile.

      Note: Isolation profile names in ZPA cannot include special characters and cannot match names used by ZIA isolation profiles.

    4. Select Next.
    5. On the Company Settings tab, leave the default settings, then select Next.
      Company Settings: defaults.
    6. Configure the render-only settings: enable View Office Files in Isolation only.
      Security: only View Office Files in Isolation is enabled.
    7. Select Next.
    8. On the Regions page, select all regions, then select Next.
      Regions: select every isolation region.

      Note: The Regions page controls which regional deployments the profile applies to.

    9. On the Isolation Banner page, leave the default settings. Optionally add watermarks, then select Next.
      Isolation Experience and banner: defaults.
  2. Review your profile settings, then select Save.
    Review, then Save.
  3. Confirm that the render_only_profile isolation profile appears in the profiles list.

Task 6.2 Creating Isolation Policies ▾

In this task, you create an isolation policy so the DVWA application can be viewed only in the isolated browser. Users cannot upload or download files, copy or paste data, or print.

  1. In the console's left navigation bar, go to Isolation Policy (Zero Trust Browser > Browser Isolation Private Apps > Isolation Policy).
    1. Select + Add Rule to create a new policy.
      Isolation Policy: select Add Rule.
  2. Configure the isolation policy:
    1. Policy name: isolate_policy_render_only
    2. Under Isolation Profile, select render_only_profile.
    3. Add criteria for the DVWA application segment:
      • Select + Add Criteria, then select Applications.
      • Under Application Segments, select your DVWA segment.
    4. Select Add Rule.
      Rule isolate_policy_render_only: isolate DVWA with render_only_profile. The screenshot also shows the Web Browser client type.
    5. Confirm that the isolate_policy_render_only policy is created and includes the DVWA application segment in its criteria.

Task 6.3 Testing and Verifying ▾

Now that you have a policy that isolates DVWA, verify that it works. To simulate a third-party user, disconnect from Zscaler Client Connector, then browse to the protected application.

  1. Disconnect from Zscaler Client Connector.
    1. Open the DVWA application in a new browser tab using its External Domain.
    2. To copy the External Domain from the console:
      • Type Browser Access in the Search menu and select the matching option (Zero Trust Browser > Web Access).
      • Copy the External Domain of dvwa-XYZ.patraining.safemarch.com, then paste it into a browser address bar.
      Copy the DVWA External Domain.
  2. Authenticate to the application. If prompted, sign in to your SAML IdP. This may be transparent if you already have an active session.
  3. Validate render-only behaviour.
    1. Sign in to the DVWA application (admin / password).
    2. Attempt to manipulate files or data.
      DVWA now opens in an isolated session; note the isolation banner.
    3. Confirm that you can open and view content in the isolated browser, but you cannot download, upload, copy, paste or print.
      File Upload finds nothing to upload: the endpoint's files are out of reach.

QUICK REFERENCE ▲
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide uses the new navigation: open features from the Search menu.
Search menu
The search box in the Experience Center top bar. Type a feature name (e.g. App Connector Groups) and pick the result; each result shows its menu path.
Service Portal
Formerly ZIdentity. Zscaler's authentication service, reached from the Experience Center menu.
Student FQDN
Your pod's unique domain (e.g. zs000834.labtenant.com). Used in every login ID: student@, hvac@.
CloudShare
The virtual lab platform that hosts your VMs. Use Actions › Send Text or Send Password to paste into a VM.
App Connector
A lightweight VM in the data center that makes outbound-only connections to ZPA, so private apps are reachable without inbound firewall ports.
App Connector Group
A set of App Connectors that share a location and settings. Server groups point to it.
Enrollment token
The OAuth code shown by cat /etc/issue on a connector. Add it under App Connectors to enroll the connector; it expires after two hours.
Application Segment
Defines a private app (domain or IP plus ports) and how it is reached: Client Connector, Browser Access or Privileged Remote Access.
Segment / Server Group
A segment group bundles segments for policy; a server group maps segments to App Connector groups.
Browser Access
Clientless ZPA access to a web app through its External Domain, with no Client Connector or VPN.
Access Policy
ZPA rules, default deny, that allow access to segments when criteria such as Applications and Client Types match.
Log Streaming Service (LSS)
Streams ZPA logs (e.g. User Activity) through an App Connector to a syslog receiver such as a SIEM.
Log Receiver
The LSS destination: host, TCP port, App Connector group, log type and template (e.g. CSV).
Privileged Remote Access (PRA)
Clientless, browser-based RDP and SSH to servers through a privileged portal, with session recording and credential vaulting.
Privileged Portal / Console
The portal is the web page users open; each console on it is one server (protocol, host, port).
Privileged Credentials
Vaulted usernames and passwords that a credentials policy injects into a console, so users never see them.
AppProtection
Inline web-application firewall in ZPA: OWASP CRS, ThreatLabZ, WebSocket and API controls on private app traffic.
Paranoia level
How wide a net the OWASP controls cast: higher levels catch more but raise false positives.
Isolation Profile
Settings for Browser Isolation of private apps, e.g. render-only with View Office Files in Isolation.
End User Collection
A ZDX container that sets which users and devices run the probes of the applications inside it.
Web / Cloud Path probe
A Web probe times page fetches to a URL; a Cloud Path probe traces hop-by-hop latency, loss and jitter to the host.
SDC
Solutions Demo Center: a shared, read-only tenant with pre-populated data, used for the reporting and Workflow Automation labs.
