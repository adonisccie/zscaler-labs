Lab 10: Analyze Data and View Integrated Reports

LAB 10

Scenario: You need to review Zscaler Digital Experience (ZDX) data to understand application and network performance, and to communicate trends to stakeholders. In this lab, you use Data Explorer, Quarterly Business Review (QBR) reports, system-generated reports, and ZDX Snapshots to analyse user experience and share findings.

  • Analyse user experience and performance data using Data Explorer.
  • Download and review QBR reports for trend insights.
  • Review system-generated reports and create ZDX Snapshots to share view-only findings.
Time: ~15 minutes
Service: Zscaler Digital Experience (ZDX)
Environment: Solutions Demo Center (SDC)

Solutions Demo Center labs: The hands-on labs so far were read-write. This lab and the next run in read-only mode on the Solutions Demo Center (SDC) because of technical dependencies, such as report generation timelines (which can take 24 hours or more) and restricted student access to some integrated services. They expose you to key features and real-world dashboards for data analysis, integrated reports and snapshots, and incident management with Zscaler Workflow Automation (ZWA).

Task 10.1 Analyze Application and Network Performance in Data Explorer ▾

In this task, you use Data Explorer to build and run custom views that analyse application and network performance and track user experience.

  1. On Corp Client PC 1, open a browser and go to the Zscaler Experience Center. To open Data Explorer, type Data Explorer in the Search menu and select the matching option (Digital Experience > Reports).
    Data Explorer lists the configured views.

    Verify: You can see a list of configured views and their details.

  2. Create and run a query.
    1. Select View to organise customised views of applications and metrics.
      Open a view with its View icon.
    2. In the left panel, configure the options you want to include, such as Data Source, Probes, Metrics, Filters, Operations, View Type or Overlays.
    3. Select Run Query.
      The query panel (left) and the resulting charts.

      Verify: You can view graphs that display individual charts for the selected applications and metrics.

  3. Explore chart details. Select and drag to zoom in on a specific area of a chart.
    Drag across a chart to zoom into that time range.

    Verify: You can view details for the zoomed time range.

Task 10.2 View QBR Reports for Insight into ZDX Users ▾

In this task, you download and review QBR reports for trend insights.

  1. Open the QBR reports list. In the left navigation bar, select ZDX QBR Reports.
    One QBR file per covered quarter.

    Verify: You see a list of reports for the covered time periods.

  2. Download and review a report.
    1. Select the Download icon for the report you want to view.
      The report downloads as a PowerPoint file.
    2. Open the downloaded QBR PowerPoint file and review the details.
      The Quarterly Digital Experience Review deck.

      Verify: You can open the file and view the report content.

    Note: A new QBR report is generated on the first weekend of every month, and each report is stored securely as a PowerPoint file in the Zscaler cloud.

Task 10.3 View System Integrated Reports and Generate Snapshots ▾

In this task, you review system-generated reports and create ZDX Snapshots to share view-only findings.

  1. Open the system-generated reports. In the left navigation bar, go to Predefined Reports.
    Predefined Reports.

    Verify: You see a list of reports.

  2. Open and interact with a report.
    1. Select the View icon for the report you want to analyse.
      View Cloud Path: End-to-End.
    2. For Cloud Path End-to-End, filter by Departments, Zscaler Locations, Geolocations or Applications.
      The report filters and the average end-to-end latency per location.
    3. Select a point in the graph to display a tooltip with latency metrics for the selected locations.
    4. Drag from left to right to select a time range.
    5. Select Zoom Out to reset the graph to the original view.

    Verify: The graph updates based on your selections.

    Note: Up to 20 device locations are displayed at a time in the legend on the right of the graph, based on user device information.

  3. Create and share a ZDX Snapshot.
    1. In the left navigation bar, select ZDX Snapshots.
    2. Select the Copy icon for an active snapshot.
      Copy the link of an Active snapshot.
    3. Paste the copied link into a new browser window.
    4. Verify that the page shows a green icon in the upper-left corner, indicating that you are viewing a ZDX Snapshot.
      The green icon (upper left) marks a snapshot view.
  4. Users can identify a ZDX Snapshot by the green icon in the upper-left corner of the page. A ZDX Snapshot captures the current state of a UI page and provides a URL that admins can share with ZDX users or other admins for view-only access. A snapshot allows limited interaction, depending on what data is obfuscated and which details are shared. For example, in a snapshot of the user details page, these features are disabled by default:
    • Time range filter
    • Drop-down menu filters
    • Device selection
    • Applications other than the one already selected
    • Root-cause-analysis data points other than the one already selected
    • Web Probe Metrics
    • Cloud Path

QUICK REFERENCE ▲
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide uses the new navigation: open features from the Search menu.
Search menu
The search box in the Experience Center top bar. Type a feature name (e.g. App Connector Groups) and pick the result; each result shows its menu path.
Service Portal
Formerly ZIdentity. Zscaler's authentication service, reached from the Experience Center menu.
Student FQDN
Your pod's unique domain (e.g. zs000834.labtenant.com). Used in every login ID: student@, hvac@.
CloudShare
The virtual lab platform that hosts your VMs. Use Actions › Send Text or Send Password to paste into a VM.
App Connector
A lightweight VM in the data center that makes outbound-only connections to ZPA, so private apps are reachable without inbound firewall ports.
App Connector Group
A set of App Connectors that share a location and settings. Server groups point to it.
Enrollment token
The OAuth code shown by cat /etc/issue on a connector. Add it under App Connectors to enroll the connector; it expires after two hours.
Application Segment
Defines a private app (domain or IP plus ports) and how it is reached: Client Connector, Browser Access or Privileged Remote Access.
Segment / Server Group
A segment group bundles segments for policy; a server group maps segments to App Connector groups.
Browser Access
Clientless ZPA access to a web app through its External Domain, with no Client Connector or VPN.
Access Policy
ZPA rules, default deny, that allow access to segments when criteria such as Applications and Client Types match.
Log Streaming Service (LSS)
Streams ZPA logs (e.g. User Activity) through an App Connector to a syslog receiver such as a SIEM.
Log Receiver
The LSS destination: host, TCP port, App Connector group, log type and template (e.g. CSV).
Privileged Remote Access (PRA)
Clientless, browser-based RDP and SSH to servers through a privileged portal, with session recording and credential vaulting.
Privileged Portal / Console
The portal is the web page users open; each console on it is one server (protocol, host, port).
Privileged Credentials
Vaulted usernames and passwords that a credentials policy injects into a console, so users never see them.
AppProtection
Inline web-application firewall in ZPA: OWASP CRS, ThreatLabZ, WebSocket and API controls on private app traffic.
Paranoia level
How wide a net the OWASP controls cast: higher levels catch more but raise false positives.
Isolation Profile
Settings for Browser Isolation of private apps, e.g. render-only with View Office Files in Isolation.
End User Collection
A ZDX container that sets which users and devices run the probes of the applications inside it.
Web / Cloud Path probe
A Web probe times page fetches to a URL; a Cloud Path probe traces hop-by-hop latency, loss and jitter to the host.
SDC
Solutions Demo Center: a shared, read-only tenant with pre-populated data, used for the reporting and Workflow Automation labs.
