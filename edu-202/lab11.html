Lab 11: Manage Incidents with Zscaler Workflow Automation

LAB 11

Scenario: You explore the tools in the Zscaler Workflow Automation (ZWA) portal to manage data protection incidents and automate related workflows. You become familiar with changing incident statuses, escalating incidents, and notifying end users to improve security posture and response times.

  • Change the status and priority of data protection incidents.
  • Escalate incidents to the appropriate stakeholders for review.
  • Notify end users by email to provide coaching or request justification.
  • Identify incident metadata, trigger data and violation content.
  • View and understand automated workflow templates and mappings.
Time: ~20 minutes
Service: Zscaler Workflow Automation (ZWA)
Environment: Solutions Demo Center (SDC)

SDC: This lab runs on the read-only Solutions Demo Center tenant. Sign in at console.zscaler.com with the SDC credentials from the CloudShare Credentials tab (see Lab 10).

Task 11.1 Enroll with Zscaler Client Connector ▾

In this task, you enroll Corp Client PC 1 as a user in the Solutions Demo Center (SDC) organisation.

  1. Log out of Zscaler Client Connector.
    1. On Corp Client PC 1, open Zscaler Client Connector.
    2. Select Log Out.
      Client Connector › Logout.
  2. Log in with the IT department credentials.
    1. Use the SDC credentials provided for the IT department (CloudShare Credentials › SDC Credentials › IT Username).
    2. Enter the IT_department_username.
    3. Select Login.
    4. At the IdP authentication prompt:
      • Enter the IT_department_username (if it isn't pre-filled), then select Next.
      • Enter the Session_Password, then select Sign in.
    Enrolled: Service Status ON, Network Type Off-Trusted Network.

    Verify: Check the connection status. After a few minutes, confirm that the Internet Security Service Status shows ON and the Network Type shows Off-Trusted Network.

    Note: Zscaler Client Connector may minimise to the taskbar and take a few minutes to initialise and finish enrolling all services.

Task 11.2 View Current DLP Incidents ▾

In this task, you use the Experience Center to view the incident list and examine specific incident details.

  1. Access the Experience Center.
    1. Log in with your SDC credentials.
    2. In the Experience Center home page, type Incidents in the Search menu and select the matching option (Data Security > Workflow Automation).
      Data Security › Workflow Automation › Incidents.
  2. Review the incident details.
    1. From the Incidents list, open the first incident by selecting its Transaction ID.
    2. Review the metadata in the Overview and Violation Details sections.
      Incident Details: Overview and Violation Details.
  3. Examine the trigger data.
    1. Scroll to the Violation Content card.
    2. Expand View Trigger Data to see the content that triggered the DLP violation.
      Violation Content › View Trigger Data: the matches are highlighted in context.

    Verify: Confirm that you can view the incident metadata and the trigger data for the selected incident.

Task 11.3 Modify Incident Metadata ▾

In this task, you update an incident to show that it is under investigation and assign it a priority level.

  1. Update the incident status.
    1. On the Incident Details page, open the Actions menu.
    2. Set the status to Investigating.
    3. In the Note field, enter Test.
      Actions menu: Investigating (and Assign Priority, next).
  2. Update the priority.
    1. Select Assign Priority.
    2. Change the priority to High (if it isn't already set).
      Assign Priority: High.

    Verify: Refresh your browser. Confirm that the Status and Priority fields reflect your changes, then scroll to State Changes to see the history entries.

    State Changes record each update with who made it and when.

Task 11.4 Test User Notification and Escalation Workflows ▾

In this task, you notify a user to request justification, then escalate an incident to an approver.

  1. Notify the end user.
    1. On the Incident Details page, open the Actions menu, then select Notify User.
      Actions › Notify User.
    2. In the Notify User settings:
      • Select a Language and Time Zone.
      • In the Note to user field, enter: Please justify uploading this document for testing purposes of HandsOnLab
      • Select Submit.
      Language, time zone and the note to the user, then Submit.

      Note: In a live environment, the originator receives an email notification similar to the sample below.

      Sample incident notification email: the user responds through Click Here.
  2. Verify the incident state. On the Incident Details page, review State Changes to confirm that the notification was sent.
    The notification moved the incident to Validating with User.

    Note: You can proceed to the next step if the originator doesn't provide a justification during your lab session.

  3. Configure an approver for escalation.
    1. In the Experience Center home page, type Approvers in the Search menu and select the matching option (Administration > Workflow Automation User Management).
    2. Select Add more (+).
    3. Enter your name and email address.
    4. Select Save.
      Add yourself as an approver, then Save.
  4. Escalate the incident.
    1. Return to the Incidents list (Data Security > Workflow Automation), then open the Actions menu for the Transaction ID you modified earlier.
    2. Select Escalate.
      Actions › Escalate.

      Note: Integration with SAML or SCIM lets the portal populate the approver list from your organisational directory.

    3. From the Select Approver drop-down list, choose your ID, then select Submit.
      Pick yourself as the approver and add a note.
  5. Approve the escalation from email.
    1. Open your personal email account and find the DLP Incident Notification email (check your spam folder if necessary).
    2. Select the Click here link in the email.
    3. Select Approved in the Justification Type field, enter a reason, then select Submit.
      Justification Type Approved, a reason, then Submit.

    Verify: Confirm that the notification and escalation actions appear in the incident's State Changes history.

Task 11.5 Configure Automated Workflows ▾

In this task, you explore how workflow templates and mappings automate incident management actions.

  1. View workflow templates.
    1. In the Experience Center, type Workflow Templates in the Search menu and select the matching option (Administration > Workflow Automation > Workflows).
    2. In the Auto Escalate row, select the View Workflow Template icon in the Action column.
      Workflow Templates › Auto Escalate › View.

      Note: The flow diagram shows the logic, such as automatically notifying a manager when an incident is created.

      Auto Escalate: find the user's manager, else fall back to an approver.
  2. Explore workflow mappings.
    1. In the left navigation bar, select Workflow Mappings.
      Workflow Mappings.
    2. Expand the first mapping to see its triggering attributes and conditions.
      Each mapping is a set of predicates (NOT / OR / AND) on incident attributes.

      Note: A workflow triggers only if an incident matches the criteria defined in its mapping.

    3. Explore the available attributes and logic constructs. Because you have read-only credentials, you cannot save changes.
    4. Select Reset when you have finished exploring.

    Verify: Confirm that you can view the workflow template logic and the workflow mapping conditions.

QUICK REFERENCE ▲
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide uses the new navigation: open features from the Search menu.
Search menu
The search box in the Experience Center top bar. Type a feature name (e.g. App Connector Groups) and pick the result; each result shows its menu path.
Service Portal
Formerly ZIdentity. Zscaler's authentication service, reached from the Experience Center menu.
Student FQDN
Your pod's unique domain (e.g. zs000834.labtenant.com). Used in every login ID: student@, hvac@.
CloudShare
The virtual lab platform that hosts your VMs. Use Actions › Send Text or Send Password to paste into a VM.
App Connector
A lightweight VM in the data center that makes outbound-only connections to ZPA, so private apps are reachable without inbound firewall ports.
App Connector Group
A set of App Connectors that share a location and settings. Server groups point to it.
Enrollment token
The OAuth code shown by cat /etc/issue on a connector. Add it under App Connectors to enroll the connector; it expires after two hours.
Application Segment
Defines a private app (domain or IP plus ports) and how it is reached: Client Connector, Browser Access or Privileged Remote Access.
Segment / Server Group
A segment group bundles segments for policy; a server group maps segments to App Connector groups.
Browser Access
Clientless ZPA access to a web app through its External Domain, with no Client Connector or VPN.
Access Policy
ZPA rules, default deny, that allow access to segments when criteria such as Applications and Client Types match.
Log Streaming Service (LSS)
Streams ZPA logs (e.g. User Activity) through an App Connector to a syslog receiver such as a SIEM.
Log Receiver
The LSS destination: host, TCP port, App Connector group, log type and template (e.g. CSV).
Privileged Remote Access (PRA)
Clientless, browser-based RDP and SSH to servers through a privileged portal, with session recording and credential vaulting.
Privileged Portal / Console
The portal is the web page users open; each console on it is one server (protocol, host, port).
Privileged Credentials
Vaulted usernames and passwords that a credentials policy injects into a console, so users never see them.
AppProtection
Inline web-application firewall in ZPA: OWASP CRS, ThreatLabZ, WebSocket and API controls on private app traffic.
Paranoia level
How wide a net the OWASP controls cast: higher levels catch more but raise false positives.
Isolation Profile
Settings for Browser Isolation of private apps, e.g. render-only with View Office Files in Isolation.
End User Collection
A ZDX container that sets which users and devices run the probes of the applications inside it.
Web / Cloud Path probe
A Web probe times page fetches to a URL; a Cloud Path probe traces hop-by-hop latency, loss and jitter to the host.
SDC
Solutions Demo Center: a shared, read-only tenant with pre-populated data, used for the reporting and Workflow Automation labs.
