LAB 4 · ZIA

ZIA Browser Isolation

Browser Isolation renders risky web content — social networking sites, unknown categories, uncategorised URLs — inside a remote Zscaler container, so no active content ever touches the endpoint. In this lab you build an Isolation Profile, enforce it via URL Filtering, and verify that browsing social sites shows the isolation watermark.

Lab 4: ZIA Browser Isolation

LAB 4

Scenario: Your organization needs to let users access social networking sites while reducing risk from downloads, uploads, and data exfiltration. You configure Zero Trust Browser (Browser Isolation) so sites are rendered in an isolated session and users can view content without being able to copy, paste, or transfer files. You also validate how isolation behaves when applied through URL Filtering and Cloud App Control policies.

Time: ~20 minutes
Service: Zscaler Internet Access (ZIA)
Task 4.1 Build Isolation Profile ▾

In this task, you build an Isolation Profile that defines how users interact with an isolation session. The profile lets users view and interact with content, but prevents them from downloading, uploading, copying, or pasting content.

  1. Go to the Browser Isolation Threat profiles page. In the Experience Center portal, go to Policies > Common Configuration > Resources > Browser Isolation Threat.
  2. Add an isolation profile. Select Add Isolation Profile.
  3. Configure the profile under General.
    • Name: isolate_profile-social_networking-internet
    • Description: Isolate Social Networking Sites to view only
    • Leave all other settings at their default values.
    Select Next.
  4. Review Company Settings. Leave all settings at their default values, then select Next.
  5. Configure Security. Enable Original URL. (This configuration restricts users to the original URL by disabling features such as copy, paste, and file transfer.) Leave all other settings at their default values, then select Next.
  6. Configure Regions. Under Regions, select Isolation Regions — any two regions closer to the user — then select Next.
  7. Configure Isolation Experience and save.
    1. Under Isolation Experience, enable Watermarking, and then select your preferred Date & Timestamp.
    2. Leave all other settings at their default values, then select Next.
    3. Review the isolation profile and select Save.

Task 4.2 Implement Isolation Policy ▾

In this task, you add a URL Filtering rule that directs users to Browser Isolation when they browse to a set of URL categories, so you can test the end-user experience.

  1. In the portal, go to Policies > Access Control > Internet & SaaS > URL Control > URL Filtering. On the URL Filtering Policy tab, select Add URL Filtering Rule.
  2. Configure the URL Filtering rule by setting the following values:
    1. Rule Order: 1
    2. Rule Name: isolate-outbound-socialsite
    3. URL Categories: Social Networking, Social Networking Adult
    4. Under Criteria, set:
      • Protocols: HTTP, HTTPS
      • User Agent: Chrome, Firefox, Microsoft Edge, Microsoft Internet Explorer, Safari
    5. Under Action, set:
      • Web Traffic: Isolate
      • Isolation Profile: isolate_profile-social_networking-internet
      Select Save.
  3. Activate the changes.
  4. Test isolation for social networking sites.
    1. Open your Zscaler Client Connector and verify that you are logged in to it.
    2. Open each of the following sites and confirm they open in isolation: x.com, instagram.com, linkedin.com, facebook.com
    3. Verify that each site opens in an isolated session. (Open Incognito Mode for it.) If you cannot see the watermarks, you can check the changed isolation URL instead.

Task 4.3 Add Cloud App Isolate Control Policies ▾

In this task, you create a Cloud App Control policy rule to allow LinkedIn while URL Filtering continues to isolate other social networking sites. Then you activate the changes and verify that linkedin.com is allowed (not isolated) and that other social networking sites still open in isolation.

  1. Go to the SaaS Application Control policies page. In the portal, go to Policies > Access Control > Internet & SaaS > SaaS Application Control > Cloud App Control.
  2. Add a Social Networking policy rule. Select the Add drop-down and select Social Networking.
  3. Configure the Cloud App Control rule.
    1. Enter the following settings:
      • Rule Order: 1
      • Rule Name: allow-outbound-linkedin-any
      • Cloud Application: LinkedIn
    2. Under Action, set:
      • Viewing: Allow
      • Description: Not isolating the LinkedIn Social Networking Site
    3. Select Save.
  4. Activate the changes.
  5. Verify the behavior.
    1. Open linkedin.com and confirm it is allowed (not isolated).
    2. Open other social networking sites and confirm they still open in isolation.
    3. Confirm that linkedin.com is not isolated, and that the other social networking sites are isolated.

Note: Cloud App Control policies take priority over URL Filtering policies, so the LinkedIn rule is matched first and LinkedIn bypasses the Isolate rule. The other Social Networking sites have no specific Cloud App Control rule and fall through to the Isolate URL Filtering rule.
