LAB 4 · ZPA

ZPA Privileged Remote Access

Privileged Remote Access (PRA) gives contractors and third-party vendors a browser-based RDP or SSH session to internal servers: no VPN, no Zscaler Client Connector, and no credentials revealed to the user. In this lab you build the full PRA stack (application segments, a privileged portal, consoles, credentials and two policies), then verify live sessions in the admin portal.

Lab 4: ZPA Privileged Remote Access

LAB 4

Scenario: You are an IT engineer tasked with enabling secure, time-limited access for third-party vendor support to troubleshoot critical Microsoft Windows and Linux servers in your organisation. These servers are inside the corporate environment and are reachable only through the Zero Trust Exchange. The organisation requires a solution that avoids VPNs and does not require external users to install Zscaler Client Connector, so access is secure and limited strictly to authorised personnel.

  • Configure a Privileged Portal and Privileged Consoles to enable clientless, browser-based access to a Linux server over SSH and a Windows server over RDP, without Client Connector or browser plugins.
  • Configure privileged application segments that restrict access to only the target Windows and Linux systems.
  • Provision privileged policies that assign access rights to specific users.
  • Configure Privileged Credentials so users connect with predefined credentials instead of their own.
  • Validate privileged remote access by opening SSH and RDP sessions through the browser-based PRA portal.
Time: ~50 minutes
Service: Zscaler Private Access (ZPA) — PRA
Task 4.1 Creating Application Segments ▾

The lab uses two application segments: one for the Windows VM and one for the Linux VM. First you create the segment for the Windows VM, Corp Win Svr 2025.

  1. Go to the Application Segments page. In the Experience Center home page, type Application Segments in the Search menu and select the matching option (Private Access > Private Applications).
  2. Add an application segment. Select Add Application Segment.
    Select Add Application Segment.
  3. Configure the application segment with the following values:
    1. Name: PRA_RDP1_win Svr
    2. Applications: 10.0.0.1 (IP address of the Win Svr)
    3. Access Type: Privileged Remote Access
    4. Protocol: RDP
    5. Port: 3389
    6. Connection Security: Any
      Name the segment PRA_RDP1_win Svr.
    7. Under Client Connector Access: Default Port Ranges RDP (3389); UDP Port Ranges 3389.
      10.0.0.1 as a Privileged Remote Access app over RDP 3389.
    8. Under Common Configuration, keep everything as it is.
      Leave Common Configuration at the defaults.
    9. Select Next.
    10. Select the segment group: Name CorpApps.
    11. Select the server group: Name CorpServers, then select Next.
    12. Review and save the configuration.
      Review: PRA_RDP1_win Svr → CorpApps → CorpServers → OnPrem.
  4. Verify the settings and select Save.
  5. Create the access policy rule for the PRA application segments.
    1. Open the Access Policy editor in one of these ways:
      • In the Add Application Segment window, select Edit Policy.
      • Type Access Policy in the Search menu and select the matching option.
      Edit Policy jumps to the Access Policy page.
    2. Select Add Rule.
    3. Configure the following settings:
      • Rule Action: Allow Access
      • Rule Name: PRA_Allow_Access
      • App Connector Selection Method: All App Connector Groups
    4. Define the criteria: select Applications and choose the PRA_RDP1_win Svr application segment.
    5. Select Add Rule.
      Rule PRA_Allow_Access: Allow Access to PRA_RDP1_win Svr through all App Connector groups.
  6. Create an application segment for the Corp Log Streaming Connector VM.

    Note: Repeat the same process to create another application segment, this time for the VM Corp Log Streaming Connector (10.0.0.20).

    1. Select Add Application Segment and configure it with these values:
      • Name: PRA_SSH2_Log_Streaming_Connector_PC
      • Applications: 10.0.0.20 (IP address of the Corp Log Streaming Connector)
      • Access Type: Privileged Remote Access
      • Protocol: SSH
      • Port: 22
    2. Under Client Connector Access: Default Port Ranges SSH (22).
    3. Under Common Configuration, keep everything as it is.
    4. Select Next.
    5. Select the segment group CorpApps, then select Next.
    6. Select the server group CorpServers, then select Next.
    7. Review the configuration.
    8. Verify the settings and select Save.
    9. Edit the access policy PRA_Allow_Access: in its criteria, add the application segment PRA_SSH2_Log_Streaming_Connector_PC.
    10. Select Save.
      PRA_Allow_Access now covers both PRA segments.

Task 4.2 Creating the Portal ▾

In this task, you create a Privileged Remote Access portal that third-party users and internal users can use to reach the systems you configured.

  1. In the Experience Center home page, type Privileged Portals in the Search menu and select the matching option (Zero Trust Browser > Clientless Portal).
    1. Select Add.
    2. Configure the following values:
      • Name: Privileged_Portal
      • Certificate Type: Managed
      • Portal URL: praportal
      • Domain Suffix: select any one from the drop-down menu
      • User Portal for Portal Links: None
    3. Select Save.
      Portal Privileged_Portal with a Managed certificate and the praportal URL.

Task 4.3 Creating the Consoles ▾

In this task, you create the consoles that appear on the portal. Consoles represent the devices that users can access.

  1. In the Experience Center home page, type Privileged Consoles in the Search menu and select the matching option (Zero Trust Browser > Privileged Remote Access). Select Add.
  2. Configure the consoles with the following values:
    1. Privileged Remote Access Portal: Privileged_Portal
    2. Privileged Remote Access Applications: select both application segments created in Task 4.1.
    3. Select Next.
      Pick the portal and both PRA applications (10.0.0.1:3389 and 10.0.0.20:22).
  3. On the Consoles tab, verify that the details for each application are correct:
    1. Protocol: SSH or RDP
    2. Port: 22 or 3389
    3. Connection Security for RDP: as set on the segment (the screenshots show Any)
    4. Select Next.
      Windows console: RDP to 10.0.0.1:3389.
      Linux console: SSH to 10.0.0.20:22.
  4. Review the details and select Save.
    Review both consoles, then select Save.
    The Linux and Windows consoles are listed and enabled.

Task 4.4 Creating Privileged Credentials ▾

Privileged Credentials let third-party users or contractors sign in to a console without entering credentials. Access to the stored credentials is controlled by a Privileged Credentials policy. In this task, you create a privileged credential for each server; in the next task, you map them to the consoles users reach through Privileged_Portal.

  1. In the Experience Center home page, type Privileged Credentials in the Search menu and select the matching option (Zero Trust Browser > Credentials Management).
    1. Select Add.
    2. Create a privileged credential for the Windows server:
      • Name: PRA_windows
      • Type: UserName-Password
      • User Name: administrator
      • Password: Admin-123!
    3. Select Save.
      Credential PRA_windows for the Windows server.
  2. Create a privileged credential for the Linux system the same way:
    • Name: PRA_Log_Streaming_Connector
    • Type: UserName-Password
    • User Name: admin
    • Password: Zscaler1!
    Both credentials are listed. The screenshots spell the Linux one PRA_Log_Streamming_Connector; any name works if you use the same one in Task 4.5.

Task 4.5 Creating Privileged Credential Policy ▾

In this task, you create credential policies that map the privileged credentials to specific consoles.

  1. Create the credential policy for RDP.
    1. In the Experience Center home page, type Credentials Policy in the Search menu and select the matching option (Zero Trust Browser > Privileged Remote Access).
    2. Select Add Rule and configure these values:
      • Name: PRA_Credential_policy_RDP
      • Privileged Credentials: PRA_windows
      • Criteria: Privileged Consoles › Windows
  2. Select Add Rule.
    PRA_Credential_policy_RDP: Windows console → PRA_windows.
  3. Create the credential policy for SSH.
    1. Repeat the same steps for the Log Streaming Connector (Linux) console:
      • Name: PRA_Credential_policy_SSH
      • Privileged Credentials: PRA_Log_Streaming_Connector
      • Criteria: Privileged Consoles › Linux
    2. Select Add Rule.
      PRA_Credential_policy_SSH: Linux console → the Log Streaming Connector credential.
      Both credential policies are in place.

Task 4.6 Create Consoles Policy ▾

In this task, you create a consoles policy for your Privileged Remote Access consoles.

  1. In the Experience Center home page, type Consoles Policy in the Search menu and select the matching option (Zero Trust Browser > Privileged Remote Access). Select Add Rule.
  2. Configure the console policy:
    1. Name: PRA_Console_Policy
    2. Under Console Configuration:
      • Clipboard Copy: Enabled
      • Record Session: Enabled
      • Join Session: Enabled
      • Share Session: Monitor Session
    3. On the Criteria tab, select Add Criteria › Applications.
    4. In Application Segments, select both application segments created in Task 4.1.
  3. Select Add Rule.
    PRA_Console_Policy: clipboard copy, session recording, monitor-style sharing and join enabled for both segments.

Task 4.7 Testing and Verifying ▾

Now that you have created the PRA components (portal and consoles), test connectivity and verify the sessions in the admin portal.

  1. Log out of Zscaler Client Connector on Corp Client PC 1.
  2. Launch the privileged portal.
    1. On the Corp Client PC 1 VM, sign in to the Experience Center console at console.zscaler.com.
    2. Type Privileged Portal in the Search menu and select the matching option (Zero Trust Browser > Clientless Portal).
    3. Select Launch to open the portal.
      Launch Privileged_Portal from its URL.
    4. If prompted, log in with your student tenant credentials (student@<Student FQDN>).
      My Consoles: Linux and Windows.
      1. Select the Windows VM (10.0.0.1) on the privileged portal and log in to the Windows system.
        An RDP session in the browser: the vaulted credential signs you in.
      2. Verify the session details in the portal: type Live Sessions in the Search menu and select the matching option (Zero Trust Browser > Privileged Remote Access), then view the active RDP session.
        Search for Live Sessions.
        The active RDP session, governed by PRA_Console_Policy.
      3. In the privileged portal, select the Linux VM (10.0.0.20).
        An SSH session in the browser to the Log Streaming Connector.
      4. After you log in to the Log Streaming Connector VM, verify the SSH session: open Live Sessions again and confirm that the active SSH session appears.
        The active SSH session appears in Live Sessions.

QUICK REFERENCE ▲
Experience Center
console.zscaler.com, the unified admin console for ZIA, ZPA, ZDX and the Service Portal. This guide uses the new navigation: open features from the Search menu.
Search menu
The search box in the Experience Center top bar. Type a feature name (e.g. App Connector Groups) and pick the result; each result shows its menu path.
Service Portal
Formerly ZIdentity. Zscaler's authentication service, reached from the Experience Center menu.
Student FQDN
Your pod's unique domain (e.g. zs000834.labtenant.com). Used in every login ID: student@, hvac@.
CloudShare
The virtual lab platform that hosts your VMs. Use Actions › Send Text or Send Password to paste into a VM.
App Connector
A lightweight VM in the data center that makes outbound-only connections to ZPA, so private apps are reachable without inbound firewall ports.
App Connector Group
A set of App Connectors that share a location and settings. Server groups point to it.
Enrollment token
The OAuth code shown by cat /etc/issue on a connector. Add it under App Connectors to enroll the connector; it expires after two hours.
Application Segment
Defines a private app (domain or IP plus ports) and how it is reached: Client Connector, Browser Access or Privileged Remote Access.
Segment / Server Group
A segment group bundles segments for policy; a server group maps segments to App Connector groups.
Browser Access
Clientless ZPA access to a web app through its External Domain, with no Client Connector or VPN.
Access Policy
ZPA rules, default deny, that allow access to segments when criteria such as Applications and Client Types match.
Log Streaming Service (LSS)
Streams ZPA logs (e.g. User Activity) through an App Connector to a syslog receiver such as a SIEM.
Log Receiver
The LSS destination: host, TCP port, App Connector group, log type and template (e.g. CSV).
Privileged Remote Access (PRA)
Clientless, browser-based RDP and SSH to servers through a privileged portal, with session recording and credential vaulting.
Privileged Portal / Console
The portal is the web page users open; each console on it is one server (protocol, host, port).
Privileged Credentials
Vaulted usernames and passwords that a credentials policy injects into a console, so users never see them.
AppProtection
Inline web-application firewall in ZPA: OWASP CRS, ThreatLabZ, WebSocket and API controls on private app traffic.
Paranoia level
How wide a net the OWASP controls cast: higher levels catch more but raise false positives.
Isolation Profile
Settings for Browser Isolation of private apps, e.g. render-only with View Office Files in Isolation.
End User Collection
A ZDX container that sets which users and devices run the probes of the applications inside it.
Web / Cloud Path probe
A Web probe times page fetches to a URL; a Cloud Path probe traces hop-by-hop latency, loss and jitter to the host.
SDC
Solutions Demo Center: a shared, read-only tenant with pre-populated data, used for the reporting and Workflow Automation labs.
