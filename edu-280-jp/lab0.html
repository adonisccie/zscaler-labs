ラボ0: ラボアクセス情報

概要

Zscaler Zero Trust Branch (EDU-280) ハンズオンラボへようこそ。このラボでは、支社拠点に高可用性 (High Availability) を備えた Zero Trust Branch (ZTB) デバイス を展開・管理します。各デバイスは最大2本の Direct Internet Access (DIA) 接続を持ちます。最初のこのラボでは、環境へのアクセス方法を学びます。完了すると、次のことができるようになります。

  • Experience Center 管理ポータル経由で割り当てられた POD を特定してアクセスする
  • Skytap ポータルにログインしてラボ VM を起動する
  • コース全体で使用する Zscaler Experience Center のナビゲーションパスにログインする
コース: EDU-280
版: 2.2 · 2026年2月
プラットフォーム: Skytap + Zscaler Experience Center

ラボの説明とシナリオ

あなたの組織には複数の支社拠点があり、各拠点には IoT および OT デバイス が存在し、WAN アップリンク経由で本社に接続されています。目標は、高可用性・セグメンテーション・負荷分散・セキュリティ を実現するよう支社ネットワークを構成し最適化することです。あなたはネットワーク管理者として、WAN インターフェースを構成し、VLAN と DHCP を備えたレイヤー3の LAN インターフェースをセットアップし、マクロセグメンテーションとマイクロセグメンテーションを実装します。

各ラボを通じた目標には次が含まれます。

  • VM テンプレートを使用して Zero Trust Branch (ZTB) サイトを、アクティブ／スタンバイの HA ペアで展開する
  • マクロセグメンテーション によるトラフィックフィルタリングで東西方向のセキュリティを構成し、OT デバイス向けに マイクロセグメンテーション を実装する
  • SaaS および ICMP トラフィック向けに Policy-Based Routing (PBR) を構成する
  • 支社ネットワーク向けに DNS セキュリティポリシー を構成する
  • Experience Center で ZTB・ZIA・ZPA のログを表示・分析する
  • プライベートサブネット間の SSH をブロックする Ransomware Kill Switch を構成する

ラボのセットアップ

このハンズオンラボは、Zscaler Web 環境上のクラウドベースのリソースを使用します。各受講者は Experience Center Portal 経由で Zero Trust Exchange のアカウントを持ち、POD にアクセスできます。各 POD では次が提供されます。

  • 2台の仮想 ZTB デバイス（アクティブ + スタンバイ）の管理コンソール
  • 4つの LAN インターフェースと 2つの WAN インターフェース
  • 1つの Management インターフェースと1つの HA インターフェース
  • Zero Trust Exchange 経由のインターネット接続、1台の基本スイッチ、および ESXi 7.0 サーバー

ラボトポロジー

ラボトポロジー: Zero Trust Exchange (ZTE) がトラフィックを検査しポリシーを適用します。ルーターが共有 DIA 接続を終端し、VLAN10 は Windows Server、VLAN20 は IoT Ubuntu ホスト、VLAN30 は2台の OT Linux ホストを収容します。App Connector がリソースへの Zero Trust アクセスを提供します。

VLAN / エンドポイントの役割

  • VLAN10 — Windows Server VM（Server コンソール）
  • VLAN20 — IoT Ubuntu ホスト VM（IoT コンソール）
  • VLAN30 — 2台の OT Linux ベース VM（OT1、OT2 コンソール）
  • ZCC Lab Machine — Zscaler Client Connector を実行する Windows 10 クライアント
  • ZTB-1 / ZTB-2 — Zero Trust Branch 管理コンソール（プライマリ + セカンダリユニット）

タスク 1.1 — 管理ポータルへのアクセスとログイン情報

Experience Center ポータルには、インターネット接続のある任意のマシンからアクセスできます。ほとんどのタスクでは、ここで Zero Trust Branch / ZIA / ZPA のセクションを構成します。アクセス情報はセッション前にメールで送付され、次が含まれます。

情報 提供される内容

  • 自分の POD 番号 — 例: POD06、POD20、POD45
  • Experience Center URL: https://console.zscaler.com/
  • ログイン ID: pod##-student@<FQDN> — 例: pod01-student@zs2115.safemarch.com
  • ポータルパスワード — メールで送付
  • Skytap URL: https://zscaler.skytap-portal.com/ と Skytap パスコード（メールで送付）

ヒント: このページ上部の ラボ設定 バーに、POD 番号・FQDN・パスワード・Skytap パスコードを一度入力しておくと、ガイド全体で導出される管理者ログインが自動的に補完されます。

タスク 1.2 — Skytap ポータルへの接続

Experience Center で構成した設定やポリシーを検証するには、クライアント PC から Skytap ポータルにログインします。

タスク 1.2 Skytap にログイン

  • ブラウザを開いて https://zscaler.skytap-portal.com/ [1] にアクセスし、メールで提供されたパスコードを入力して Go [2] を選択します。
Skytap Course Manager: URL [1] を入力し、メールのパスコードを入力して Go [2] をクリックします。
  • ログインに成功すると、ホームページに POD で利用可能なコンソールの種類が表示されます。
    • IoT — VLAN20 IoT Ubuntu ホスト VM
    • OT1 / OT2 — VLAN30 OT Ubuntu ホスト VM
    • Server — VLAN10 Windows Server
    • ZCC Lab Machine — Zscaler Client Connector ラボマシン
    • ZTB-1 / ZTB-2 — Zero Trust Branch 管理コンソール（プライマリ／セカンダリ）
  • 任意の VM を起動するには、その名前（例: IoT）をクリックします。別タブで開きます。
Skytap ホームページには POD 内の7つのコンソールがすべて一覧表示されます。名前をクリックすると、その VM が新しいタブで開きます。

注意: VM が自動的にログインしない場合は、ハイライトされた コピー／貼り付け アイコンをクリックしてパスワード欄に貼り付け、続行してください。

自動ログインしない場合は、VM コンソールツールバーのコピー／貼り付けアイコンで認証情報を貼り付けます。

タスク 1.3 — Experience Center Portal への接続

すべての受講者ラボは同一構成のため、Experience Center へのログインはセットアップ手順の必須ステップです。ノート PC またはクライアント PC から次を行います。

タスク 1.3 Experience Center にログイン

  • ブラウザを開いて https://console.zscaler.com/ にアクセスし、Enter を押します。
  • ユーザー名／メールとして pod##-student@<FQDN> [1]（例: pod25-student@zs2115.safemarch.com）を入力し、Next [2] を選択します。
Experience Center サインイン: POD の受講者ログイン [1] を入力して Next [2] をクリックします。
  • メールで共有されたパスワード [1] を入力し、Sign in [2] を選択します。
メールのパスワード [1] を入力し、Sign in [2] をクリックしてダッシュボードに進みます。
正しい認証情報を入力すると、Experience Center ダッシュボードが表示されます。

注意: Zero Trust Branch のラボ全体を通して、主に次の3つのナビゲーションパスを使用します。

ナビ よく使う3つのパス

  • サイト構成、統合、ダッシュボード、テンプレート: Infrastructure › Connectors › Edge › Zero Trust Branch
  • グローバル／テンプレート／サイトポリシー、Kill Switch、Objects & Groups: Policies › Access Control › Segmentation › Zero Trust Branch
  • Packet ログと Flow ログ: Logs › Insights › Zero Trust Branch

ラボの進捗
クイックリファレンス ▲
Zero Trust Branch (ZTB)
支社拠点に Zero Trust セグメンテーションとセキュアな DIA をもたらす Zscaler 支社アプライアンス (ZT800)。
ZT800
本ラボで使用する仮想 Zero Trust Branch デバイスのモデル。アクティブ／スタンバイの HA ペアで展開。
POD
ZTB デバイスと各 VLAN のエンドポイント VM を含む、分離された自分専用のラボ環境（例: POD06）。
Experience Center
console.zscaler.com — Zero Trust Branch・ZIA・ZPA・Insights の統合管理ポータル。
Skytap
zscaler.skytap-portal.com — 支社 VM（ZTB コンソール + VLAN エンドポイント）をホストし、実機検証を行う。
DIA
Direct Internet Access — 各 ZTB デバイスがインターネット／Zero Trust Exchange に到達するための WAN アップリンク。
HA（アクティブ／スタンバイ）
2台の ZT800 による高可用性ペア。アクティブ機が障害時にスタンバイ機が引き継ぐ。
Site
支社拠点とその ZTB デバイス・インターフェース・ポリシーを表す Experience Center オブジェクト。
VLAN10 / 20 / 30
Windows Server / IoT Ubuntu / OT Linux（×2）— 支社内のセグメント化されたエンドポイントの役割。
マクロセグメンテーション
VLAN／セグメント間のトラフィックを制御するポリシー（東西方向）— 例: VLAN10 → VLAN20 をブロック。
マイクロセグメンテーション
VLAN 内のトラフィックを制御するポリシー — 例: VLAN30 上で OT1 → OT2 をブロック。
PBR
Policy-Based Routing — 選択したトラフィック（SaaS、ICMP 等）を既定とは別の特定経路に誘導する。
DNS ポリシー
特定ドメインの名前解決をリダイレクトまたはブロックする支社 DNS セキュリティルール。
Ransomware Kill Switch
横方向の侵害拡大を封じ込めるための迅速なブロックモード（例: プライベートサブネット間の SSH）。
Insights
Logs › Insights › Zero Trust Branch — 支社トラフィックを監視する Packet ログと Flow ログ。
