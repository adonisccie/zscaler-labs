ラボ6 · EDU-280

内部・外部通信セキュリティポリシーの検証

設計全体が機能することを実証します。OT・IoT・Windows Server から、トラフィックが Zscaler 経由で送出されること、インターネットが稼働していること、ギャンブルサイトがブロックされること、データセンターの Web アプリが ZPA 経由で読み込まれることを確認し、最後に Off-Trusted-Network の ZCC ホストから ZPA 経由で Windows サーバーに RDP します。

ラボ6: 内部・外部通信セキュリティポリシーの検証

検証

構築したすべてを確認するときです。各エンドポイントから4つの項目を検証し、最後に Zero Trust リモートアクセスのシナリオで締めくくります。

  • トラフィックが Zscaler クラウド 経由でルーティングされる（ip.zscaler.com）
  • インターネットが稼働している（ゲートウェイ・8.8.8.8・cnn.com への ping）
  • ギャンブル／ゲームサイトがブロックされる（例: 888.com）
  • VLAN 間フォワーディングと ZPA 経由のデータセンター Web アプリが想定どおり動作する
  • Off-Trusted-Network の ZCC ホストから ZPA 経由で Windows サーバーに RDP する

ip.zscaler.com
ホストが送出する Zscaler サービスロケーションを表示 — トラフィックがクラウドへ転送されていることを確認。
888.com ブロック
ZIA URL フィルタリング（Gambling）のブロックページ — 支社がインターネットトラフィックを ZIA へ転送している証拠にもなる。
VLAN ゲートウェイ
10.1.30.1 (OT)、10.1.20.1 (IoT)、10.1.10.1 (Server) — 「インターネット稼働」チェックの最初の ping 先。
dcweb.ztwan.lab
ZPA 経由で到達するデータセンターホストの Web アプリ — http://（https:// ではない）を使用しないと失敗。
ZCC
Zscaler Client Connector — エンドポイントエージェント。ここではホストを Off-Trusted にして ZPA/ZIA へ転送。
Off-Trusted Network
ホストが社内 LAN の外にあることを示す ZCC のネットワークタイプ — トラフィックは Zscaler クラウドを通る。
ZPA 経由の RDP
ZPA が仲介する 10.1.10.10 へのリモートデスクトップ（administrator / Zscaler123!）— インバウンド露出なし。
Logs › Diagnostics
ZPA リモートセッション（ユーザー・ポリシー・アプリケーションポート）を確認する Experience Center のビュー。
