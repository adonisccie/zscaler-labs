ラボ7 · EDU-280

ログと監視

支社が見ているものを可視化します。Packet Logs と Flow Logs を自分の POD にフィルタリングし、レコードを展開してすべてのフィールドを読み、リアルタイムの Alarms を重大度で確認し、自分の POD ロケーションにスコープした Web Insights クエリを実行します。

⚙ ラボ設定
ログフィルタ値: pod## POD ロケーション: pod##-student-location

ラボ7: ログと監視

監視

Zero Trust Branch プラットフォームの監視・トラブルシューティング機能を探索します。packet logs・flow logs・リアルタイムの alarms を分析してトラフィックパターンを把握しポリシー適用を検証し、その後、自分の POD の Web Insights を確認します。

  • 自分の POD にスコープした Packet Logs と Flow Logs を表示・フィルタリングする
  • ログレコードを展開してすべてのフィールドを読む（テーブル形式または JSON）
  • 重大度でフィルタした Alarms を確認する
  • 自分の POD ロケーションで Web Insights クエリを実行する
コース: EDU-280
版: 2.2 · 2026年2月
プラットフォーム: Skytap + Zscaler Experience Center
  • Logs [1] › Packet Logs [2] に移動します。Calendar アイコン [3] をクリックし、時間範囲を 3 hours に設定して Apply [4] をクリックします。
Logs › Packet Logs › Calendar → 直近3時間 → Apply。
  • + アイコン [1] をクリックしてフィルタを追加します — Field: Policy、Operator: is、Value: pod## [2] — その後 Add Filter [3]。
フィルタ: Policy is pod##。
  • いずれかのログのトグル／ダイアログアイコンをクリックして詳細を表示します。
レコードを展開して確認します。
詳細ペインはすべてのフィールドをテーブル形式または JSON で表示します。
  • Logs [1] › Flow Logs [2] に移動します。Calendar [3] をクリックし、3 hours に設定して Apply [4]。
  • + [1] をクリックして同じフィルタを追加します — Policy is pod## [2] — その後 Add Filter [3]。
  • いずれかの flow log を展開して詳細を表示します（テーブル形式または JSON）。
Logs › Flow Logs › 直近3時間。
フィルタ: Policy is pod##。
flow レコードを展開します。
すべての flow フィールドをテーブル形式または JSON で。
  • Administration › Alerts › Zero Trust Branch › Alarms に移動します。warning アラームの一覧が表示されます（表示されない場合はフィルタ設定を確認します）。
Administration › Alerts › Zero Trust Branch › Alarms。
  • 重大度でフィルタします — Emergency、Alert、Critical、Error、Warning、Notice、Informational、Debug。ここでは Warning アラームを選択しています。
Warning 重大度のアラーム — 管理者にとって参考になるシグナル。
  • Experience Center で Logs [1] › Web Insights [2] に移動します。
Logs › Web Insights。
  • Logs タブ [1] を選択し、Add Filter [2] をクリックして、"user" と入力して User [3] を選択します。
Logs タブ › Add Filter › User。
  • ドロップダウン [1] から自分の POD ロケーション（例: pod##-student-location）[2] を選択し、Done [3] をクリックします。
  • Run Query を選択します。
自分の POD ロケーションを選択 → Done。
Run Query。
  • 数秒後に自分の POD のログイベントが表示されます — 横スクロールで他のフィールド、縦スクロールで他のイベントを表示します。
自分の POD にスコープした Web ログイベント。

注意: 同じフィルタを使って、自分の POD の Insights タブも分析できます。

Insights タブは同じ POD フィルタで集計分析を提供します。

完了: packet・flow・alarm・web の各ログで支社のテレメトリを見つけて読めるようになりました。次は環境のトラブルシューティングとデバッグを行います。

🧠
覚えておこう
Packet logs = パケット単位の詳細（1つのパケットがなぜドロップされたか）、flow logs = セッション単位のサマリ（トラフィックパターン）。どちらも Logs › Insights › Zero Trust Branch 配下。Policy is pod## + 3時間の範囲でフィルタし、レコードを展開（テーブル/JSON）。Alarms: Administration › Alerts、重大度でトリアージ（Emergency→Debug）。Web Insights: Logs タブ → User でフィルタ → 自分の POD ロケーション → Run Query。常に自分の POD にスコープすること。

ラボの進捗
クイックリファレンス ▲
Packet Logs
どのポリシーがトラフィックに作用したかを示すパケット単位のイベント — 特定のドロップ／リジェクトの確認に使用。
Flow Logs
セッション単位（5-tuple）のサマリ — 全体のトラフィックパターンとマッチしたフローの確認に使用。
Policy フィルタ (pod##)
Field: Policy、Operator: is、Value: pod## — 共有テナント内でログを自分の POD にスコープ。
詳細ペイン
レコードを展開して、すべてのフィールドをテーブル形式または JSON で表示。
Alarms
Administration › Alerts › Zero Trust Branch — リアルタイムイベント。重大度でフィルタ可能。
重大度レベル
Emergency、Alert、Critical、Error、Warning、Notice、Informational、Debug — 高い順にトリアージ。
Web Insights
Logs › Web Insights — ZIA の Web ログイベント。User / POD ロケーションでフィルタして Run Query。
POD ロケーション
pod##-student-location — Web Insights を自分の POD にスコープするために使うロケーション値。
