ラボ5 · EDU-280

DNS ポリシーの構成

名前解決そのものを制御します。VLAN30 からの google.com を 8.8.8.8 にリダイレクトする DNS Override と、VLAN20 からの *.whatsapp.com をブロックする DNS Reject を作成し、ping・nslookup・ブラウザで前後を実証します。

⚙ ラボ設定
管理者ログイン: pod##-student@<受講者FQDN> サイト名: POD##-Student-Lab Override ルール: POD##-Override-Google ブロックルール: POD##-Block-Whatsapp

ラボ5: DNS ポリシーの構成

DNS セキュリティ

Zero Trust アーキテクチャにおいて、DNS ポリシーは特定ドメインへのリクエストの扱い方をきめ細かく制御します。適用／監視のためのトラフィックリダイレクト、リスクの高いドメインのブロック、そしてユーザーグループ・サブネット・ゾーンごとに名前解決を制限することによる攻撃対象領域の削減が可能です。

2つのタスクを実施します。

  • 10.1.30.0/24 からの Google トラフィックを Override IP 8.8.8.8 にリダイレクト（DNS Override）
  • 10.1.20.0/24 からの WhatsApp を、エラーコード 5 – Query Refused でブロック（DNS Reject）
コース: EDU-280
版: 2.2 · 2026年2月
プラットフォーム: Skytap + Zscaler Experience Center

5.1.1 · 構成前に検証

  • Skytap で Ubuntu ホスト OT1 を開き、ターミナルから google.com が正常に解決されることを確認します（ping が Google のデフォルト IP を返す）。
OT1（VLAN30）を開きます。
ベースライン: ping google.com が Google のデフォルト IP に解決します。

5.1.2 · Google のドメインオブジェクトを作成

  • Policies [1] › Access Control › Segmentation › Zero Trust Branch › Objects & Groups [2] に移動します。Add [3] › Domains [4] をクリックします。
Objects & Groups › Add › Domains。
  • Rule Name: POD##-Google [1]
  • Domains: google.com [2] › Add [3]
  • Add [4] をクリックしてオブジェクトを保存します。
google.com 用の POD##-Google ドメインオブジェクトを作成します。

5.1.3 · Override DNS ポリシーを構成

  • Infrastructure › Connectors › Edge › Zero Trust Branch › Sites [1] に移動し、POD##-Student-Lab を選択して、DNS Policies タブ [2] を開き、Configure [3] をクリックして Add Policy を選択します。
Site › DNS Policies › Configure。
Add Policy。
  • Rule Name: POD##-Override-Google [1]
  • Sources: Subnet/Host [2] › 10.1.30.0/24 [3] › Add [4]
  • Destination Domains: POD##-Google [5]
  • Action: Override [6] · Override IP: 8.8.8.8 [7]
  • Add [8] をクリックし、Commit して適用します。
Override ルール: source 10.1.30.0/24 → Google オブジェクト → Override IP 8.8.8.8。
Commit してポリシーを有効化します。

5.1.4 · 構成後に検証

  • Skytap で OT1 を開き直し、ping google.com を実行します。今度は Google のデフォルト IP ではなく 8.8.8.8 に解決され、リダイレクトが機能しています。
OT1 を開き直します。
google.com が上書きされた 8.8.8.8 に解決されるようになりました。

5.2.1 · 構成前に検証

  • Skytap で Ubuntu ホスト IoT（VLAN20）を開きます。
  • web.whatsapp.com が解決されることを確認します: nslookup web.whatsapp.com または ping web.whatsapp.com。
  • 同じマシンのブラウザで web.whatsapp.com を読み込みます。ログインページが表示されます。
IoT ホスト（VLAN20）を開きます。
ベースライン: web.whatsapp.com が有効な IP に解決されます。
WhatsApp のログインページが正常に読み込まれます。

5.2.2 · WhatsApp のドメインオブジェクトを作成

  • Policies [1] › Access Control › Segmentation › Zero Trust Branch › Objects & Groups [2] に移動します。Add [3] › Domains [4] をクリックします。
Objects & Groups › Add › Domains。
  • Rule Name: POD##-Whatsapp [1]
  • Domains: *.whatsapp.com [2] › Add [3] （ワイルドカードがすべてのサブドメインをカバー）
  • Add [4] をクリックして保存します。
ワイルドカードオブジェクト *.whatsapp.com がドメインファミリー全体をブロックします。

5.2.3 · Reject DNS ポリシーを構成

  • Infrastructure › … › Sites [1] に移動し、POD##-Student-Lab を選択して、DNS Policies [2] を開き、Configure [3] をクリックして Add Policy を選択します。
Site › DNS Policies › Configure。
Add Policy。
  • Rule Name: POD##-Block-Whatsapp [1]
  • Sources: Subnet/Host [2] › 10.1.20.0/24 [3] › Add [4]
  • Destination Domains: POD##-Whatsapp [5]
  • Action: Reject [6] · Error Code: 5 – Query Refused [7]
  • Add [8] をクリックし、Commit して適用します。
Reject ルール: source 10.1.20.0/24 → WhatsApp オブジェクト → error 5 (Query Refused)。
Commit してポリシーを有効化します。

5.2.4 · 構成後に検証

  • IoT VM を開き直し、ping web.whatsapp.com を実行します。名前解決が失敗します（例: Name or service not known）。
  • VLAN20 のマシンのブラウザで web.whatsapp.com を読み込みます。This site can't be reached が表示されます。
IoT ホスト（VLAN20）を開き直します。
名前解決が失敗するようになりました — DNS Reject が有効です。
ブラウザ: This site can't be reached — DNS ブロックが機能しています。

完了: DNS Override と Reject の両方を検証しました — 名前ベースの選択的な Zero Trust 制御です。次は、すべてのポリシーをエンドツーエンドで検証します。

🧠
覚えておこう
DNS ポリシーは IP/ポートではなく名前解決に作用します。Override = ドメインを選んだ IP にリダイレクト（VLAN30 から google.com → 8.8.8.8）。Reject = エラーコード（5 – Query Refused）で解決を失敗させる（VLAN20 から *.whatsapp.com）。2ステップで構築: ドメインオブジェクト（Objects & Groups › Domains）を作成してから DNS Policy（Site › DNS Policies）。*. ワイルドカードですべてのサブドメインを捕捉。ping/nslookup + ブラウザで前後を検証。

DNS Policy
支社が特定ドメインをどう解決するかを制御するルール — 送信元サブネット・ゾーン・宛先ドメインオブジェクトで指定。
Domain Object
DNS ポリシーの Destination として参照する、名前付きのドメイン一覧（Objects & Groups › Domains）。
Action: Override
ドメインを指定した Override IP にリダイレクト（例: google.com → 8.8.8.8）。
Action: Reject
DNS エラーコード（5 – Query Refused）で解決を失敗させ、アクセスをブロック。
Override IP
Override ポリシー下で、マッチしたドメインが強制的に解決される先の IP。
Error Code 5
Query Refused — Reject アクションが返す DNS 応答コード。
*.whatsapp.com
すべてのサブドメインにマッチするワイルドカードドメイン。別ホスト経由でブロックを回避できないようにする。
nslookup / ping
ポリシー適用の前後で解決を検証するために使うクライアントツール。
Sources（サブネット）
ポリシーが適用されるサブネット — Google override は 10.1.30.0/24、WhatsApp block は 10.1.20.0/24。
